# G4 · מעבדת טניס עצמאית

המעבדה נמצאת רק ב־`codex-lab/island-tennis/`; הבדיקה היחידה מחוץ לה היא `tests/island-tennis.test.mjs`. אין ייבוא מהאי, שינוי ב־`workout/`, תלות במעבדת הכדורגל או רישום ספורט בפועל. חיבור האי הוא G4b.

## הרצה

משורש המאגר:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

פתחו [את המעבדה המקומית](http://127.0.0.1:8765/codex-lab/island-tennis/). מסך הגלגל מאפשר בחירת שלב 1–10 ודרגות 1–5. החלה פותחת מערכה חדשה. חצים ורווח במחשב; בטלפון גרירה בחצי התחתון וטאפ במגרש או בכפתור החבטה. מחזיקים ומשחררים להגשה טעונה. הגרירה אינה נחשבת גם לחבטה. הילד נשאר בצד הקרוב.

פרסום GitHub Pages הנוכחי מעתיק `workout/` ואינו מעתיק `codex-lab/`. לכן קישור לתיקיית המעבדה במאגר אינו כתובת משחק מפורסמת. G4 אינו משנה את תהליך הפרסום.

## חוזה המודל

```js
const game = createTennis({ config, stage: 1, seed: 4107,
  ranks: { speed: 1, hit: 1, serve: 1 } });
game.update(dt, { targetX, move, swing, charge });
const state = game.getState();
const result = game.result;
```

- `dt` בשניות. המודל צובר תת־צעדים של 1/120 שנייה. פריים ארוך מוגבל ל־`simulation.maxDelta`; מעטפת אינה משלימה זמן שהטלפון היה ברקע. ערכי זמן לא תקינים אינם משנים מצב.
- `targetX` במטרים, בטווח תנועת השחקן; `move` בתחום ‎−1..1 למקלדת. יעד מפורש קודם ל־`move`. גרירה מתורגמת לתזוזה יחסית מנקודת תחילת המחווה.
- `swing` הוא קצה עולה; יש לשחרר בין חבטות. `charge` הוא מצב מתמשך של החזקה לפני ההגשה. שחרור יוצר `swing` ומשתמש במטען שהצטבר.
- `getState()` מחזיר הפניה לקריאה בלבד לצורך רינדור; לא משנים אותה מבחוץ. `snapshot()` מחזיר העתק עמוק לבדיקות. `result` הוא null עד סיום ויציב לאחריו.
- הפאזות: `serve → rally → point/game → serve`, ובסוף `complete`. `event.id` מונוטוני; המעטפת מציגה צליל, הבזק והודעה פעם אחת לכל אירוע. `contact` מכיל צד מקבל, מיקום וזמן מגע; `landing` מכיל נחיתה וחוקיות. `pointLabels` מחזיר מספר או מזהי `deuce`/`advantage`.
- RNG מקומי בזרע uint32; אין שימוש ב־`Math.random`, בשעון או ב־localStorage בתוך המודל. אותו זרע, תצורה ורצף `update` מחזירים אותה תוצאה.

הכדור נע עם כבידה; פגיעה ברשת נבדקת לאורך חציית המישור כדי למנוע דילוג בכדור מהיר. הנחיתה הראשונה נבדקת כולל סבולת קו; בהגשה גם עומק ריבוע ההגשה. נחיתה שנייה מפסידה את הנקודה. חלון התזמון הוא **רוחב מלא**: 0.5 שנייה בשלב 1 ו־0.18 בשלב 10. טאפ מוקדם חוקי נשמר עד המגע אחרי הקפיצה; האיחור/הקדמה קובעים את זווית החבטה. אין הגשה שנייה, let, זוגות, החלפת צדדים או כללי תחרות נוספים. יש שוויון ויתרון בנקודות; מערכה מסתיימת ב־4 משחקונים גם בתוצאה 4–3.

בשלבים 1–3 התנועה האופקית והעומק מסייעים לילד להגיע לכדור; דרישת התזמון נשארת. בהמשך רק העומק אוטומטי. דירוג מהירות משנה מהירות ריצה; חבטה משנה משך מעוף; הגשה משנה כוח ומהירות, והחזקה מוסיפה כוח. היריב משפר ריצה, פיזור, כוח, בחירת פינות והחמצות לפי השלב. הוא מגיש מקו הבסיס ויכול להתקרב לרשת בזמן חילוף. קצב החילוף עולה בהדרגה והסתברות ההחמצה של היריב גדלה בחילופים ארוכים, כדי לשמור על מערכה קצרה. רשת ביטחון של 90 שניות לחילוף מזכה את החובט האחרון; המתנה להגשת הילד מוגבלת ל־9 שניות. שתי ההגבלות בנתונים ומבטיחות נקודה גם ללא קלט או ברצף מושלם חריג.

## תוצאה וחיבור G4b

תוצאת הטניס המדויקת היא:

```js
{ won, gamesFor, gamesAgainst, stage, stars, seed, durationSeconds }
```

ניצחון 4–0 נותן 3 כוכבים; 4–1 נותן 2; ניצחון אחר נותן 1. לבקשת G4 שטווח התוצאה יהיה 1–3, **הפסד במעבדה מקבל כוכב עידוד אחד**; הוא אינו כסף, ניצחון או פרס של האי. זמן הוא זמן סימולציה פעיל, מעוגל למילישנייה; השהיה ובחירת דרגות אינן נספרות. רק סיום מערכה נשמר; יציאה אינה שומרת תוצאה חלקית.

ב־`workout/island/ARCHITECTURE.md`, סעיף ״פעילות G2״, החוזה הקיים שונה: `ctx.finish({outcome, score, performance})`, ואחריו `onResult(raw,ctx)` מחזיר `{outcome, score, money, stars}`. אין כיום באי חוזה מקורי עם `gamesFor` ו־`won`. G4b צריך מתאם, בלי לשנות את `tennis.mjs`:

```js
const raw = {
  outcome: result.won ? 'win' : 'lose',
  score: result.gamesFor,
  performance: result.won ? (result.stars - 1) / 2 : 0,
  tennis: result
};
ctx.finish(raw); // פעם אחת בלבד; לא לכתוב לשמירת האי מתוך המודל
```

`onResult` של הטניס צריך לאמת את תוצאת הטניס, שלב/זרע/טווחים, לחשב כסף מהגדרות האי, ולהחזיר את הכוכבים המקוריים בניצחון ו־**0 בהפסד** כמקובל באי. לא להסתמך על ספי `gameResult()` הכלליים: הם אינם בהכרח ספי 4–0 ו־4–1. ה־`performance` בדוגמה הוא מדד עזר; `tennis.stars` אחרי אימות הוא מקור כוכבי הניצחון. אין להעביר את כוכב העידוד לכלכלת האי.

סדר השילוב העתידי:

1. להעתיק את `tennis.mjs`, `tennis-view.mjs`, `controls.mjs` ו־`vendor/` אל תיקיית משחקון מבודדת, למשל `workout/island/minigames/tennis/`. המודל אינו צריך שינוי. אפשר להפנות את ייבוא התצוגה ל־vendor הקיים באי במקום עותק נוסף, רק אם כל הייבואים נשארים ב־r160.
2. למזג את תצורת הטניס תחת `config.minigames.tennis` ואת המחרוזות עם תחילית `minigame.tennis.`. המעטפת העתידית מעבירה למודל את ענף התצורה השלם. `ctx.level` בוחר שלב; דרגות שחקן מהציוד מתורגמות ל־`ranks`. אין להשתמש בהתרחבות העיר בתור שלב.
3. לכתוב `session.mjs` שמנהל HUD וקלט ייעודיים, RAF, השהיה ו־dispose. **לא להעתיק את `app.mjs`**, שמכיל אחסון וכלי מעבדה. גם `index.html` והסגנונות הגלובליים למעבדה אינם מעטפת אי; את עיצוב הממשק יש לתחום לרכיב ה־session.
4. ליצור את התצוגה עם `characterUrl: new URL('../../assets/kid-full.glb', import.meta.url)` ממיקום `minigames/tennis/session.mjs`. כך משתמשים בנכס האי הקיים ללא כל תלות ב־`codex-lab/`. ברירת המחדל במעבדה נשארת `../kid-full/kid-full.glb`.
5. להוסיף מודול `extensions/tennis.mjs` לרשימת `data/extensions.json.modules`, ולקרוא ל־`registry.registerSport(record)` ו־`registry.registerMinigame({id,title,featureFlag,difficulty,helpId,icon,start,onResult})`. הרישום הפתוח נמצא ב־`engine/registry.mjs`; אין צורך לשנות אותו. הגדרות ספורט נקראות דרך `config.sports[id]`, והמגרש משויך ב־`buildingId`.
6. להשתמש בשם ובצבעי הקבוצה מ־`data/team.json`, ובמזהי השחקנים/שמות/צבעים מ־`data/players.json` (תבניות G1 שלב 5). המודל אינו זקוק לשמות או למטבע. דירוגי ברירת המחדל העתידיים יכולים להתרחב בנתוני השחקנים/הציוד ל־speed/hit/serve; רכישה וניצחונות נשארים באחריות מנוע האי, מחוץ למודל.
7. בזמן המשחק להשהות רינדור אי; בסיום/ביטול לנקות בקרות, RAF, סצנה ושמע ולהחזיר את מצלמת האי. יציאה מפעילה `ctx.cancel()` ללא פרס. `dispose()` של התצוגה והבקרות ניתן לקריאה חוזרת. לבדוק פרסום כשהמעבדה חסומה ב־404, כפי שהאי בודק היום.

## נכסים, אנימציה וביצועים

הדמות נטענת פעם אחת יחסית מ־`../kid-full/kid-full.glb`, ללא העתקת GLB. אותו ArrayBuffer מפוענח פעמיים לשני שלדים עצמאיים; `Ball` המקורי מוסר ומשוחרר. מקטעי `stand` ו־`run` מופעלים באמצעות AnimationMixer. אין קטע חבטת טניס בנכס: אחרי דגימת האנימציה הקוד מסובב את `UpperArm_R`, `LowerArm_R` ו־`Chest` במשך `player.swingSeconds`; המחבט מחובר ל־`Hand_R`. אין כתיבה מחדש של הדמות. זוהי חבטה מסוגננת על השלד הקיים, ללא motion capture או IK מקצועי.

המקור והרישוי של הדמות ב־`codex-lab/kid-full/source-manifest.json` וב־`workout/island/ASSETS.md`; אין ייחוס CC0 חדש. `vendor/{three.module.js,GLTFLoader.js,BufferGeometryUtils.js,LICENSE.three}` הם עותקים זהים מהמעבדה הקיימת, Three.js r160 ברישיון MIT. אין CDN, הורדת נכסים או תלות npm חדשה. המגרש, המחבטים, הקהל, השופט והגביע הם צורות פשוטות מקוריות. שמע נוצר ב־Web Audio בלבד.

גאומטריה סטטית מתאחדת לפי חומר בהקמה; הקהל בשני InstancedMesh; 72 חלקיקים מוקצים מראש ב־Points אחד. אין יצירת גאומטריה בתוך render. איכות יורדת אחרי מדגם פריימים איטיים: תקרת DPR ‏1.5→1→0.75, הסרת צללים וקהל 72→36→0. אין עלייה אוטומטית שגורמת להתנדנדות איכות. שינוי גודל אינו בונה גאומטריה. ביציאה משוחררים mixers, skeleton textures, גאומטריות, חומרים, מפות, observer, renderer/context, מאזינים ו־AudioContext. ראיות ומגבלות מדידה ב־[QA.md](QA.md).
