# G3 · ליגת האי — מעבדת כדורגל עצמאית

המעבדה נמצאת רק ב־`codex-lab/island-soccer/`. היא אינה מייבאת קוד מהאי, אינה נרשמת במנוע שלו ואינה כותבת לשמירתו. הקובץ היחיד מחוץ למעבדה שנוסף ב־G3 הוא `tests/island-soccer.test.mjs`. `workout/` ומקור הדמות לא שונו.

## הרצה ומבנה

משורש המאגר:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

פתחו את [המעבדה המקומית](http://127.0.0.1:8765/codex-lab/island-soccer/). המעבדה אינה חלק מפרסום `workout/` הקיים. קישור לקובץ בענף הוא קישור לקוד, ואינו פרסום חי של המשחק.

| קובץ | אחריות |
| --- | --- |
| `soccer.mjs` | פיזיקה, AI, ניקוד, מחציות, זרע ותוצאה; ללא DOM, רשת, שעון מערכת או שמירה. |
| `soccer-view.mjs` | Three.js r160, מצלמה, נכס הילד, דמויות קוד, קהל, רשתות וקונפטי. |
| `controls.mjs` | Pointer Events עם capture, ריבוי מגע, חצים, רווח ושיפט; `AbortController` לניקוי. |
| `app.mjs` | תפריט, דרגות, RAF, השהיה, צליל מסונתז ותוצאה מקומית. |
| `config.json` | איזון, עשרת השלבים, תבנית הקבוצה, דרגות, מידות ותקציבי איכות. קבועי צורה ואיור אינם איזון. |
| `strings.he.json` | כל המלל המוצג; ממשק RTL. |
| `verify-browser.mjs`, `verification/` | בדיקת דפדפן, צילומים ודוח מדידות. |

## ממשק המודל

```js
import {createSoccer} from './soccer.mjs';
const model = createSoccer({config, seed: 2026, stage: 1, team: config.team});
model.update(1 / 60, {
  moveX: 1, moveZ: 0, kickHeld: false, switchPlayer: false
});
const state = model.getState();
const result = model.result; // null עד שריקת הסיום
```

`dt` נמדד בשניות. המודל משתמש בצעד קבוע מ־`match.fixedStep` ובצבירה פנימית; אותה סדרת קלט מתוזמנת עם אותו זרע משחזרת את אותו מצב. `random` אופציונלי מאפשר הזרקת `ctx.random` של האי. הזרע המקומי ממומש ב־Mulberry32. כל קריאת `update` מוגבלת ל־`rules.maxUpdateSeconds` כדי למנוע קפיצה בזמן אחרי השהיית הדפדפן. RAF מקומי מגביל אף הוא את זמן הפריים; זמן טאב מוסתר והשהיה אינם זמן משחק.

`getState()` מחזיר מבט חי לקריאה בלבד, כדי שלא להעתיק שישה שחקנים בכל פריים. אין לשנותו במתאם. `snapshot()` נותן עותק מנותק לבדיקות. בדיקות תרחיש בלבד מציבות דרך המבט החי כדור ליד שער או שעון ליד סיום, ואז מפעילות את חוקי המודל הרגילים. `clearInput()` מבטל טעינה וקצוות קלט בהשהיה, ביטול אצבע, החלפת צדדים ויציאה. לאחר תוצאה, `update` אינו משנה דבר.

קואורדינטות: X לאורך 30 מטר, Z לרוחב 18 מטר, Y הוא גובה הכדור. `moveX/moveZ` הם צירי עולם ב־‎−1…1, עם נרמול אלכסונים. במחצית השנייה `attackDir` מתהפך והמצלמה פונה מהצד השני; המתאם המקומי מכפיל את שני צירי המסך ב־`attackDir` כדי לשמר תנועה לפי המסך ותקיפה ימינה.

`kickHeld` הוא מצב החזקה, לא אירוע. שחרור קצר מוסר לחבר הקרוב; שחרור אחרי `physics.shortPressSeconds` בועט לכיוון השער, בכוח עד `chargeSeconds`. מסירה כחולה מעבירה אוטומטית שליטה למקבל. `switchPlayer` מופעל בקצה עולה ומחליף לשחקן הכחול הקרוב לכדור, כולל השוער. קצוות נשמרים עד לצעד הבא גם במסך 120 Hz.

מצבים: `playing`, `goal`, `restart`, `halftime`, `finished`. השעון מתקדם רק ב־`playing`, שתי מחציות של 75 שניות. בגול המודל מאט את הכדור והרשת והקונפטי חוגגים, ואז היריבה מוציאה מהאמצע. במחצית מתחלפים הצדדים. אחרי חוץ יש מיקום וכדור חדשים בהשהיה קצרה: קו רוחב מחזיר בעיטת שער פשוטה; קו השער נותן קרן אם ההגנה נגעה אחרונה, אחרת בעיטת שער. אין עבירות, נבדל או כרטיסים.

שלושה שחקנים בכל קבוצה כוללים שוער אחד. חבר תוקף מתפרס לאגף ומסומן כשהוא פנוי; היריב לוחץ, מכסה מסלול מסירה, ובשלבים הגבוהים מחפש מסירה קדימה לשחקן פנוי. בשלב 1 יש עזרה אחרי חוסר קלט: השחקן מצטרף לבינה של חבריו עד הקלט הבא. אין שינוי תוצאה מלאכותי או הענקת שערים בסיום. בשלב 10 לחץ כפול, טווח חטיפה ושוער משופרים מענישים הובלה לבד.

## תוצאה ושמירה

התוצאה המקומית היא בדיוק שבעת השדות שהתבקשו:

```json
{"won":true,"goalsFor":3,"goalsAgainst":0,"stage":1,"stars":3,"seed":2026,"durationSeconds":150}
```

ניצחון ללא ספיגה מקבל 3 כוכבים, גם אם ההפרש הוא אחד; אחריו ניצחון בהפרש 2 מקבל 2, וניצחון אחר מקבל 1. הדרישה מגבילה את שדה `stars` ל־1–3: בהפסד או בתיקו נשאר 1 במטען, אך הממשק מציג שלושה כוכבים ריקים ואינו מתאר זאת כפרס. G3b חייב להתנות זכייה וכוכבי האי ב־`won`. תיקו הוא `won:false`, ללא הארכה או פנדלים. `durationSeconds` הוא זמן משחק פעיל: 150 בסיום רגיל.

רק `app.mjs` שומר את התוצאה האחרונה, במפתח `soccer-lab`. אין שמירת משחק חלקי, כסף או התקדמות של האי; דרגות ושינוי צד שליטה הם בדיקה לסיבוב הנוכחי. כשל storage מוצג ואינו מפסיק משחק. אין דריסה או מחיקה של מפתחות אחרים.

## נכסים, ביצועים וניקוי

שלוש ספריות ו־`LICENSE.three` הועתקו ללא שינוי מ־`../kid-full/vendor/`; בדיקה משווה בייטים. הדמות נטענת רק מ־`../kid-full/kid-full.glb`, ללא העתק וללא שינוי בקובץ. מקור ורישיון הנכס מתועדים ב־`../kid-full/source-manifest.json` וב־`../../workout/island/ASSETS.md`. לא הורדו נכסים ולא נוספו חבילות.

ה־GLB המקורי מכיל 15,152 משולשים, מתוכם 140 ב־`Ball`. גם בלי ששת הכדורים הפנימיים, שש דמויות הן 90,072 משולשים, מעבר לתקציב 80,000 לפני הסביבה. לכן מופע מונפש יחיד עובר לשחקן הנשלט; חמש הדמויות האחרות מצוירות כילדים פשוטים עם חולצה, ראש, שיער, עיניים, ידיים ורגליים, ב־InstancedMesh. `run`, `kick` ו־`stand` המקוריים מופעלים דרך AnimationMixer. הצבע הכחול בלבד מותאם בשיידר החומר לפי צבע הקודקוד; עור ופנים נשמרים. הדמויות הפשוטות מקבלות צבעי קבוצה נפרדים. הרשת הפנימית `Ball` מוסתרת מהדמות, והגאומטריה שלה משמשת כדור פיזיקלי יחיד וממורכז.

הסביבה הסטטית מאוחדת לפי חומר. הקהל הוא איור מקורי בקנבס שנוצר פעם אחת, על atlas יחיד. חלקי דמויות, צללים, בקשות כדור ו־96 חלקיקי קונפטי משתמשים במאגרים קבועים. אין יצירת גאומטריה בפריים. הצללים הם כתמי קרקע קלים, ללא מעבר shadow map. שתי רמות ירידת איכות מפחיתות DPR וקהל; השנייה מסתירה צללים. האיכות אינה משנה פיזיקה או תוצאה. המדידות ב־QA ובדוח הדפדפן; 60 FPS בטלפון פיזי הוא יעד שטרם נמדד.

`view.dispose()` מנתק ResizeObserver ו־context-loss, עוצר ומנקה mixer, משחרר skeletons, גאומטריות, חומרים, טקסטורות ו־WebGL. טעינה שהושלמה אחרי יציאה משחררת את הנכס. `controls.dispose()` מנתק מאזינים ומשחרר capture. `app.dispose()` מבטל RAF, סוגר AudioContext ומנקה את שניהם. כשל טעינת GLB משאיר דמות קוד; כשל WebGL מציג הודעה ועוצר משחק.

## שילוב עתידי ב־G3b

זו תוכנית החיבור; היא לא בוצעה ב־G3:

1. העתיקו את `soccer.mjs` ללא שינוי ל־`workout/island/minigames/`, ואת `soccer-view.mjs` ו־`controls.mjs` לשם או לתיקיית session ייעודית. המתאם מחזיק RAF, קנבס ופקדי מגע, ומשהה את תצוגת האי בזמן המשחק. אין להעתיק את `app.mjs` עם השמירה המקומית שלו.
2. העבירו את נתוני `config.json` תחת `config.minigames.soccer` ואת המחרוזות עם תחילית מתאימה למילון האי. `team.id` ומזהי `playerSun/playerWave/playerStar` תואמים לתבניות G1; השדות הם `speed/kick/guard`, דרגות 1–5. ברירות המחדל של האי כיום 3, ואילו המעבדה מתחילה ב־1 לפי G3. על המתאם למפות את שדרוגי העיר ולתחום דרגות בלי לשנות את המודל.
3. שנו רק את נתיבי הייבוא בתצוגה ובמתאם: השתמשו ב־`../vendor/` הקיים של האי וב־`../assets/kid-full.glb`. אין צורך להעתיק GLB נוסף. אל תיצרו תלות של האי ב־`codex-lab/`: הפרסום הקיים שלו אינו כולל את המעבדה.
4. מודול יחיד ב־`extensions/` יירשם דרך `registerMinigame({id,title,featureFlag,difficulty,helpId,icon,start,onResult})`; הוסיפו אותו ל־`data/extensions.json`. ספורט נרשם בנפרד דרך `registerSport` ומפנה ל־buildingId של הכדורגל. רשומת `sports.soccer.teamSize` באי כרגע היא 5; G3b יחליט על שינוי ל־3. אין צורך לערוך את מנוע הרישום.
5. `start(ctx)` יוצר `createSoccer({config:balance, stage:ctx.level, seed, random:ctx.random, team})`. יש להחזיר session עם `dispose`, `setPaused` ו־snapshot; ב־pause יש לקרוא `clearInput`, וביציאה `ctx.cancel()`. הקלט מקבל את `attackDir` מהמודל כפי שהמתאם המקומי עושה.
6. **הבדל חוזה מפורש:** האי הנוכחי מתעד `ctx.finish({outcome,score,performance})` ו־`onResult(raw,ctx)` שמחזיר `{outcome,score,money,stars}`; הוא אינו מתעד את אובייקט הכדורגל שלעיל. המתאם יכול להעביר ל־`ctx.finish` מעטפת עם `outcome` לפי `won`, `score:goalsFor`, `performance` מספרי ו־`soccer:payload`. `onResult` יבדוק את שבעת השדות, שלב, זרע, משך, שערים וכוכבים, ויחזיר את חוזה האי. יש לחשב כסף ומגבלות ניקוד בנתונים; הפסד ותיקו מחזירים אפס כוכבי אי. אין להעביר `stars:1` של הפסד כפרס ואין לכתוב לשמירה מתוך המודל.
7. בדקו במסלול האי session יחיד, תשלום פעם אחת, כוכבים ופתיחת שלב, ביטול ניטרלי וניקוי במשחק חוזר. הריצו את בדיקת הפרסום כשהמעבדה חסומה. G3 אינו משנה שמירת אי או גרסת סכימה.

לבדיקות בלבד, `?dev=1` מפרסם `window.__soccer` עם המודל, מדידות התצוגה, `step`, השהיה ו־dispose. ללא הפרמטר אין API בדיקה גלובלי.
