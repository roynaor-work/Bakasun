# כדורגל · תנועות v11

חבילת פעולות כדורגל מקוריות על שלד motion2 בן 18 עצמות, עם אירועי מגע, מסלולי כדור ועוגני נטיעה. הכיסוי כולל כדרור בשלושה קצבים, סיבוב ופיינט, shielding, מסירות, בעיטות, תיקולים וחטיפה, נגיחות, נייחים, שוער וחגיגות יחיד וקבוצה. רשימת הקליפים המדויקת נמצאת ב־[קטלוג](runtime/catalog.json); התוצאות והספים ב־[REPORT.md](REPORT.md).

ההנפשות והקבצים החדשים הם CC0-1.0. הגאומטריה היא הדמות הבדיונית הקיימת של v10, המבוססת על נכסי MakeHuman CC0. המקור והרישיון של כל קובץ מופיעים ב־[LICENSES.md](LICENSES.md). אין מותגים, אנשים אמיתיים או צילום תנועה מיובא.

## צפייה

1. משורש המאגר מפעילים שרת מקומי:

   ```sh
   python3 -m http.server 8765
   ```

2. פותחים את [preview.html](http://localhost:8765/workout/island/design/soccer-motion-v11/preview.html).
3. בוחרים קטגוריה וקליפ, מנגנים בלולאה או במצב מעברים, ובוחרים את ספריית הייחוס v9 או v10. אפשר לקפוץ למגע, לעצור בכל פריים ולשנות מצלמה וקצב. מסלול הייחוס מוצג פעם אחת; תצוגה במקום מציגה את הנכס ללא תנועת הבקר החיצונית.

כל קובצי ה־GLB בתיקיית `runtime/`, לרבות קובצי הייחוס, נטענים ללא Draco, ללא meshopt וללא WebAssembly. התצוגה משתמשת בספריות three.js, GLTFLoader ו־SkeletonUtils הקיימות ב־`../soccer-motion-v8/runtime/vendor/` שב־main; לא נוסף עותק vendor לחבילה. יש להגיש את הדף דרך HTTP יחד עם הנתיב הזה. `file://` אינו מסלול ההפעלה.

כל נכסי הפעולה מסומנים `loop:false`: אלה פעולות חד־פעמיות. מצב הלולאה של התצוגה ממשיך פעולות תנועה ביתרת מחזור הריצה של v10 (כ־0.533 שנ׳), ומחבר פעולות מעמידה במעבר פוזה של 0.18 שנ׳. מיקום וסיבוב מצטברים בין המחזורים; מסלול הייחוס אינו חוזר לאחור. הכדור נשאר מוצג בהמשך הריצה ומתחבר למסלול המחזור הבא. זהו replay לצפייה, וה־GLB המקורי נשאר פעולה חד־פעמית. משך הסגירה לכל קליפ נחשף ב־`loopBlendSeconds` ב־snapshot ונמדד בדוח, בנפרד מפער סוף–תחילה של הנכס המקורי.

## חוזה הנכסים

| שדה | משמעות |
|---|---|
| `id`, `category`, `role` | מזהה יציב, קבוצת פעולה ושחקן שדה או שוער |
| `duration`, `frameCount`, `nativeRate` | זמן ופריימים מקוריים; מספרי פריימים מתחילים ב־0 |
| `events`, `event`, `contactFrame` | כל האירועים, אירוע ראשי והפריים שלו |
| `supports` | עצם, טווח זמן ועוגן במרחב הייחוס לבדיקת נטיעה |
| `entry`, `exit` | קליפ ייחוס, פאזה בשניות ומשך blend מפורש |
| `referenceRootMotion` | מסלול מדידה ותצוגה חיצוני בלבד |
| `ball` | רדיוס ומסלול חזותי לתזמון המגע |
| `cadence` | יעדי צעדים ונגיעות לכדרור, כאשר השדה קיים |
| `actors` | דמויות נוספות ומיקומן בחגיגה קבוצתית, כאשר השדה קיים |
| `asset`, `bytes`, `sha256` | קובץ הריצה ומזהה התוכן המדויק שלו |

הצירים הם ‎+Y למעלה, ‎+Z קדימה ו־‎+X שמאל אנטומי; היחידות מטרים. הסיבובים הם quaternion במרחב ההורה בסדר xyzw. ל־GLB יש 18 ערוצי סיבוב וערוץ תרגום אגן אחד. `Root` נשאר זהות ו־`rootMotion:false`: תנועת השחקן על המגרש אינה נאפית לתוך הנכס.

`referenceRootMotion.samples` מגדיר את המסלול שבו חושבו העוגנים, האירועים והכדור. מדידת הנטיעה מחילה אותו פעם אחת. בקר המשחק אחראי למיקום ולכיוון: אם הוא כבר מזיז את השחקן, אין להוסיף שוב את מסלול הייחוס. נעילה שנמדדה לאורך מסלול הייחוס אינה הבטחה לנעילה תחת כל מהירות או מסלול אחרים שהבקר יבחר.

`events[].time = events[].frame / nativeRate`. `bone` ו־`local` מזהים נקודה על הדמות; `position` היא נקודתה במרחב הייחוס. `normal`, כאשר קיים, הוא כיוון במערכת העצם מנקודת המגע אל מרכז הכדור. `ballContact:true` מסמן מגע בכדור. אירועי קרקע, התנגשות גוף או חגיגה נשמרים כסוג המגע האמיתי שלהם, והחטאה אינה מקבלת מגע כדור מלאכותי. `distanceMeters` מתאר את מרחק מסלול הכדור המתוכנן של הפעולה; הוא אינו תוצאת מנוע פיזיקה.

`ball.keys` או `ball.samples` מתארים מרכז כדור במרחב הייחוס, בתוספת רדיוס. המסלול משמש לבדיקה ולהדגמה; חיבור למשחק צריך להעביר את אירועי הבעיטה, התפיסה והשחרור למערכת הכדור שלו. אין כאן שינוי בעלות אוטומטי, זיהוי שער או הכרעת תיקול.

פוזות v9 ו־v10 נמסרות מקומית תחת `runtime/reference/`. פוזות v9 הועתקו מהאפייה הלא דחוסה של v10; מקור הערוצים הוא קומיט v9 ‏`5d516207d66cdf91af062b93142e04c6dcbae131`. פרטי המקור וה־SHA-256 נמצאים ב־[provenance.json](verification/provenance.json). אין תלות בענפי v9 או v10 בזמן ריצה.

הפרש פוזה גולמי לייחוס ותוצאת המעבר המוצג הם שתי מדידות שונות. בחירת v9 בתצוגה מערבבת מול פוזות v9; בחירת v10 מערבבת מול פוזות v10. חיבור בפועל צריך לשמור גם על פאזה, מהירות ותזמון אירועי הכדור של הבקר.

## הפקה ובדיקה

כל הסקריפטים כותבים בתוך תיקיית v11 בלבד. יצירת התנועה משתמשת ב־IK במצב לא מקוון; הנגן והבדיקה המספרית קוראים ערוצים אפויים ואינם מתקנים את הפוזה בזמן ריצה. הגאומטריה נקראת מקובצי v10 שכבר פוענחו, ולכן אין שלב פענוח Draco בצינור v11.

הפקודות הבאות רצות משורש המאגר, לאחר שהמקורות המצומצמים של v9 ו־v10 זמינים לצורך שחזור:

```sh
node workout/island/design/soccer-motion-v11/source/author.mjs
node workout/island/design/soccer-motion-v11/source/bake.mjs
node workout/island/design/soccer-motion-v11/source/calibrate.mjs
node workout/island/design/soccer-motion-v11/source/bake.mjs
node workout/island/design/soccer-motion-v11/source/calibrate.mjs --smooth-dribbles
node workout/island/design/soccer-motion-v11/source/bake.mjs
node workout/island/design/soccer-motion-v11/verification/check.mjs --validator /tmp/soccer-v11-tools/node_modules/gltf-validator
node workout/island/design/soccer-motion-v11/verification/surfaces.mjs
PLAYWRIGHT_MODULE=/tmp/soccer-v11-tools/node_modules/playwright/index.mjs node workout/island/design/soccer-motion-v11/verification/browser-check.mjs
node workout/island/design/soccer-motion-v11/source/report.mjs
node workout/island/design/soccer-motion-v11/verification/integrity.mjs
```

כלי הפיתוח gltf-validator ו־Playwright מותקנים מחוץ לחבילה. אפשר להכין תיקייה זמנית:

```sh
npm install --cache /tmp/soccer-v11-npm-cache --prefix /tmp/soccer-v11-tools gltf-validator@2.0.0-dev.3.10 playwright
```

לבדיקת הדפדפן נדרש Chromium; נתיב ברירת המחדל הוא `/usr/bin/chromium`. מאמת Khronos בודק את מבנה כל ה־GLB. בדיקה עצמאית קוראת float32 מהקבצים, מבצעת slerp ו־FK ב־120Hz ומודדת מרכז סוליה, קדמה ועקב. בדיקת המשטח מודדת את הכדור מול הרשת המונפשת. בדיקת הדפדפן טוענת את כל הקבצים, מפענחת טקסטורות ומנגנת כל קליפ בלולאה ובמעברים תחת CSP שחוסם WebAssembly. ראיות המדידה קשורות ל־SHA-256 של הנכסים. אחרי הפקת הדוח והרישיונות, `verification/integrity.mjs` קורא כל קובץ בחבילה ומשווה גודל, SHA-256 ושורת רישיון מול המניפסט; המניפסט עצמו מופיע ברישיונות ומוחרג רק מ־hash של עצמו.

זו מסירת נכסים ו־PR טיוטה. לא נמדדו כאן קצב פריימים בטלפון, משחק מלא או שיפור בתחושת המשחק. לאחר החיבור נדרשת מדידה חוזרת עם בקר התנועה ופיזיקת הכדור בפועל. קוד קיים, שחרורים, תגי גרסה, `CLAUDE.md`, ‏`ops` ובדיקות קיימות אינם חלק מהשינוי.
