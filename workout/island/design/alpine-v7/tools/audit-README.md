# בדיקות מסירה עצמאיות

הכלים קוראים את **קובצי המסירה הדחוסים** ואינם משתמשים בנתוני מחולל הגאומטריה כמקור למספרים. דוחות הנכסים והדפדפן נשמרים ב־`verification/`, דוחות התנועה ב־`motion/verification/`, והדוח המסכם ב־`REPORT.md`. התצוגה המקומית אינה זקוקה לכלים אלה, ל־npm או לבנייה. כל הפקודות להלן מופעלות משורש המאגר.

תלויות הבדיקה מותקנות מחוץ למאגר ב־`/tmp/alpine-v7-tools`. סביבת העבודה השתמשה ב־Node 24.19.0, ב־`@gltf-transform/core` ו־`extensions` בגרסה 4.2.1, ב־`draco3dgltf` בגרסה 1.5.7, ב־`gltf-validator` בגרסה 2.0.0-dev.3.10 וב־`sharp` בגרסה 0.34.5. כלי הדפדפן משתמשים ב־Playwright Core מאותה התקנה וב־`/usr/bin/chromium`.

1. הפעילו משורש המאגר את בדיקת הנכסים:

   ```sh
   node workout/island/design/alpine-v7/tools/audit-assets.mjs --modules /tmp/alpine-v7-tools
   ```

   התוצאה נמצאת ב־`verification/asset-audit.json`, טבלת המשקלים ב־`verification/asset-weights.md`, ודוחות Khronos המלאים ב־`verification/gltf/`. נבדקים GLB 2.0, תקציב קובץ, Draco בכל primitive, משאבים מוטמעים, פענוח עצמאי, 18 עצמות ושמות/הורות קנוניים, inverse bind matrices, משקלים מנורמלים, אטלס יחיד בגודל תקין, UV ודגימות צבע בפועל, כיוון הפאות העליונות של הציוד, כל 14 הקליפים, זמני מפתח וקווטרניונים, LOD, חותמות ומספרי ה־manifest. מפות חוזרות נבדקות לאחר פענוח תמונה: השוליים הנגדיים חייבים להתאים להצהרה.

2. הפעילו את דגימת האנימציות המוטמעות:

   ```sh
   node workout/island/design/alpine-v7/tools/audit-motion.mjs --modules /tmp/alpine-v7-tools --all-lods
   ```

   `verification/motion-audit.json` מתעד 121 דגימות לכל קליפ. הדגל `--all-lods` בודק את כל תשעת קובצי הדמויות; בלעדיו נבדקות שלוש דמויות הבסיס. המדידות כוללות כיפוף ברכיים ונטיית גוף מתוך מיקומי המפרקים בפועל, גובה אגן, סיבוב מצטבר של השורש, רציפות נפילה/קימה, תזוזת נעליים ביחס לסנובורד, גובה קודקודי הציוד לאחר skinning וגובה מקלות קשיחים. המדידות אינן משתמשות בזוויות שהתכוון המחבר ליצור. מדובר באבחון גאומטרי; ביקורת חזותית נפרדת עדיין נדרשת.

   שתי בדיקות תנועה נוספות מפעילות AnimationMixer רגיל על הנתונים המפוענחים:

   ```sh
   node workout/island/design/alpine-v7/tools/motion-boundaries.mjs --all-lods
   node workout/island/design/alpine-v7/tools/motion-json-check.mjs
   ```

   הראשונה יוצרת `motion/verification/dense-boundaries.json`: כל תשעת הקבצים ב־120Hz, זמני מפתח Float32 והפרשים זעירים משני צדיהם, כולל קודקודי מגפיים, לוח ומקלות; גוף מלא נבדק בנפילה ובקימה. השנייה יוצרת `motion/verification/json-playback.json` ומשווה את JSON העצמאי לקליפי GLB בשלוש דמויות הבסיס, כולל שגיאות מפרקים וקודקודי רגל מייצגים. שתי הבדיקות שומרות SHA של הקלטים; שינוי קובץ מחייב דוח חדש.

3. לאחר אריזת דפי התצוגה הפעילו בדיקה של הבתים המוטמעים בפועל:

   ```sh
   node workout/island/design/alpine-v7/tools/audit-package.mjs
   ```

   `verification/package-audit.json` מפענח במעבד את המטענים המקומיים ואת ה־gzip של דף התצוגה העצמאי. הוא משחזר גם מטענים המחולקים למקטעי תוכן משותפים, ובודק כל מקטע וכל GLB, תמונה ומודול מול SHA-256 של קובצי המסירה. לכן דף מקומי שנארז לפני שינוי נכסים אינו יכול להסתמך על בדיקת נכסים חדשה כאילו הוא כבר מציג אותם. הבדיקה אינה מפעילה את קוד המודולים ואינה מפעילה GPU.

4. לאחר הקפאת המקורות והאריזה הפעילו את בדיקת הממשק:

   ```sh
   node workout/island/design/alpine-v7/tools/browser-audit.mjs
   ```

   `verification/browser-audit.json` מתעד שני מסכים מדויקים, 390×844 ו־844×390, ב־DPR1.5. נבדקים בחירת דמות/קליפ, השהיה, seek, חלקיקים בשלוש התאורות, LOD, מחוות ומסגור הגוף והציוד. סריקת המסגור מקרינה את כל הקודקודים לאחר skinning דרך מטריצת המצלמה בפועל, בשלוש דמויות, 14 קליפים ושני מרחקים בשתי האוריינטציות; זמני נפילה נוספים מכסים שלבי ביניים קריטיים. מספר הדגימות בפועל מתועד בכל שער בדוח. במהלך סריקת גאומטריה זו בלבד מדלגים על רסטריזציה; עדכון התנוחה, השלד והמצלמה נשמר. אין מדובר באותו מספר של רינדורי GPU או בהשוואת פיקסלים.

   בדיקה ממוקדת נוספת דורשת אפס חפיפות של קודקודי ראש, אמות וידיים עם מלבן בקרות הדמות בפועל, עבור נפילה וקימה בתצוגת הקרבה. נכללים קודקודים שמשקל עצמות אלה בהם גדול מ־0.2. לפני כל תנוחת נפילה/קימה נבחר קליפ אווירי ואז מתבצעת בחירה אמיתית דרך אירועי פקדי הממשק; כך נבדק איפוס המצלמה בלי לאפסה בעקיפין דרך API של בחירת מרחק. גם זמן התנוחה וכיוון המצלמה נבדקים. בדיקות הממשק והחלקיקים, צילומי הסבב האחרון והמטריצה מפעילים רינדור ממשי. הדפדפן מנותק מרשת, ושגיאות דפדפן/קונסולה ובקשות HTTP נשמרות בדוח. ניווט `file://` נבדק בנפרד; חסימת `ERR_BLOCKED_BY_ADMINISTRATOR` מתועדת כמגבלת המדיניות המנוהלת, וה־HTML העצמאי נבדק אז ב־`about:blank` עם רשת כבויה. אין שינוי של המדיניות כדי לעקוף חסימה.

5. הריצו מטריצה מלאה אחת, ללא תהליך רינדור נוסף במקביל:

   לפני הרצה חדשה, אם `verification/matrix/` כבר מכילה ראיות, העבירו את **התיקייה השלמה** לארכיון שמור. אין לרוקן את קובץ המקרים או לדרוס צילומים כדי להתחיל מחדש; בקר ההרצה מסרב לדרוס יומן קיים.

   ```sh
   taskset -c 0-2 node workout/island/design/alpine-v7/tools/matrix-soak.mjs --dwell 10 --limit 504
   ```

   אלה 3 דמויות × 14 קליפים × 3 תאורות × 2 מרחקים × 2 אוריינטציות. כל שילוב נצפה לפחות 10 שניות: **84 דקות לכל הפחות**, בתוספת טעינה, בדיקות סיום וצילומים. Chromium פועל עם ANGLE SwiftShader בתוכנה, DPR1.5 ורשת כבויה. פרוטוקול schema2 דורש לפחות שני רינדורים ושני שינויי זמן שנצפו בעקבת rAF נפרדת; לאחר עשר השניות מוגדר timeout של 45 שניות להשלמת תנאי ההתקדמות. מצב הריצה נשמר ב־`snapshot` עם `progressObservation`, כולל פער rAF מרבי מתחילת התצפית ועד סופה ונראות/מיקוד הדף. קליפ חד־פעמי שלא הסתיים באופן טבעי מקבל לאחר התצפית `endProbe` נפרד: seek ל־50 מילישניות לפני הסוף, עם timeout של 45 שניות לעצירה בפועל. אין טענה שכל קליפ מתנגן בשלמותו בעשר שניות תחת רינדור התוכנה. תוצאת הסיום, מדידת המשאבים ומקור התנוחה המצולמת נשמרים בנפרד, והאישור דורש גם התקדמות אמיתית וגם סיום טבעי או בדיקת סיום מוצלחת.

   ריצת המסירה מוגבלת באמצעות `taskset -c 0-2` לשלוש ליבות בתוך מכסת cgroup של ארבע ליבות. `execution` מתעד את גרסת Node, זיקת המעבד והמכסה בפועל; `toolSourceSHA256` מזהה את כלי המטריצה בזמן ההפעלה. אלה תנאי סביבת הבדיקה בתוכנה. ניסיון 04, לרבות כישלון 062 והאבחון ששינה את זיקת המעבד, נשמר בנפרד ואינו מצורף לספירת המקרים של ריצת המסירה.

   בקמפיין המסירה נשמרו 285 מקרים שעברו לפני timeout של 30 שניות בצילום מקרה 286. לאחר שמירת היומן, הרשומות, הלוג ובקר ההרצה ב־`verification/matrix/continuation-01/`, הופעל `--resume` עם אימות קשיח של הקידומת ושל אותה חבילה. הקשר רוחב חדש משחזר את 253–285 במלואם, במשך עשר שניות לפחות ובאותם תנאי סיום ומשאבים, לתוך `replay-01/`; אחר כך הוא ממשיך 286–504. השחזור אינו נכלל במניין 504, אך משמר את רצף 252 מקרי הרוחב בהקשר החדש. זהו המשך מאומת לאחר הפסקה, ולא תהליך רצוף אחד. לצילום בהמשך הוגדרו 90 שניות וניסיון חוזר אחד רק במקרה timeout, ללא שינוי התנוחה המושהית. כל ניסיונות הצילום נרשמים.

   `--resume` מיועד לשחזור המסוים הזה, ורק לקידומת 285 המדויקת שנשמרה; הוא אינו מדלג על מקרה כושל. מקור כל מקטע בקר וחותמתו, ה־baseline החדש, 33 השחזורים, ניסיונות הצילום והשמירה של 61 התמונות המקוריות נבדקים ב־`audit-matrix-continuation.mjs`, דרך הבודק העצמאי וכלי הדוח. הכלי מסרב לדרוס יומן מקרים קיים בהרצה חדשה; יש לשמור את תיקיית הראיות הקיימת לפני שחזור נוסף.

   התוצאה הסופית היא `verification/matrix-soak.json`; שורות המקרים וצילומי ביניים נשמרים ב־`verification/matrix/`. דוח תקין דורש 504 מקרים בפועל, ניגון/סיום צפוי, גבולות משאבים ואפס שגיאות/בקשות רשת. הרצה מקוצרת עם `--limit` קטן מועילה לאבחון, אך אינה עוברת את שער המסירה. זמני הרינדור הם זמני הגשת עבודה במעבד; הם אינם מדידת השלמת GPU או הוכחת 30fps בטלפון.

   במהלך הריצה ניתן להפעיל `node workout/island/design/alpine-v7/tools/audit-matrix-observer.mjs --modules /tmp/alpine-v7-tools`. כלי זה קורא בלבד את שורות המקרים והצילומים שכבר נשמרו, ובודק באופן עצמאי סדר וזהות שילובים, משך, DPR, זהות חבילה, מצב ניגון, גבולות משאבים ומידות צילומים. הוא אינו מפעיל דפדפן או GPU. תצפיותיו נשמרות ב־`verification/matrix-observer.json` וביומן JSONL; מצב `incomplete` אינו אישור של המטריצה המלאה.

   למעקב קצר ללא כתיבה: `node workout/island/design/alpine-v7/tools/watch-matrix.mjs --wait 50`. הוא מחזיר מיד כשנוסף מקרה או שחזור, כשנוצר דוח סופי או כשמתגלה תהליך מת ללא דוח; ההמתנה מוגבלת ל־50 שניות. `--hold` ממתין את מלוא הזמן גם כשיש התקדמות, אך עדיין חוזר מוקדם בסיום, בכישלון או במות התהליך. הנתונים נקראים מ־`run-state.json`, מ־`cases.jsonl` ומ־`process-id`, כולל בדיקה שה־PID שייך לתהליך המטריצה. הפלט מפריד בין 504 המקרים הראשיים לבין ספירת השחזורים וכישלונותיהם. יומן הריצה נשמר אטומית בתחילתה, אחרי כל baseline וכל מקרה ובסיומה. הכלי אינו מחליף את הבודק העצמאי או מאשר מטריצה חלקית.

   `node workout/island/design/alpine-v7/tools/audit-matrix-gallery.mjs` יוצר את `verification/matrix/index.html` מהתצפיות והצילומים הקיימים, עם מסנני תאורה, דמות, מרחק, מסך וקליפ. המטא־נתונים מוטמעים ב־HTML, והתמונות נטענות מנתיבים יחסיים בלבד. יש ליצור את הגלריה שוב אחרי השלמת המטריצה כדי לכלול את כל 108 הצילומים.

6. הפעילו את בדיקות המאגר באמצעות ההגדרה הנתמכת של הדפדפן המותקן:

   ```sh
   ISLAND_PLAYWRIGHT="$PWD/workout/island/design/alpine-v7/tools/system-chromium.mjs" node workout/island/design/alpine-v7/tools/repository-check.mjs
   ```

   המתאם משנה רק את בחירת קובץ ההפעלה של Chromium דרך `ISLAND_PLAYWRIGHT`; הוא שומר את ארגומנטי הבדיקות ואת בדיקות ה־CSP. ניתן להגדיר `ALPINE_PLAYWRIGHT_MODULE` ו־`CHROMIUM_PATH` להתקנה אחרת. `verification/repository-tests.json` שומר את סיכום `npm test`, כולל כישלונות ודילוגים. הפלט הגולמי נשמר ב־`/tmp/alpine-v7-repository-tests.log`, כדי לא להעתיק לריפו נתוני fixtures שאינם שייכים לנכסים. אין לערוך בדיקות קיימות כדי להשיג הצלחה.

7. השלימו את ציוני הביקורת ואת שעון העבודה לפני יצירת הדוח:

   `verification/scores.json` מכיל `reviewedAt` ו־`criteria`: בדיוק שישה אובייקטים עם `id`,‏ `label`,‏ `score`,‏ `evidence` ו־`notes`. המזהים הם `character`,‏ `carving`,‏ `snow`,‏ `trees`,‏ `background`,‏ `consistency`. כל ציון חייב להיות 8–10 עם ביקורת כתובה ורשימת קובצי ראיה מקומיים קיימים. ציונים נקבעים לאחר צפייה בתמונות הסופיות; הכלי אינו מעניק אותם.

   `verification/work-log.json` חייב להכיל `startedAt` ו־`completedAt` אמיתיים, ללא זמן עתידי, במשך 120 דקות לפחות. זמן הסיום חייב להיות אחרי השלמת בדיקות הדפדפן, המטריצה והמאגר. אין להסיק מזמני קבצים כאילו הם זמן עבודה.

   ```sh
   node workout/island/design/alpine-v7/tools/report-final.mjs --check
   node workout/island/design/alpine-v7/tools/report-final.mjs
   ```

   `--check` אינו כותב דבר. הפקודה השנייה יוצרת `REPORT.md` רק אם כל השערים עוברים: ציונים וראיות, נתוני נכסים ותנועה עדכניים, SHA של החבילה והמודולים, דפדפן, בדיקות המאגר, בדיוק 504 שילובי מטריצה ייחודיים מלאים ב־DPR1.5, משך עבודה והיקף Git. כל קובץ חסר, בדיקה כושלת או חותמת ישנה מונעים יצירת דוח חדש.

8. לאחר יצירת הדוח וסיום כל כתיבת קובצי המסירה הפעילו:

   ```sh
   node workout/island/design/alpine-v7/tools/audit-delivery.mjs --modules /tmp/alpine-v7-tools
   ```

   `verification/delivery-audit.json` בודק ששינויי Git הם תוספות בלבד בתוך התיקייה, שקיימים שישה סבבים לפחות עם ביקורת כתובה וארבעה צילומים במידות המדויקות, ושהבדיקות העצמאיות הושלמו. חותמות דוחות הנכסים והתנועה, כולל הדגימה הצפופה שב־`motion/verification/dense-boundaries.json`, חייבות להתאים לקבצים הנוכחיים. דוח הדפדפן חייב לעבור ולהציג אותה חבילה ואותן חותמות מודולים שנבדקו בדוח החבילה הסופי. הוא יוצר גם `verification/file-inventory.json` עם בתים, MB ו־SHA-256 לכל קובץ ומציג את הגדולים ביותר. את הבדיקה יש להריץ שוב לאחר שינוי קובצי המסירה. משך העבודה נקרא מ־`verification/work-log.json`; אין להסיק מזמני קבצים כאילו הם תיעוד של זמן עבודה.
