# ליטוש הכדורסל באי · v1

החבילה מיועדת ל־`workout/island` על בסיס `main` בקומיט `9e95482fbe1887856cbca69fd43c1c77ba62cff4`. הענף `codex/hoops-polish-patches-v1` מוסיף את תיקיית המסירה בלבד. השינויים למשחק ולמניפסט האופליין נמצאים בפאצ׳ים שבתיקייה.

## מה לבדוק במשחק

כל השיפורים פעילים כברירת מחדל לאחר החלת הפאצ׳ים. מוסיפים את הדגלים לכתובת האי לפני פתיחת משחק הכדורסל. `?hoopsPolish=0` מחזיר את הפיזיקה, המראה ותמהיל השמע הקודמים וגובר על כל דגל משני. אפשר לצרף פרמטרים קיימים באמצעות `&`.

| שיפור | דגל לכיבוי | תוספת קריאות ציור / משולשים | מה רואים או שומעים |
|---|---|---:|---|
| תגובת הכדור לטבעת | `hoopsPolishPhysics=0` | `0 / 0` | פגיעה חזקה מנתרת. במגע חלש מלמעלה הכדור יכול להתאזן לרגע על הצינור, ואז להתגלגל פנימה או החוצה לפי נקודת המגע והתנע. |
| רטיטת הטבעת | `hoopsPolishRim=0` | `0 / 0` | הטבעת בצד המגע מתנדנדת סביב התושבת, עם פיתול קטן בפגיעה צדית. |
| תנועת הרשת | `hoopsPolishNet=0` | `0 / 0` | הטבעת או כדור שעובר בסל מניעים את הרשת בצד הרלוונטי. הקשרים העליונים נשארים מעוגנים והחוטים חוזרים לצורת המנוחה. תגובות הטבעת והרשת מחושבות לפי טיק המשחק, גם בהילוך חוזר. |
| צלילי פגיעה | `hoopsPolishAudio=0` | `0 / 0` | שלוש נקישות טבעת לפי העוצמה, שלוש קפיצות פרקט, חבטת לוח, גרסאות עמומות לריפוד ולחסימה ורשרוש רשת במעבר כדור. |
| תאורה | `hoopsPolishLighting=0` | `0 / 0` | אור ראשי מתון יותר, עם מילוי רך והחזר פרקט מעט מפוזר יותר באולם v8. |
| צל כדור | `hoopsPolishShadow=0` | `0 / 0` | צל מגע מרוכז בכדרור, שמתפשט ונחלש כשהכדור מתרומם וזז בכיוון התאורה. |
| מעברים | `hoopsPolishTransitions=0` | `0 / 0` | שחרור מהידיים ותפיסה מתחברים בתנועה רציפה, והמצלמה נכנסת לזווית קו הבסיס ברכות אחרי סל. |

בדיקת הדפדפן חשפה שאירוע סל מכדור חופשי הגיע למסך התוצאה בלי מערך התוצאה הדרוש ל־HUD. הפאצ׳ מוסיף אותו גם כשהליטוש כבוי. צורת הניקוד, ערך הסל והחוקים הקיימים משמשים גם במסלול הזה.

## מדידת רינדור

Chromium `151.0.7922.173` עם SwiftShader מדד 196 פריימים ב־28 הרצות. באולם v8 נמדדו שני גדלי תצוגה ברמת איכות 1 וב־LOD 0. בכל גודל הושוו הקוד המקורי, כל שבעת הדגלים יחד, כל דגל בנפרד ומתג הכיבוי. המצלמה, מצב השחקנים ורמת הפירוט הוצמדו בין ההרצות. קהל התלת־ממד האדפטיבי כובה למדידה. שבע נקודות הדגימה כללו מעוף, פגיעה בטבעת, מעבר ברשת, מגע ברצפה, חזרה למנוחה, מסירה ותפיסה.

הזוגות בטבלה הם קריאות ציור / משולשים לפריים, והיו זהים לפני ואחרי בכל תרחיש תואם. העמודה הכוללת סופרת את קריאות WebGL של הפריים, כולל מפת הצל והשתקפות הפרקט כשהן פעילות.

הטבעת והרשת משתמשות באותם מאגרי קודקודים וקריאות ציור של האולם. בפגיעה המבוקרת ב־v8 נמדדו תזוזות של כ־3.2 ס״מ בטבעת וכ־4.8 ס״מ בחלק הגמיש של הרשת. שני הצדדים נבדקו וחזרו לערכי המנוחה. בסדרת מגע איטי מלמעלה נמדדו 317–350 מ״ש מהמגע הראשון עד שהכדור ירד לגובה 9 ס״מ מעל מישור הטבעת. המדידה נערכה ברינדור תוכנה בגדלי תצוגה של טלפון.

## החלה ובדיקות

1. משורש checkout של הענף, בודקים את ארבעת הפאצ׳ים. הסקריפט בודק את כל החבילה לפני כתיבה ומדווח אם היא כבר הוחלה.

   ```bash
   bundle=workout/island/design/hoops-polish-patches-v1
   "$bundle/apply.sh" --check
   ```

2. מחילים ב־checkout המיועד להרצת המשחק, ואז מריצים את הבדיקות. אפשר לתת לסקריפט `--target PATH` כדי לעבוד מול checkout נפרד. Chromium ו־Playwright דרושים לבדיקה השנייה. אם Chromium מותקן מקומית, אפשר למסור את הנתיב באמצעות `CHROMIUM_PATH`.

   ```bash
   "$bundle/apply.sh"
   node --test "$bundle/tests/polish.test.mjs"
   node "$bundle/tests/browser.mjs"
   ```

3. לוחצים על הכדורסל באי ובודקים זריקה נקייה, פגיעה בלוח וזריקה קצרה אל הטבעת. משווים מול `?hoopsPolish=0`. `apply.sh --reverse` מסיר את הפאצ׳ים מה־checkout. `HOOPS_BASELINE_ROOT` מצביע בבדיקות על checkout נקי להשוואה לקוד שלפני הפאצ׳ים. `HOOPS_BROWSER_JSON` קובע נתיב לדוח המדידה הגולמי של הדפדפן.

החלה חוזרת, ביטול חוזר והשוואת הקבצים לבסיס עברו ב־checkout זמני. תשע הבדיקות בחבילה ו־314 בדיקות הכדורסל, השמע והאופליין של המאגר עברו. מבחן הדפדפן הפעיל דרך המנוע פגיעות בטבעת, בלוח וברצפה וסל מכדור חופשי. כל מגע השמיע את הדגימה המתאימה, ובחסימה יזומה של קובץ Ogg לטבעת הושמע קובץ ה־MP3 שלו.

`npm test` הניב 4,371 בדיקות שעברו ו־86 שדולגו, עם אותה שגיאת נתיב Chromium בבדיקת רועיקי גם בבסיס וגם אחרי הפאצ׳ים. בהרצה חוזרת של קובץ הבדיקות עם Chromium המותקן, כל חמש הבדיקות שלו עברו.
