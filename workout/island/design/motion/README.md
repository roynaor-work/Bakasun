## שלד ומערכת צירים

השלד הקנוני כולל 18 עצמות, כולל Root:

```text
Root → Hips → Spine → Chest → Neck → Head
Chest → LeftArm → LeftForeArm → LeftHand
Chest → RightArm → RightForeArm → RightHand
Hips → LeftUpLeg → LeftLeg → LeftFoot
Hips → RightUpLeg → RightLeg → RightFoot
```

`skeleton.bones` מגדיר לכל עצם הורה והיסט מנוחה מקומי במטרים, `restTranslationMeters`. הפרופורציות הן של מפרט הדמות בגובה 1.60 מ׳: אגן 0.86, כתפיים 1.30, ראש 1.47, ירך 0.41 ושוק 0.37. הרצפה היא Y=0; למעלה +Y, קדימה +Z ושמאל אנטומי +X. ימין ושמאל אינם מתחלפים ב־RTL.

`rotations` מכיל quaternion יחידה `[x,y,z,w]` לכל עצם בכל פריים, כולל עצמות שאינן זזות. זהו סיבוב מקומי מוחלט בבסיס הקנוני, לא Euler ולא סיבוב עולמי. בסיס המנוחה הקנוני משתמש בסיבובי זהות; מנח הזרועות של כ־35° מופיע בפוזות עצמן. הרכבת סיבובים: `qWorld = qParentWorld * qLocal`; וקטור מסתובב באמצעות `q * [v,0] * inverse(q)`.

`skeleton.designBoneMap` ממפה לשמות מפרט הדמות, למשל `LeftUpLeg → thigh.L` ו־`RightHand → hand.R`. בייצוא לשלד יעד יש להתאים צירי עצמות ו־bind pose תחילה. אם המתאם של היעד מצפה ל־`qBind * qDelta`, לחשב אחרי ההתאמה `qDelta = inverse(qBind) * qLocalTarget`. העתקת הערכים הקנוניים ישירות לשדה delta של שלד אחר אינה התאמה תקינה.

## קריאת קליפ ודגימה

| שדה | משמעות |
| --- | --- |
| `durationSeconds`, `loop`, `rootMotion` | משך ומדיניות מהמקור; כל הקליפים in-place |
| `keyframes[].time` | זמן מנורמל עולה ממש, כולל 0 ו־1; שניות = זמן × משך |
| `keyframes[].rotations` | פוזה מלאה של 18 העצמות |
| `hipsOffsetMeters` | היסט חזותי של Hips, נוסף להיסט המנוחה; מאפשר כריעה, נשימה ונפילה |
| `referenceRootTranslationMeters` | מסלול בדיקה חיצוני בלבד; אינו ערוץ תנועה של Root |
| `events` | אירועי המקור עם `atSeconds` ו־`time` מנורמל נוסף |
| `ballContacts` | נקודת מגע בכדור או מערך ריק, בהתאם לפעולה |
| `supportContacts` | חלונות תמיכה ויעדי סוליה לבדיקת החלקה |

בין שני פריימים בזמן `a..b`, לחשב `u=(t-a)/(b-a)` ואז `w=u*u*(3-2*u)`. לערבב סיבובים ב־slerp בקשת הקצרה עם המשקל `w`, והיסטים ב־lerp באותו משקל. זו משמעות `interpolation.easing: smoothstep`; אין לבצע lerp ישיר לרכיבי quaternion ללא נרמול. הדגימות הצפופות כוללות גם את זמני המגע וגבולות התמיכה במדויק.

Root נשאר בראשית עם סיבוב זהות. תזוזת הדמות וסיבובה בעולם שייכים לסימולציה; אין להוסיף את `referenceRootTranslationMeters` למיקום הדמות במשחק. המסלול מאפשר לבדוק תנועה in-place ביחס למהירות התקדמות ידועה. בסיבוב, הגוף נוטה והאגן מתפתל מקומית; שינוי כיוון העולם מגיע מהסימולציה.

בקליפים ללא כדור מופיעים `ballContactStatus: none`, מערך ריק ו־`ballContactReason`. אין מגע כדור מומצא בריצה, בנפילה או בסקי. בסקי `equipmentContacts` משמר את סמני המקלות והנחיתה. כל האירועים חזותיים: זמן הקליפ אינו מפעיל פיזיקה, ניקוד, בעלות בכדור או תוצאה.

## מחזור ריצה ותמיכת רגליים

מחזור הריצה הוא 0.72 שניות, עם מגע שמאל ב־0 וימין ב־0.5; הפוזה והיסט האגן ב־1 זהים ל־0. עקומת ההאטה מגיעה למהירות אפס בקצות מקטעי הדגימה. סוף `fall` ותחילת `recover` זהים גם הם.

לבדיקת הריצה מוגדרת מהירות 2.2 מ׳/שנייה ואורך מחזור 1.584 מ׳. התמיכות הן שמאל ב־0..0.24 וימין ב־0.5..0.74. `anchorMeters` קבוע בעולם של מסלול הבדיקה; נקודת הסוליה היא `effectorOffsetMeters: [0,-0.08,0]`. במחזור הבא יש להזיז את עוגני הריצה ב־`cycleAnchorTranslationMeters`, ולא לאפס אותם לאותו מקום בעולם.

ב־`mode: plant` נבדק המרחק התלת־ממדי מעוגן קבוע, בסבילות 2 ס״מ, גם בין פריימי המפתח. בסקי `mode: ski-slide` בודק גובה בלבד: המגלש מחליק על השלג בכוונה, והמגף נשאר מחובר אליו. אין לפרש החלקת סקי כהיתר להחליק רגל נטועה במשחקי הכדור.

## ערבוב ומעברי מצבים

כל רשומות המעבר מהמקור נשמרות בסדרן, כולל עדיפויות ו־wildcard. בנוסף נשמרים `visualBlendSeconds`, `blendCurve`, `sourcePose`, `sourceContinuation`, `targetTime` ו־`footLock`. זמן הערבוב החזותי חיובי בכל מעבר, לרבות `reset`: מצב ואירועים מתאפסים מיד לפי המקור (`crossfadeSeconds: 0`), ואילו הפוזה המוצגת מתערבבת במשך 0.12 שניות.

במעבר יש לשמור את הפוזה המוצגת בפועל ואת מהירויות הסיבוב וההיסט שלה, גם אם היא באמצע ערבוב קודם; זו משמעות `sourcePose: current-displayed`. לפי `sourceContinuation: velocity-extrapolation`, להמשיך את צד המקור מהפוזה השמורה באקסטרפולציה של המהירויות לאורך הערבוב. צד היעד מתחיל ב־`targetTime: 0` וממשיך להתנגן בזמן הערבוב, עם slerp ומשקל smoothstep לאורך `visualBlendSeconds`. אין להחליף את המקור בסוף הקליפ הישן כשאירוע קוטע אותו.

משקל smoothstep מתחיל ב־0 ומסתיים ב־1, עם נגזרת אפס בשני הקצוות: המשך המקור שומר על מהירותו בכניסה, והיעד שומר על מהירותו ביציאה. חוזה זה נועד לרציפות הפוזה והמהירות (C0/C1). הקפאת פוזת המקור בלבד הייתה עוצרת את תנועתו בפתאומיות בתחילת הערבוב; נדרש מימוש המשך המהירות במתאם הצורך.

`footLock: carry-until-release` דורש מהמתאם הצורך לשמר עוגן תמיכה יוצא בעולם דרך הערבוב, לפתור IK של שתי עצמות ותיקון אגן אחרי ערבוב הפוזות, ואז לשחרר משקל בהדרגה עם סיום התמיכה. ההמרה לעולם חייבת לכלול את כל טרנספורמציית הדמות, כולל yaw. ערבוב רוטציות בלבד יכול להזיז סוליה גם כששני הקליפים בנפרד נטועים; נתוני החבילה מגדירים את החוזה למתאם, ואינם מימוש של מתאם כזה.

## בדיקה

משורש המאגר:

```sh
node workout/island/design/motion/validate-motion.mjs
```

אפשר להריץ מכל תיקייה דרך נתיב מלא, וגם לבחור קובץ בודד:

```sh
node /workspace/Bakasun/workout/island/design/motion/validate-motion.mjs /workspace/Bakasun/workout/island/design/motion/soccer.json
```

הנתיב המלא בדוגמה הוא של סביבת העבודה הזו; בשכפול אחר יש להחליף אותו בנתיב המקומי. הבודק מאתר את מקורות האנימציה ביחס למיקומו, ללא תלות בתיקיית ההרצה.

הצלחה מדווחת 32 קליפים בסך הכול, 5 נקודות מגע בכדור ו־147 מעברים אפשריים אחרי הרחבת wildcard והחרגות המקור. נבדקים כיסוי העצמות, quaternion מנורמל, זמנים עולים, קצוות לולאה, התאמה למקורות, סמני מגע וגבולות ערבוב. בדיקת FK של תמיכות דוגמת את כל המפתחות והגבולות ובנוסף 120 דגימות לשנייה; בנפילה ובקימה נבדקות גם נקודות סוליה, כף יד, ראש ומפרקים מול הרצפה. 735 דגימות מעבר בודקות התאמת פוזת הכניסה והיציאה, רציפות C0 וערכי quaternion סופיים ומנורמלים. הן אינן בדיקה של mixer צרכן, המשך מהירות בפועל או IK אחרי ערבוב. שגיאה מחזירה קוד יציאה 1 עם הקליפ והשדה שנכשלו.

הבדיקות הן של נתוני השלד הקנוני. הן אינן טענה שנבדקו skinning, בגד, שיידר, GLB מיוצא או ניגון על טלפון. לאחר התאמת שלד יש לבדוק שוב מגע, רצפה וערבוב, ולשנות קנה מידה גם להיסטים, לעוגנים ולסבילויות. משקל כל JSON הוא פחות מ־1.1 מיליון bytes; זו אינה בדיקת עמידה בתקציב GLB עתידי של 150,000 bytes לדמות.
