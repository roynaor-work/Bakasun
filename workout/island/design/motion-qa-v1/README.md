# מעבדת QA לתנועה

כלי Node מקומי למדידה חוזרת של ספריות כדורגל וכדורסל בגרסאות 8, 9 ו־10, ושל 98 תנועות על שלושת מבני הגוף הגבוהים. כל קובצי הכלי והתוצרים נמצאים בתיקייה זו. אין שינוי במשחק או בקובצי המקור.

## צפייה בתוצאה

1. הגישו את המאגר בשרת מקומי:

   ```sh
   python3 -m http.server 8765
   ```

2. פתחו [דוח ממויין](http://localhost:8765/workout/island/design/motion-qa-v1/output/report.html) או [תצוגת שלד](http://localhost:8765/workout/island/design/motion-qa-v1/preview.html).
3. בדוח בחרו ספרייה, חפשו קליפ ומיינו לפי ציון. לחיצה על קליפ מציגה את הערך, הסף, הראיות, זמן החריגה ותמונת שמונה פריימים. אזור ההשוואה מציג את שתי הגרסאות וקליפים שאין להם התאמה.

התוצרים נשמרים במאגר, ואפשר לצפות בהם בלי להריץ את הניתוח. תצוגת השלד מדגימה את שמונה הפוזות שבתמונה, ללא אינטרפולציה מומצאת. המדידה עצמה משתמשת בדגימות צפופות ובזמני המפתח והמגע.

## הרצה בפקודה אחת

נדרש Node 20 ומעלה ו־Git. אין התקנת npm. הריצו משורש המאגר:

```sh
node workout/island/design/motion-qa-v1/run.mjs
```

הפקודה טוענת את **כל** הספריות והפרופילים, מודדת אותן באותם ספים, וכותבת `output/report.html`, דוח JSON מרכזי, JSON ו־HTML לכל קליפ ותמונת SVG עם שמונה פריימים. היא מעדכנת גם `REPORT.md` עם 20 הקליפים בעלי הציון הנמוך ביותר והסיבה לכל אחד. דוחות קיימים בתיקיית הפלט מוחלפים; המקורות לעולם אינם נכתבים.

מקורות הניתוח ננעלו לקומיטים ב־[sources.json](sources.json). קריאת המקורות נעשית מ־Git, וקובצי המטמון נמצאים ב־`.cache/` בלבד. אפשר להפעיל שוב ללא רשת לאחר מילוי המטמון. הרשימה ב־JSON המרכזי כוללת SHA-256, גודל וקומיט לכל קובץ מקור שנקרא. אם הענפים עדיין לא נמצאים במאגר המקומי, משכו אותם פעם אחת:

```sh
for b in codex/soccer-motion-v9 codex/soccer-motion-v10 codex/hoops-motion-v9 codex/hoops-motion-v10 codex/hoops-tall-v1; do git fetch --depth 1 --filter=blob:none origin "$b"; done
```

מודול three.js נטען **מקומית** מהעותק הקיים של ספריית כדורגל 8. ב־sparse checkout צריך לכלול לפחות את הספרייה הזו:

```sh
git sparse-checkout add workout/island/design/soccer-motion-v8 workout/island/design/motion-qa-v1
```

דוגמאות להרצה ממוקדת ולהשוואה:

```sh
node workout/island/design/motion-qa-v1/run.mjs --library soccer-v9,soccer-v10 --compare 9,10 --out /tmp/soccer-qa
```

```sh
node workout/island/design/motion-qa-v1/run.mjs --library hoops-v10 --fps 120 --out /tmp/hoops-qa
```

פלט HTML משתמש בקובצי התצוגה שבתיקייה זו. לתצוגה בנתיב מותאם מחוץ לתיקייה, העבירו את התוצרים לתיקיית `output` או השתמשו ב־JSON עם תצוגת השלד באותו שרת. הדוח המצורף הופק ב־60Hz; ספים של מהירות ותאוצה מחושבים ביחידות זמן ואינם תלויים במרווח דגימה קבוע.

## מה בדיוק נמדד

[metrics.mjs](metrics.mjs) הוא מקור ההגדרות: כל מדד מפרט נוסחה, יחידות, תקרת ירוק, תקרת צהוב ומשקל. מעל תקרת צהוב הוא אדום. נתון שאינו זמין מופיע באפור ואינו מקבל ציון ירוק. ציון התחושה, 0–100, הוא ממוצע משוקלל של המדדים הרלוונטיים, לצד כיסוי המדידה. מדד רלוונטי שחסר לו מידע מקבל אפס נקודות; מדד שאינו חל אינו משתתף במכנה. ציון עם כיסוי שונה דורש זהירות בהשוואה.

| מדד | משמעות | מגבלה |
|---|---|---|
| החלקת רגליים | תנועת נקודת הסוליה בחלון תמיכה מוצהר | בלי חלון תמיכה משתמשים רק בזיהוי נתמך ומסומן |
| חדירה לרצפה | עומק נקודות סוליה ומפרקים מתחת למישור Y=0 | אינו פענוח קודקודי הרשת הדחוסה |
| קפיצות פוזה | שינוי בין פריימים סמוכים עם נרמול זמן וגובה | תנועה מהירה מכוונת עשויה להצדיק חריגה |
| אנטומיה | טווחי ברך, מרפק ומפרקים על פי השלד | בדיקת טווח גסה; אין אבחנה רפואית או בדיקת כל טוויסט |
| מגע בכדור | הפער בין נקודת מגע מקומית לבין פני הכדור בזמן מגע מוצהר | אין ציון אם הכדור נגזר מאותה יד ואינו מסלול עצמאי |
| רציפות מול המתנה | קצות הקליפ מול עמידת המתנה מתאימה | אינה מריצה את מערבל המשחק או תיקון IK |
| החלקת הגוף | מהירות שורש, קצב צעדים ותנועת הרגל ביחס לשורש | מסלול ייחוס הוא תרחיש המחבר, לא מהירות המשחק בפועל |
| סימטריה | הפרשי אורך עצמות זוגיות ובדיקות תנועה כשמוגדר | זוגות שמאל/ימין באותו שם מושווים זה לזה; בריצה מחזורית נבדקת סימטריית רגליים בחצי מחזור |

צירי הניתוח הם מטרים, Y למעלה. גובה הפרופילים הגבוהים נלקח מהמפרט. בספריות הקנוניות הגובה הוא אומדן שלד: גובה הראש פחות גובה הקרסול ועוד 0.30 מטר עבור כיפת הראש והסוליה; לא נמדד גובה הרשת הדחוסה. יש להביא זאת בחשבון בהשוואה בין שלדים שונים. בכדורגל וכדורסל במקום מחילים את מסלול הייחוס המוצהר רק כאשר הוא חיצוני; בכדורסל 10 מסלול זה כבר מוטמע בצומת Motion בקובץ GLB. נשמרים גם נתוני המיקום המקוריים כדי למנוע הוספת מסלול פעמיים. אירועי מגע, חלונות תמיכה ונתיב כדור נלקחים מהמטא־דאטה, ולא מוכרעים לפי תוצאת משחק.

מודלי הדמויות הגבוהות מכילים שלד סטטי. עבורם מפעילים את מודול ההתאמה המדויק המצורף למקור, על כל 98 התנועות ולכל אחד משלושת המבנים; קפיצות דאנק כוללות את הכיול של התצוגה המקורית. מדד הכדור מוצג כחסר כשאין מסלול עצמאי לאחר ההתאמה. בכדורסל 8 אין קליפ המתנה נפרד, ולכן רציפות עשויה להיות חסרה במקום להמציא עמידת מוצא.

## בדיקות

```sh
node --test workout/island/design/motion-qa-v1/test/*.test.mjs
```

הבדיקות כוללות GLB מלאכותי תקין ופגום, stride/sparse, אינטרפולציית STEP/LINEAR/CUBICSPLINE, חסימת WebAssembly, הזרקת פגמים לכל שמונת המדדים, ספים וכיסוי חסר, ואת כל קובצי הפלט. בדיקת תוצרים מאמתת גם את 495 קובצי הקלט במטמון, ולכן יש להריץ את פקודת ההפקה קודם במחשב חדש:

```sh
node workout/island/design/motion-qa-v1/test/verify-output.mjs
```
 אין עריכה של בדיקות המאגר הקיימות.

## רישיונות

כל הקבצים החדשים מקוריים ומשוחררים כ־CC0-1.0. אין מותגים או דמויות של אנשים אמיתיים. [LICENSES.md](LICENSES.md) כולל רישום מפורש לכל קובץ תוצר וקוד, מקור ואופן ההפקה. three.js הקיים הוא MIT ואינו מועתק או מופץ מחדש בחבילה.

בדיקת דפדפן אופציונלית נמצאת ב־`test/browser-check.mjs`; היא אינה תלות בזמן ריצה. נדרשת התקנה חיצונית של Playwright/Chromium והגדרת `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH` ו־`MOTION_QA_URL` לפי הסביבה. תוצאות הבדיקה שבוצעה למסירה נמצאות ב־[verification/summary.json](verification/summary.json).
