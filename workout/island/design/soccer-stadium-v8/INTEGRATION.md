# חיבור אצטדיון ערב v8

העתיקו את `runtime/` כפי שהיא. היא מכילה את קובצי הריצה המקומיים, כולל three.js r160 ומפענח Draco. אין build, התקנת npm, CDN או שירות רשת. טוענים דרך HTTP(S), לא דרך `file://`. הציגו את הודעת הטעינה של המארח עד שה־Promise מסתיים.

דוגמה למארח שכבר מחזיק `scene`, `camera`, `renderer` ואלמנט `stage` בעל `position: relative`:

```js
import {loadStadium} from './runtime/stadium.mjs';
import {frameBroadcastCamera} from './runtime/cameras.mjs';
import {createBroadcastHUD} from './runtime/broadcast.mjs';

const stadium = await loadStadium({scene});
const hud = createBroadcastHUD(stage, {home: 'בית', away: 'חוץ'});
await hud.ready;
frameBroadcastCamera(camera, {aspect: stage.clientWidth / stage.clientHeight});

function draw(ms, match) {
  stadium.update(camera, ms / 1000);
  hud.update({homeScore: match.home, awayScore: match.away,
    seconds: match.seconds, phase: match.opening ? 'opening' : 'live'});
  renderer.render(scene, camera);
}
// ביציאה: stadium.dispose(); hud.dispose();
```

`THREE` מיוצא גם מתוך `runtime/stadium.mjs`. למארח חדש אפשר להשתמש בו ליצירת הסצנה והרנדרר. החבילה מותאמת ל־r160. אל תכניסו עותק נוסף של three בגרסה אחרת. הגדרות הרינדור של התצוגה: `antialias: true`, ‏`SRGBColorSpace`, ‏`ACESFilmicToneMapping`, חשיפה `1.03`, ‏DPR מרבי `1.25`; אין shadow maps או postprocessing.

| עניין | חוזה |
|---|---|
| יחידות | מטרים; Y כלפי מעלה; אורך המגרש על X; המרכז ב־0,0,0 |
| מגרש | 105 × 68; שערים 7.32 × 2.44; גובה הדשא Y=0 |
| בעלות | המארח מחזיק רנדרר, RAF, מצלמות, משחק, שחקנים ושעון |
| LOD | אוטומטי לפי מרחק מקומי ממרכז האצטדיון: 0 / 115 / 190, עם מרווח היסטרזיס 5 |
| שליטה ידנית | `stadium.setLOD(0 / 1 / 2)` ואז `update(camera, seconds, {autoLOD: false})` |
| נגישות | `update(camera, seconds, {reducedMotion: true})` מפסיק את תנודת הקהל; ה־HUD מכבד גם את העדפת המערכת |
| גג קרוב | `update` מסתיר את הגג והקורות הקרובים כשהמצלמה נכנסת מעל היציע; היציעים ומסך הרוח נשארים סגורים. אפשר לבטל באמצעות `{roofCutaway: false}` למבט חיצוני מכוון |
| מדידה | `stadium.metrics()` מחזיר פירוט משולשים פעילים, תקציב ושארית; כל מופע קהל נספר |
| מצלמות | `view: 'main' / 'close' / 'opening'`; ‏`azimuth` ברדיאנים לסיבוב מלא; מעדכנים `aspect` בסיבוב מסך |
| נתיב נכסים | `baseURL` אופציונלי, URL לתיקיית runtime עם `/` בסוף |
| הסתרת חלקים | `omitParts` הוא מערך שמות חלקים, חל על כל שלוש הרמות; למשל `['Markings','Goals','Nets']` |
| שחרור | `dispose()` מנתק את השורש ומשחרר גאומטריה, חומרים, מרקמים ו־workers; מותר לקרוא פעמיים |
| כישלון טעינה | ה־Promise נדחה; לא מתווסף שורש חלקי. `signal` תומך בביטול לפני/במהלך הטעינה, עם ניקוי לאחר סיום הבקשות שכבר התחילו |

טוענים אצטדיון אחד לכל Scene. בזמן שהוא מחובר הוא מחזיק את רקע הסצנה ואת הערפל; בשחרור מוחזר המצב הקודם, אם המארח לא החליף אותו בינתיים. `root` כולל גם את האורות ואת המטרות שלהם, ולכן תרגום וקנה מידה אינם משאירים את התאורה מאחור.

## התאמה למשחק הקיים

בקונפיגורציה שנבדקה בריפו מגרש המשחק הוא 48 × 30 והשערים 5.4 × 2.3. אין להקטין שער תקני יחד עם האצטדיון ולצפות שהוא יתאים לפיזיקה הקיימת. במסלול החיבור הזה משאירים את סימוני המשחק ואת השערים שלו, מסתירים את המקבילים בחבילה, ומחליפים את הדשא/האצטדיון/הקהל/התאורה הקודמים כדי לא לספור אותם פעמיים:

```js
const stadium = await loadStadium({scene,
  omitParts: ['Markings', 'Goals', 'Nets', 'ContactShadows']});
stadium.root.scale.set(48 / 105, 48 / 105, 30 / 68);
// המשיכו להשתמש במצלמת המשחק ובסימוני/שערי המשחק הקיימים.
```

התקציב המדווח של החבילה המלאה הוא הגבול השמרני; החלקים שהוסתרו יורדים מ־`metrics()`. בזמן החיבור סופרים גם את הסימונים, השערים וכל אפקט אחר שהמארח משאיר. 40,000 הוא התקציב הכולל של כל מה שאינו שחקנים, ולא רישיון להוסיף עוד תפאורה מעליו. קוד המשחק, ה־release והגרסה לא שונו בחבילה הזאת.

## בדיקה מקומית

1. מתוך תיקיית החבילה הריצו:

   ```sh
   node --test
   python3 -m http.server 8765 --bind 127.0.0.1
   ```

2. פתחו [תצוגה מקומית](http://127.0.0.1:8765/preview.html), עברו בין שידור רחב, קרוב ופתיחה, סובבו מצלמה ומסך ובחרו את רמות הפירוט.
3. התוצאה הרצויה: אין שגיאות טעינה, היציעים מקיפים את המגרש, ה־HUD קריא, ורק רמת LOD אחת נראית. הבדיקה ב־Node מפענחת את שלושת ה־GLB עם ה־WASM המצורף, סופרת פאות אמיתיות לכל חלק, מכפילה מופעי קהל ומוודאת סך של עד 40,000. אין תלויות npm לבדיקה הזאת.

Draco נטען ב־Worker סטטי מאותו מקור. יש להגיש את כל `runtime/` מאותו מקור של המשחק; מסלול הטעינה מתאים למדיניות `script-src 'self'` ו־`connect-src 'self' blob:` הקיימת, ללא שינוי CSP. WebAssembly מפוענח ב־Worker. הטעינה אינה רושמת service worker ואינה משנה אחסון מקומי.

בדיקת הסריקה מתייחסת לשלוש המצלמות המצורפות, בשתי מידות המסך וב־360°; השמיים מעל קו הגג הם חלק מהפתיחה. מצלמת טיסה חופשית כלפי מעלה אינה מבט משחק. טלפון פיזי נדרש לאימות יעד 30fps לאחר החיבור עם השחקנים.

לסגירת פער הביצועים: הריצו את המשחק המחובר בטלפון בינוני פיזי, ב־DPR עד 1.25, עם השחקנים והאפקטים הרגילים. לאחר חימום של דקה מדדו דקה בכל כיוון מסך ובכל LOD, כולל תנועה ומעברי מצלמה. שמרו דגם מכשיר, גרסת דפדפן, מספר פריימים שהוצגו ו־p50/p95 של זמן הפריים. תנאי הקבלה ליעד הוא לפחות 30 פריימים לשנייה; יש לבדוק גם קפיצות בזמן טעינה ומעבר LOD. תוצאות SwiftShader המצורפות אינן סוגרות בדיקה זו.
