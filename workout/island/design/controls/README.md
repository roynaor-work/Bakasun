## גאומטריה ו־safe area

ה־JSON משתמש בפיקסלי CSS ובנקודת מוצא פיזית משמאל למעלה. `x/y/width/height` מתארים בדיוק את המידה הנקובה עם safe area אפס. `anchor_x/anchor_y` וה־offsets מאפשרים הוספת שולי מכשיר בלי לשנות את גודל היעד:

| עוגן | חישוב בפיקסלים |
| --- | --- |
| שמאל | `left = offset_x + safeLeft` |
| ימין | `left = viewportWidth - safeRight - offset_x - width` |
| עליון | `top = offset_y + safeTop` |
| תחתון | `top = viewportHeight - safeBottom - offset_y - height` |

12px כבר כלולים ב־offsets החיצוניים. מוסיפים אליהם `env(safe-area-inset-*)`. אין כפל ב־DPR, אין שיקוף של המלבן בגלל RTL, ואין הקטנת יעדי מגע. השהיה 48×48; סטיק 104×104 ברוחב ו־96×96 באורך; פעולות 56–80px ברוחב ו־64–80px בגובה. המרווח המזערי בפועל 8px. רוחבי היעדים קבועים בשתי המידות המבוקשות; מידות קטנות אחרות דורשות פריסה נוספת ואינן מוסמכות על ידי הבדיקה הנוכחית.

אזורי הפעולה קבועים. זריקה/חסימה/גלישה חולקים `primary`; מסירה/חטיפה חולקות `secondary`; ריצה נשארת ב־`sprint`; תרגיל/החלפה ב־`trick`; מסך ב־`support`. בהוצאה יעד שלא מוצג גם אינו מקבל מגע או פוקוס. אי־זמינות זמנית, כמו תרגיל סקי על השלג, משאירה יעד מושבת עם מסגרת מקווקוות וסיבה כתובה. אין שוער בכדורסל ובסקי; אין התקפה, הגנה או הוצאת כדור בסקי.

## אצבע אחת ושתיים

באצבע אחת אפשר לגרור סטיק, להרפות ולעבור לפעולה; השחרור עוצר תנועה ומשאיר רק כיוון אחרון. רצף באותה נגיעה הוא **מתאם מתוכנן**, לא יכולת קיימת של `hud-kit`: מחליקים מהסטיק אל כפתור גלוי, שוהים בתוכו 120ms לבחירה, והתנועה נעצרת. שחרור מבקש פעולה; 320ms מהבחירה הופכים להחזקה. יציאה של 24px מבטלת. לא מעבירים pointer capture בין כפתורים ולא שולחים אירועי DOM מלאכותיים.

בשתי אצבעות שמאל מזיז וימין מפעיל פעולה. כדי לרוץ וגם למסור/לזרוק בלי אצבע שלישית, הטיית סטיק של 0.9 ומעלה במשך 320ms מבקשת ספרינט; ירידה מתחת 0.75 מבטלת. החלופה היא נעילת ריצה מפורשת בהשהיה. כפתור ריצה גלוי תמיד במצבי משחק פתוח: החזקתו מבקשת ריצה מיד, והמסגרת עוברת לסימון החזקה ארוכה לאחר 320ms. שחרור מפסיק; click שאחרי החזקה אינו נועל בטעות. שינוי מצב או pause מבטל גם נעילה.

בספרינט אין טעינת כוח. בסקי boost נשאר בקשה חד־פעמית ואינו הופך לספרינט מוחזק. באצבע אחת ובאוויר בלבד, החלקת סטיק לאחד מארבעה כיוונים יכולה לבחור אחד מארבעת התרגילים הקיימים; היא מקפיאה היגוי עד לשחרור ומבקשת תרגיל יחיד. כל המחוות הן תכנון למתאם חיצוני.

## חיבור ל־hud-kit

| יעד | מודול וחוזה | הנחיית מתאם |
| --- | --- | --- |
| השהיה | `pause-button.mjs` · `create(host,{onPause})` | מבטלים קלט לפני פתיחת `pause-panel.mjs`; מחזירים פוקוס בסגירה |
| סטיק | `joystick.mjs` · `onChange(x,y,active)` | x חיובי ימינה, y חיובי למטה; בסקי משתמשים רק ב־x להיגוי; בסיס המצלמה ננעל בתחילת נגיעה |
| כל פעולה | `action-button.mjs` · `create(host,options)` | לכל כפתור ב־JSON יש options ו־update מלאים, כולל label, icon, disabled, loading, charge |
| טעינת זריקה/מסירה/בעיטה | `power-meter.mjs` · `update({value,label})` | value בתחום 0–1, נראה רק במהלך טעינה; אינו מבטיח הצלחה |
| מהירות סקי | `speed-meter.mjs` · `update({kmh,unit})` | מציגים נתון מאומת בלבד, באזור הקריא מעל הידיים |
| אירוע | `event-banner.mjs` | שער/סל/נפילה מאומתים בלבד; לא בהקשה על הכפתור |

משתמשים ב־`../hud-kit/hud.css` וב־`.ih-kit[data-theme]` במימוש. ממקמים את ה־hosts לפי slots, ודורסים **לאחר** CSS הערכה את מידות `.ih-action/.ih-stick` גם בתוך media queries. רף 48px בחבילה זו מחמיר ביחס לברירת המחדל 44px בערכה. בתצוגות הסטטיות הצבעים ונתיבי SVG זהים למקור, והמידות נוצרות מה־JSON; אין יבוא של קוד הערכה ואין השפעה על המוצר.

אין לחבר אותה פעולה גם ל־`onActivate` וגם ל־`onRelease`: נגיעה רגילה משתמשת בראשון, והחזקה בשני עם `onPress` ובדיקת cancelled. callback של `action-button` אינו מספק קואורדינטות או pointerId, לכן swipe ולחיצה כפולה דורשים האזנה ל־Pointer Events ב־host ומתאם יחיד שמונע פעולה כפולה. אין בחבילה שינוי ל־HUD כדי להוסיף זאת.

המתאם צריך להמיר כוונות לממשקי המשחק הקיימים. אלו אינן הבטחות שחוזי קלט חדשים כבר קיימים. נקודות עיון קיימות: `hoops-controls.mjs` (shootDown/shootUp, passPress, altPress, switchPress ושדה sprint), `soccer-session.mjs` והוצאות המודל, `alpine-controls.mjs` (boost ו־trickQueued). ביטול טעינה חייב להימנע מזריקה; לא ממפים cancel אוטומטית ל־shootUp שמבצע שחרור במנוע.

## משוב, ביטול ונגישות

לחיצה מקטינה רק תוכן פנימי ל־0.96 במשך 80ms, ללא שינוי hit target. החזקה מקבלת מסגרת כפולה ופס/תווית פעילים. אישור קבלת בקשה יכול להציג וי ל־180ms; הצלחת חטיפה, חסימה, סל או שער מגיעה רק מאירוע מנוע. דחייה מציגה סיבה ומסגרת מקווקוות, ללא הבהוב. בתצוגות מופיעות דוגמאות מוכנות, פעיל, בוצע ולא זמין.

`feel/<game>.json` מספק `speed.knots` ו־`speed.lines` למהירות מאומתת ו־`events` לאירועים שאושרו. לא מפעילים אפקט של חסימה על כל לחיצה על חסימה, לא משנים פיזיקה או שעון משחק, ולא מכפילים משוב שכבר מופעל. בהפחתת תנועה אין שינוי FOV, רעידה, קווי מהירות או משובי זמן; מסגרת וטקסט נותרים. רטט וקול הם בחירה נפרדת ואינם נדרשים להבנת המצב.

`pointercancel`, אובדן capture, blur, הסתרת מסמך, pause, resize, שינוי מצב, השבתה ויציאה מבטלים תנועה, ספרינט, טעינה, חלון double tap ותור מחוות. כפתור ומצב ננעלים ב־pointerdown; אין שחרור לתוך פעולה חדשה לאחר החלפת התקפה/הגנה. חזרה דורשת נגיעה חדשה.

עברית RTL, מספרים מבודדים ב־LTR; גופן מערכת. טקסט רגיל עומד ב־4.5:1 לפחות, קצה יעד ב־3:1 לפחות. פוקוס מקלדת לבן 3px, Tab בסדר סמנטי, חצים לסטיק ו־Enter/Space לפעולה. סיבה מוצמדת ל־aria-label כשיעד מושבת. מחוות והחזקה אינן הדרך היחידה לפעולה: בהשהיה בוחרים פעולת נגיעה מועדפת ונעילת ריצה. בחיבור יש לבדוק גם קורא מסך בטלפון, טקסט מוגדל ואחיזה פיזית; הבדיקה הסטטית אינה מאמתת את אלה.

## בדיקה ושחזור

נדרשים Python 3, חבילת Playwright ו־Chromium. הבדיקה משתמשת ב־Chromium מקומי אם הוא נמצא ב־PATH, או בדפדפן Playwright. אפשר להגדיר `PLAYWRIGHT_EXECUTABLE_PATH`. התקנת כלי הבדיקה אינה תלות של התצוגה הסטטית.

```sh
python3 workout/island/design/controls/tools/render.py --check
python3 workout/island/design/controls/tools/verify_browser.py
```

הבדיקה מפעילה `--use-gl=angle --use-angle=swiftshader`, שרת loopback זמני, וחוסמת מקורות חיצוניים. היא בודקת את כל 17 המצבים בשתי המידות, RTL/LTR ושלושה פרופילי safe area; משווה DOM ל־JSON, יעד 48px, מרווח 8px, חפיפות, גבולות, תוויות, השבתה, פוקוס, הפחתת תנועה ושינוי כיוון באותו מסמך. תיקיית `verification/` מכילה דוח ו־16 צילומי מסך. `CONTROLS_TEST_OUT` מאפשר להוציא ראיות מחוץ למאגר.

אחרי שינוי JSON יוצרים שוב HTML:

```sh
python3 workout/island/design/controls/tools/render.py
```

אין לערוך את HTML שנוצר בנפרד. אין קבצי לוגיקת משחק, שינויים לקבצים קודמים או עדכון תגי גרסה בחבילה.
