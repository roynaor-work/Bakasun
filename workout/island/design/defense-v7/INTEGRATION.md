# חוזה שילוב

יחידות במטרים; מעלה `+Y`, קדימה `+Z`. המודלים החדשים מאורגנים תחת `asset_root`. קובצי GLB דורשים `KHR_draco_mesh_compression`. כל מפענח וכל ספרייה בתצוגה נמצאים ב־`vendor/` המקומי.

ה־manifest כולל נתיב, גודל מדויק, SHA-256, משולשים, מרקמים, רמות פירוט ועוגנים לכל קובץ. `BUDGET.md` מציג את טבלת המשקלים. אין לשנות את קנה המידה כדי לפצות על טעינת Draco שגויה.

| קבוצת נכסים | שימוש |
|---|---|
| `alien-scout`, `alien-manta`, `alien-beetle`, `alien-carrier`, `alien-harvester` | חמש צלליות בסיס נפרדות. הסוג החמישי אינו הבוס. |
| `alien-boss` | בוס הכתר, מחולל מרכזי ושישה מודולי היקף. |
| `defender-plane` | עוגני `anchor_fire_left/right`, `anchor_engine_left/right`, `anchor_hit`. |
| `boar-amber`, `boar-ash`, `boar-striped` | LOD0/1 עם `trot` באורך 0.8 שניות; LOD2 הוא דמות מאוחדת ב־pose סטטי. הגור מוצב בקנה מידה 0.72 בפריסת החווה. |
| `guard-ranger`, `guard-lookout`, `guard-keeper` | LOD0/1 עם `idle`, `patrol`, `alert`; LOD2 סטטי. |
| אביזרי החווה | מקטע גדר עם מרחק עוגנים 2m, שער, סככה, תחנה, פעמון בעל ציר `bell`, שוקת, חבילות קש וערוגות. |
| סביבה | אי, דקל, ענן, ירח וכוכב לכת עם טבעות. |

## שלד צוות השמירה

18 שמות עצמות והיררכיה זהים ל־`motion2/soccer.json`. ערכי המנוחה הם ה־bind המכויל של `soccer-v5`, עם קריסת הכתפיים העזרות לתוך `Chest`. לתנועה חדשה משתמשים במפת ה־retarget של המציג הקיים. אין להעתיק קווטרניונים מקומיים של השלד הקנוני לתוך ה־bind המכויל בלי ההתאמה.

סדר: `Root`, `Hips`, `Spine`, `Chest`, `Neck`, `Head`, `LeftArm`, `LeftForeArm`, `LeftHand`, `RightArm`, `RightForeArm`, `RightHand`, `LeftUpLeg`, `LeftLeg`, `LeftFoot`, `RightUpLeg`, `RightLeg`, `RightFoot`. המפרט המלא ב־`skeleton.json`. קליפ `patrol` נגזר מן הריצה המכוילת הקיימת; הוא אינו הליכה מוקלטת. `alert` חד־פעמי ואחריו חוזרים ל־`idle`.

לחזירי הבר ארבעה צירי רגליים מקומיים. תרגום מפצה שומר את הפרסות מעל הקרקע לאורך הטרוט. השורש נשאר במקום; תנועת עולם, התנגשויות וניקוד הם באחריות המשחק המשלב.

## LOD וזיכרון

מומלץ לבחור LOD לפי גודל מוקרן. במציג, דמות קטנה מ־80px מקבלת LOD2; בין 80 ל־160px נעשה שימוש ב־LOD1; בקטלוג ובקירוב גדול נעשה שימוש ב־LOD0. מעברי גדרות ודקלים מתבצעים ברמת מקבץ ומוצגים ב־`InstancedMesh`. גם קהל של 18 דמויות הוא מופעים של רשת אחת.

לכל דמות אטלס יחיד בגודל 512², והבייטים שלו זהים בכל רמות הפירוט. בשילוב יש לשתף את אותה Texture בין הרמות, כפי שמדגים `load()` ב־`app.mjs`. צל תמונה סביבתית ואטלס האפקטים הם משאבים משותפים נפרדים.

## אפקטים

`effects.mjs` מייצא `DefenseEffects`. יוצרים מופע אחד עם scene ואטלס, קוראים `burst({position,scale,normal})`, מכוונים שתי קרני לייזר ב־`aimLaser(index,from,to)`, ומעדכנים ב־`update(dt,camera)`. קואורדינטות הלייזרים מקומיות לשורש הפיצוץ. הפעולה מחליפה פיצוץ קיים; המאגרים מוגבלים לפיצוץ אחד, שתי קרניים ו־32 גיצים. `dispose()` משחרר רק את המשאבים שבבעלות המופע.

חיי האפקט 1.1 שניות. אטלס 4×4 עם 16 פריימים, 512². אין יצירה של גאומטריה חדשה בכל פריים. אין שמע אוטומטי או רטט.

## מדידה

יעד: 30fps. המציג מגביל ל־30 ומפחית רזולוציה, צללים וחומר תחת עומס. אחרי הפחתה ל־DPR ‏0.75, צל תמונה, חומר Lambert ו־LOD נמוך, עומס מתמשך מאפשר שלב אחרון של DPR ‏0.5. הטקסט והפקדים אינם מוקטנים. תאורה נקודתית וטשטוש CSS מוסרים בפרופיל החסכוני, בעוד גופי הפנסים נשארים זוהרים. דוגמת כל פרופיל מצולמת בסבב הסופי. פתיחת נכס ועצירה דרך הפקד מחזירות רזולוציית ציור עד 1.5. מצב עצור אינו מצייר שוב עד שיש שינוי.

בדיקות SwiftShader והאטת CPU הן תצפית תוכנה; בדיקת מכשיר פיזי נדרשת אחרי השילוב. המדידות הגולמיות וההבדל בין הפרופילים מתועדים בדוח. הפעמון מעלה זמנית את השומר הראשי ל־LOD מונפש גם בזמן חיסכון, כדי שההתרעה תישאר נראית.
