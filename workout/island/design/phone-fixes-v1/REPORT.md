בסיס מדויק: `43b27dc235387e3cb737aee9558cdf9d5fd5a262`, מיזוג v24.1 מ־PR 461; תג המטמון הקיים: `island-v2-20261107-15`. המסלולים הפעילים כוללים גם מודולי משחק בשם v25. הבדיקות מכוונות למסלולים האלה.

## הבקשות והפתרונות

### A — כדורסל

> "זה התחלף לשריקה כי יש חטיפה. לא צריכה להיות שריקה כשיש חטיפה. שריקה צריכה להגיע רק כשיש עבירה, כדור אאוט, או נגמר הזמן. הצליל שהכדור פוגע בטבעת נשמע כמו גונג ולא מתאים."

חטיפה ויירוט מסירה שקטים ואינם מפעילים את מחוות השריקה של השופט או צורכים את מרווח השריקות. שריקות נשמרות לעבירה, הפרת כללים/אאוט וזמן החזקה; הפרות כגון צעדים וכדרור כפול נחשבות כאן עבירות כללים. פתיחת משחק ופסק זמן שקטים; צופר סיום הרבע נשמר. פגיעת הטבעת מחליפה גם את אירוע ההתנגשות וגם את מסלול השמע של האנימציה, באותו buffer מקומי שנוצר פעם אחת ב־JavaScript.

מדידה: דגימת הטבעת הקיימת 752.5 מ״ש לפי הקובץ (750 מ״ש לאחר פענוח בדפדפן) → 180 מ״ש; שיא PCM ‏0.85; RMS של 80 מ״ש האחרונים הוא 1.335% מזה של 50 מ״ש הראשונים. חטיפה ויירוט: שתי שריקות → אפס, תוך שמירת שריקת העבירה הבאה. הוכח גם ב־Web Audio אמיתי ללא WASM. [ניתוח](evidence/A-rim-analysis.json), [דפדפן](evidence/AD-after-browser.json), [דגימה להאזנה](evidence/A-rim-180ms.wav).

סיכון: התאמת גוון הצליל היא גם עניין שמיעתי; יש דגימה ממשית להאזנה. תחושת הרמקול בטלפון פיזי לא נמדדה.

### B — ספינות

> "הנעילה היא מהירה מדי, ואחרי כל ירייה צריך לבטל את הנעילה. ובנוסף, בזמן הנעילה צריך שבאמת הרדאר ימשיך לרוץ ולחפש את הנעילה כמו שצריך. אבל הנעילה צריכה לקחת לפחות בין 3 ל-4 שניות."

כל רכישת מטרה אורכת 3.5 שניות. במהלך הרכישה המודל ממשיך לבדוק מטרה חיה וטווח, מעדכן כיוון וסריקה, והחיווי מציג את הסריקה החיה. כל ירייה מוצלחת מאפסת נעילה ורכישה, כולל תור ירי ומצב רכישה דביק; לחיצה שנדחית בגלל חוסר תחמושת או טעינה אינה צורכת נעילה. תור ירי שנלחץ במהלך הרכישה מופעל פעם אחת בסיומה.

ב־9 צירופי שלב/קושי: 1.000–1.267 ש׳ → 3.517 ש׳ במדידת 60Hz (סף 3.5 ש׳ ועוד פריים). נעילה שנשארה אחרי ירייה: 9/9 → 0/9. בדפדפן המתוקן נמדדו 3.506 ש׳, 12 דגימות מרונדרות לאורך הרכישה, שלוש סריקות מלאות וכיוון מטרה שמשתנה תוך כדי; כל זווית HUD תאמה את המודל. יריית מגע אחת איפסה את כל מצבי הנעילה. [36 תרחישי מדידה](evidence/B-model-measurements.json), [דפדפן](evidence/B-after-browser.json).

סיכון: ההמתנה מגדילה את החשיפה לירי אויב. לא שונו הנזק, קצב ירי האויב או זמני הטעינה.

### C — חלליות

> "כשהירי עובר את החללית אחרי שהוא פוגע בה, כלומר החללית מאחורה נפגעת גם מאותו ירי. הירי צריך להיעלם ולהתקע בחללית. בנוסף אולי לעשות גם טיפה אפקטים שהם החלליות נפגעות."

קליעי התותח, הוולקן והלייזר נעצרים במגע הראשון לאורך המסלול הנסרק, גם כשהקליע משודרג או חוצה כמה חלליות בפריים יחיד. המגע הקרוב נבחר לפני סדר המערך. גם השמדת החללית או פגיעה במגן צורכות את הקליע. אפקט הפגיעה הקיים מורחב לקליעים הרגילים: תצוגה של 180 מ״ש, עד 24 רשומות, ניקוי בתוך 300 מ״ש. יכולות שטח מיוחדות נשארות במסלול שלהן.

שמירת ערך השדרוגים: מקדם הלייזר שהקוד הקיים כבר גובה בהגדלת חיי האויב מועבר לנזק בפגיעה הראשונה, עם אותו מעריך קנה מידה. כך דרגות לייזר גבוהות אינן הופכות את המשחק לקשה יותר בגלל אובדן החדירה. הנוסחה משתמשת במקדמים הקיימים, ללא קבוע נזק חדש; קליע רגיל, מטח kind2 ויכולות שטח שומרים את נזקם.

במגע בדפדפן, מול שתי חלליות במצב בדיקה עם ציוד בדרגה 2: לפני — נזק 1 לכל גוף, שתי פגיעות וקליע ממשיך; אחרי — נזק 2.219 לגוף הראשון, אפס לשני, קליע נעלם ואפקט אחד. שני דגלי הכיבוי משחזרים בדיוק את מדדי הבסיס. [ארבעת מצבי הדפדפן](evidence/C-browser-results.json).

מבחן התקדמות מודרני: 30 שלבים × 3 זרעים, ציוד מרבי חוקי, שני כפתורי ירי והתחמקות חזויה — 90/90 ניצחונות לפני, אחרי ובחזרה. נבדקו גם שעון, ניקוד ותגמול אמיתי, בלי הזרקת חיים/נזק או שינוי אויבים. [מדידות מלאות](evidence/C-progression.json), [בדיקה על העותק המשולב](evidence/C-progression-integrated.tap).

סיכון איזון ממשי: הפיצוי מרכז את כוח הלייזר בגוף הראשון; בציוד המרבי שנמדד זמן סיום ממוצע ירד מ־178.085 ל־123.176 שניות, כ־30.8%. זו אינה הוכחת קושי למתחילים או תחושת טלפון פיזי. שני דגלי הכיבוי משחזרים גם את הנזק הישן ואת זמן הבסיס. בדיקות חדירה וזמנים של גרסאות היסטוריות נשמרות תחת דגל החזרה.

### D — מרוצים

> "לא צריך שיהיה את הכפתור לביטול הפיטס, כי בעצם כולם נכנסים לשם להחליף צמיגים."

במרוץ עם פיטס אוטומטי כפתור ההזמנה/ביטול אינו מחובר לממשק, וגם API הביטול אינו יכול לעקוף זאת. התזמון האוטומטי, הכניסה, עצירת החלפת הצמיגים והיציאה נשמרים. המסלול הידני הישן נשמר כאשר דגל הפיטס האוטומטי הקיים כבוי.

בדיקות כוללות מרוצים של שתי ושלוש הקפות, החלפת צמיגים בפועל, סירוב לביטול דרך המודל ושני דגלי חזרה. בדפדפן: 0 כפתורי ביטול, API מחזיר false, כניסה אוטומטית וטפיחת מגע על החלפת הצמיגים מסתיימות בעצירה אחת ובצמיגים מלאים. כפתור הביטול: קיים → אינו קיים. [דפדפן](evidence/AD-after-browser.json). סיכון: אין עוד אפשרות לדלג על העצירה האוטומטית; זו ההתנהגות המבוקשת.

### E — טניס

> "בזמן ההגשה, ככל שזה יותר רחוק מהירוק, או מהסגול באמצע, ההגשה צריכה להיות פחות טובה, או להיות מחוץ, או לפגוע ברשת, אם זה לא בטווח הירוק או קרוב לסגול. בנוסף, המכה שההגשה צריך להיעלם אחרי שמגישים, והכפתורים צריכים להיות מסודרים קצת יותר נוח ויותר אסתטי. בר האיכות של המכה צריך להיות בצד ימין ולא להפריע לצפייה של המשחק."

איכות ועוצמת ההגשה יורדות עם המרחק מהמרכז. הירוק בטוח; בצהוב הסיכון עולה בהדרגה; אדום מוקדם פוגע ברשת ואדום מאוחר יוצא מקו ההגשה. ההכרעה מתבצעת באמצעות מסלול הכדור ובדיקות הרשת/קווים הקיימות, כולל טעות כפולה. מד ההגשה וכפתור ההגשה נעלמים לאחר המגע; מד החזרה מופיע כשהוא נחוץ. הכפתורים בקבוצת אגודל קומפקטית של 64/76 פיקסלים והמד במסילה הימנית החיצונית.

ב־128 זרעים: צהוב קרוב לירוק 0 → 32 תקלות; צהוב רחוק 0 → 101. במגע, איכות טובה/מוקדמת 1/1 → 0.955/0.162. שני מצבי הכיבוי תואמים את הבסיס ב־4,500 פריימים. המד הפעיל עבר מ־x596–620 ל־x816–830 ב־844×390, מימין לכפתורים. 10/10 בדיקות דפדפן עברו, כולל רשת מוקדמת וטעות כפולה בפעולות מגע. [מדידות מודל](evidence/E-model-metrics.json), [הוכחת דפדפן](evidence/E-after-browser.json), [הערות](evidence/E-NOTES.md).

סיכון: הגשות גרועות מכשילות יותר, בכוונה. הפריסה הוכחה בגודל המבוקש; נוחות אחיזה ואסתטיקה סופיות דורשות שימוש בטלפון.

### F — חזירים

> "צריך לתת שדרוגים קלים יותר בקטע של הנשק הראשי, הוולקן, שהתחמם לאט יותר במקור, וגם שיש שדרוגים לזה."

קצב ההתחממות הבסיסי של משפחת המקלע מופחת ב־25%. כל דרגת נשק מפחיתה את ההתחממות לשנייה ב־4% לצד שיפור הנזק והקצב הקיימים; כל דרגת קירור מפחיתה אותה בעוד 5%. שדרוג קירור שנרכש בחנות מרענן מיד את נתוני הנשק. מחירי המקלע הראשונים יורדים מ־110/176/282 ל־80/120/180; 250 מטבעות התחלה מספיקים לשני שדרוגים במקום אחד. החנות מסבירה את השפעת השדרוג ומחשבת DPS ממחזור התחממות/קירור בפועל.

זמן רציף עד התחממות במודל: בסיס 3.584 → 4.780 ש׳; דרגה 3 ‏3.201 → 5.186 ש׳; בסיס עם קירור 1 ‏3.584 → 5.031 ש׳. במגע במשחק המלא: 30 → 40 יריות בסיס, 32 → 52 בדרגה 3 ו־30 → 42 עם קירור 1. ‏11/11 בדיקות דפדפן עברו בשלושה מצבים, כולל רכישות והעברת דגלי החזרה למסגרת. שמירות, נזק וקצב אש נשמרים; כלכלת כלי הנשק האחרים נשמרת. [מדידות](evidence/F-measurements.json), [דפדפן](evidence/F-after-browser.json), [הערות](evidence/F-NOTES.md).

סיכון: צירוף שדרוגים גבוה סלחני משמעותית — דרגת מקלע 10 וקירור 6: ‏2.328 → 9.859 שניות ירי רציף. זהו שינוי איזון מכוון ויש לבדוק תחושה ברמות המאוחרות בטלפון.

## בדיקות והוכחות

ה־runner יוצר שני checkouts נפרדים של קומיט הבסיס, מריץ **אותם קובצי בדיקה** לפני ואחרי, מחיל רק בעותק השני, ושומר TAP לכל אות. כישלון בסיס מתקבל רק אם יש assertion שנכשל; שגיאת import/setup אינה הוכחת תיקון. דגלי החזרה נבדקים בנוסף להתנהגות החדשה. [תוצאות משולבות](evidence/regressions.json).

בנוסף: 5/5 בדיקות בטיחות החלה ובדיקת התקדמות C של 90 ריצות בכל מצב.

ריצות Node הרחבות משתמשות ב־`ISLAND_PLAYWRIGHT=/__phone_unit_suite_no_optional_browser__` כדי להשאיר את בדיקות הדפדפן האופציונליות של המאגר לריצה נפרדת. גילוי Playwright רגיל בסביבה זו מצא ספרייה אך לא את בינארי Chromium הפרטי שהיא מצפה לו; [הניסיון המקורי](evidence/repository-baseline-browser-discovery.log) תועד. הוכחות A–F משתמשות ב־Chromium המותקן במערכת ומבוצעות בנפרד, ללא דילוג על מקרי המגע המבוקשים. פלטי הבסיס והעותק המתוקן כוללים את מספרי המעברים והדילוגים בפועל.

גם בבסיס וגם בעותק לאחר ששת ה־patches הסופיים: 4,261 עברו, 0 נכשלו, 65 דולגו מתוך 4,326 בדיקות. [סיכום שתי הריצות](evidence/repository-results.json). קובצי `*-pre-compensation.log` ו־`*-historical-contracts.log` שומרים ניסיונות אבחון מוקדמים; פלטי המסירה הסופיים הם `repository-baseline.log`, ‏`repository-after.log`, ‏`regressions.json` וקובצי הדפדפן המפורטים כאן.

בדיקות היסטוריות שתיארו במפורש שריקה בחטיפה, חדירת לייזר, נעילה מתמשכת או ביטול פיטס קיבלו hunks בתוך A/B/C/D שמפעילים את דגל החזרה שלהן. ה־assertions נשמרו. בדיקות המוצר החדשות נשארות חיצוניות ב־`tests/A.test.mjs` עד `F.test.mjs` ובודקות את ההתנהגות המתוקנת. לא הוחלה שום התאמה על קובצי הבדיקה במאגר המסירה.

בדיקות דפדפן משתמשות ב־Chromium ‏151.0.7922.173, ‏Playwright ‏1.57.0 ו־Node ‏24.19.0, viewport ‏844×390, ‏`hasTouch:true` במפורש, אירועי מגע מקוריים ו־service worker חסום. יש 60 צילומים, נתוני מודל ובדיקת שגיאות/CSP. חלק מהתרחישים מציבים מצב התחלתי סינתטי דרך hooks קיימים, ומתקדמים בשעון מבוקר; המודל, הרינדור ושערי הקלט הם קוד המוצר. זוהי אמולציית מגע בענן, לא מדידת ביצועים או הוכחה במכשיר פיזי.

[בדיקת שלמות המסירה](evidence/AUDIT.json) עברה: כל קובצי התוצאות הסופיים קיימים, כל ה־hashes תואמים, כל התמונות בגודל המבוקש, כל מצבי הדפדפן הנדרשים נבדקו, והוכחת C כוללת את פיצוי הלייזר הסופי. אפשר לשחזר אותה באמצעות `node tests/audit-evidence.mjs` מתוך תיקיית החבילה.

**גבול הוכחת ה־WASM:** התיקונים עצמם הם JavaScript בלבד. ספינות, חלליות וטניס מוכחים גם כאשר `WebAssembly` אינו זמין, עם דגלי הגרפיקה הקיימים `navalV7=0`, ‏`defenseV7=0` ו־`tennisV7=0`, וללא בקשת `.wasm`; גם הוכחת החזירים פועלת ללא WASM. הוכחת המרוצים משתמשת בדגל הקיים `racingV7=0` ומוודאת אפס בקשות והפעלות WASM. הכדורסל הקיים דורש Draco/WASM לפענוח נכסי האולם גם בגרסאות הנכסים הישנות; הוכחת המשחק המלא מתעדת תלות בסיס זו. בדיקת השמע החדשה רצה בנפרד ב־Web Audio אמיתי כאשר WASM כבוי. החבילה אינה מסירה תלות קיימת זו ואינה טוענת שהכדורסל המלא פועל ללא WASM.

## סדר החלה והחזרה

1. עובדים על עותק Git נקי ונפרד של קומיט הבסיס. אפשר גם עותק נקי של ענף המסירה, כל עוד השינויים מול הבסיס הם רק קובצי החבילה. אין להחיל במאגר המסירה המקורי.
2. מריצים בדיקה ללא כתיבה, עם נתיב מוחלט לחבילה וליעד:

```bash
bash /path/to/Bakasun/workout/island/design/phone-fixes-v1/apply.sh --check /path/to/clean-copy
```

3. מחילים A → B → C → D → E → F בפעולה אטומית אחת:

```bash
bash /path/to/Bakasun/workout/island/design/phone-fixes-v1/apply.sh /path/to/clean-copy
```

`apply.sh` מסרב ליעד מלוכלך, למאגר המסירה עצמו, לבסיס שונה ולהחלה שנייה. הוא מאמת את hash כל patch וקובץ מקור מול [manifest.json](manifest.json), בודק את כל השישה לפני כתיבה, ואינו משתמש בהחלה חלקית או `--reject`. B/C נוגעים גם באותו קובץ בדיקות היסטורי, במקטעים שונים; הסדר המשולב נבדק. החלה ידנית של חלק מהחבילה אינה מסלול האימות המתועד.

4. משחזרים את בדיקות לפני/אחרי; נדרש Git ו־Node 22 ומעלה. ה־runner שומר עותקים זמניים לצורך ביקורת ומדפיס את נתיבם:

```bash
node /path/to/Bakasun/workout/island/design/phone-fixes-v1/tests/verify.mjs
```

5. משחזרים את בדיקות הדפדפן ברצף באמצעות ה־runner, או לפי הפקודות בראש קובצי `*-browser.mjs`. נדרש Playwright ו־Chromium מותקנים. אפשר לבחור אותיות באמצעות `PHONE_FIX_ONLY=A,B`:

```bash
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright CHROMIUM_PATH=/path/to/chromium node /path/to/Bakasun/workout/island/design/phone-fixes-v1/tests/browser.mjs /path/to/base-copy /path/to/applied-copy /path/to/evidence-output
```

בדיקות SwiftShader מקבילות הכבידו על סביבת הענן ויצרו timeouts. אין להציג timeout כהצלחת תיקון.

6. לאחר שילוב ופרסום עתידי, `?phoneFixes=0` מחזיר את כל ההתנהגות הישנה, או דגל אות בודדת מחזיר משחק אחד. פרסום, מיזוג והעלאת גרסה מרכזית לא בוצעו בחבילה זו; החיבור למטמון/שחרור הבא נשאר אצל סשן האינטגרציה.
