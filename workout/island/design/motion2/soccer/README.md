## פורמט ושלד

הפורמט הוא `schemaVersion: 1`,‏ `kind: authored-skeletal-motion`, בדיוק במבנה של [motion/soccer.json](../../motion/soccer.json):‏ `states`,‏ `transitions`,‏ `skeleton`,‏ `keyframes`,‏ `events`,‏ `ballContacts` ו־`supportContacts`. השלד הקנוני בן 18 העצמות הועתק ללא שינוי. כל מפתח כולל את כל הסיבובים המקומיים כ־quaternion‏ `[x,y,z,w]`, היסט אגן ומסלול ייחוס. המיפוי הקיים [retarget-map.json](../../viewer/retarget-map.json) מתאים אותו ל־20 העצמות שב־[rig.json](../../characters/rig.json).

`sourceContract` מפנה ל־`design/motion/soccer.json` ול־Git blob המדויק שלו. הקליפים החדשים מרחיבים אותו. בעת צריכה מאחדים את המצבים והמעברים של שלושת הקבצים עם החבילה המקורית; אין לדרוס מזהה קיים. מעברים אל `idle`,‏ `run`,‏ `dribble_run` ו־`pass_short` מתייחסים למאגר המאוחד. `initialState` של כל קובץ מזהה את תחילת קבוצת הקליפים שלו; חיבור החבילות שומר את מצב ההתחלה של הצרכן.

הצירים נשארים +Y למעלה, +Z קדימה, +X לשמאל אנטומי; היחידות מטרים. `rootMotion: false`: הסימולציה אחראית למיקום ולכיוון בעולם. `referenceRootTranslationMeters` הוא מסלול בדיקה, לרבות ריצת הכדור והגלישות, ואינו פקודת תנועה למשחק. זמני `keyframes`,‏ `ballContacts`,‏ `supportContacts` ו־`groundContacts` מנורמלים לטווח 0–1. `events[].atSeconds` וזמני הקטלוג ב־manifest הם בשניות.

## מגעים ואירועים

`ballContacts` שומר את נקודת המגע במערכת העצם ואת נקודת המגע ומרכז הכדור במערכת הדמות, ללא מסלול הייחוס. נקודות אלו נבדקות ב־FK עצמאי. באחיזה בשתי ידיים שתי הנקודות שייכות לאותו כדור. קליפים שאינם נוגעים בכדור כוללים מערך ריק ו־`ballContactReason`; טעינה וכשל בגלישה אינם ממציאים פגיעה בכדור.

`supportContacts` מכיל חלונות שבהם סוליה נטועה ועוגן קבוע. הרגל נשארת בעוגן לאורך החלון, גם לפני פתרון ה־IK של הצופה. רכישת ושחרור התמיכה מתערבבים באמצעות מנגנון הצופה הקיים. `groundContacts` מוסיף תזמון של מגעי קרקע, ובגלישות גם כפות ידיים, אגן ורגל מחליקה. הצופה הקיים נועל ומודד רק סוליות; מגעי הגוף הנוספים הם תיאור מתוזמן ואינם אילוץ IK של הצופה. נתון עם נקודה מקומית ו־`pointMeters` נבדק מול FK; רשומות ללא נקודה הן תזמון בלבד, כפי שמפורט בדוח המקור.

בגלישה מכוונת אין חלון רגל נטועה לאורך ההחלקה עצמה. מדד החלקת רגל נטועה בקטע ללא `supportContacts` הוא **לא ישים**, ולא הוכחה שהגוף אינו מחליק. הרצפה עדיין נבדקת על כל הרשת המוצגת.

כל אירוע הוא presentation בלבד: צליל, תנוחה או רגע להצגת מגע. זמני הקליפ אינם קובעים פיזיקה, בעלות בכדור, הצלחת גלישה, פסילה, תוצאה או תגמול. `disallowed` מציג תגובת אכזבה לאירוע `result_failure` מהסימולציה; הוא אינו פוסק חוק כדורגל.

## רציפות ומעברים

כל 111 ההמלצות החדשות מוגדרות כרשומות `transitions` עם `visualBlendSeconds` חיובי, `smoothstep`,‏ `current-displayed`,‏ `velocity-extrapolation` ו־`carry-until-release`. במעבר שומרים את הפוזה המוצגת ומהירותה, מקדמים את זמן היעד וממשיכים את נעילת התמיכות עד שחרורן. הצופה הקיים מממש ובודק חוזה זה. `reset` מהחבילה המקורית מכסה גם את המצבים החדשים ומאפס מצב מיידית תוך ערבוב חזותי.

שרשרת זריקת החוץ היא `throw_in_prepare → throw_in_release → throw_in_follow`. הקרן היא `corner_runup → corner_kick`. שרשרות הגלישה הן `slide_{straight,lateral,fast}_prepare → slide_{straight,lateral,fast} → slide_{straight,lateral,fast}_fall → slide_{straight,lateral,fast}_recover`. כשל בגלישה מוביל לנפילה ולקימה; יציאה מפעולות חוזרת למצב תנועה או לעמידה. `kick_charge`,‏ `dribble_run` ו־`defensive_jockey` הם לולאות סגורות; שאר הקליפים חד־פעמיים.

## הרצה ודוח

1. משורש המאגר, מריצים בדיקה מספרית בלתי תלויה:

   ```sh
   node workout/island/design/motion2/soccer/verification/check-assets.mjs --out workout/island/design/motion2/soccer/verification/assets-report.json
   ```

2. עם Playwright ו־Chromium מותקנים, מריצים את הצופה המקורי על החבילה המאוחדת:

   ```sh
   node workout/island/design/motion2/soccer/verification/run.mjs --executable /usr/bin/chromium
   ```

   אפשר למסור נתיב דפדפן אחר ו־`PLAYWRIGHT_MODULE` לפי תיעוד הצופה. כלי האימות החדש מעתיק את הצופה והנכסים לתיקייה זמנית, מאחד שם את נתוני התנועה ומפעיל את `design/viewer/test-viewer.mjs` הקיים ללא שינוי. הקובץ המקורי אינו מאפשר לבחור חבילת הרחבה ב־CLI; לכן ההרצה משתמשת בעותק זמני. מצבי המקור נשמרים עבור בדיקות השיבוש, מדידת CPU וצילום `kick` שהסקריפט המקורי דורש.

3. התוצאה הצפויה היא PASS לכל 33 הקליפים, לשחקן ולשוער, בשני חלונות: 844×390 ו־390×844. ראיות הריצה: [VALIDATION.md](VALIDATION.md),‏ [verification/provenance.json](verification/provenance.json),‏ [דוח השחקן](verification/soccer-player/report.json),‏ [דוח השוער](verification/goalkeeper/report.json) ו־[מדדים לפי קליפ](verification/clip-metrics.json). כל מצב חדש נבדק על ידי הבודק המקורי; צילומי ברירת המחדל שלו מציגים את `kick` המקורי. תמונות הקליפים החדשים מצורפות בנפרד בתיקיית האימות.

ספי הצופה נשארים 0.02 מ׳ לתמיכה, 0.001 מ׳ לקפיצת לולאה ומעבר, 0.01 רדיאן לסיבוב, מינימום רצפה ‎−0.001 מ׳ וממוצע CPU עד 16.67ms. הדוח שומר גם את תיקוני הרצפה והאגן שהצופה ביצע, כדי להבחין בין נתוני המקור לבין הגאומטריה לאחר התאמה.
