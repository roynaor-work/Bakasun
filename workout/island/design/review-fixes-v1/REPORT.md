`exit 0` של probe אינו הוכחה לתיקון: רוב שחזורי הביקורת מודדים את התקלה או מאשרים שהיא קיימת. שלושת שחזורי הכדורגל דורשים את ההתנהגות התקינה ולכן עוברים מ־1 לפני ל־0 אחרי. השחזורים של 008, 013 ו־016 מאשרים דווקא את הבאג הישן ולכן עוברים מ־0 לפני ל־1 אחרי. השחזורים של 001/004 ניגשים למצב כשל או ל־DOM שכבר נוקה בתיקון; אחרי הם מסתיימים ב־predicate timeout או assertion של השחזור, והבדיקות החדשות מאמתות שהרחוב והמעבר מתאוששים. Timeout חיצוני או כשל סביבתי אינם מסומנים כהצלחת אימות.

גבול חשוב ב־011/012: השחזורים המקוריים קוראים לעזר ה־heading ולעזרי האחסון הנמוכים ישירות. התיקונים נמצאים בגבול התצוגה וה־session, ולכן ה־probes הישנים עדיין יכולים למדוד את ההתנהגות הנמוכה ללא הגבול החדש. הם הורצו ללא שינוי בשני הצדדים; בדיקות 011/012 מפעילות את פונקציית ההצבה שה־view משתמש בה ואת ה־session בפועל, ובודקות כיוון בעולם ובחירת שיא/ghost בהתאם. אין הצגה של probe ישן שנותר זהה כהוכחת התיקון.

בדיקות הבקר בכדורגל כוללות mixer, retargeter ו־tracks אמיתיים לאורך כמה פריימים; בכדורסל נטענים הגוף והאנימציות האמיתיים. בדיקות המקלדת, אובדן WebGL, כשלים בטעינה והקהל משתמשות ב־Chromium. בדיקת האופליין מתחילה בפרופיל חדש, מורידה את המניפסט דרך Service Worker אמיתי, מכבה רשת ורק אז טוענת את הגוף עם ובלי דגלי החזרה. כל האחסון והפרופילים של הבדיקות זמניים.

בסקירה נוספת ל־014 נבדקו שלוש עמדות ושני דורות גוף: אין ניתור או החלקת רגל משמעותית, אך במעבר מ־idle לפייק קיימת תנודת גובה קטנה של 13–15 מ״מ עקב blending. תיקון 003 מאפשר לסגור את כרטיסי השיעור והחדר במקלדת; הוא אינו מוסיף מערכת כיוון וחילוץ מלאה בחצים. ב־012 נבדקה גם התאמה של מרחב הזמנים במפה ובסשן בכל 30 השלבים ושישה צירופי דגלים, ללא טעינה מוקדמת של Three דרך מנגנון הליגה.

## הרצה בטוחה

נדרשים Git עם תמיכה ב־worktree, Node.js, Python 3 עם Playwright ו־Chromium. נבדק ב־Node 24.19.0. בדיקות JavaScript מחפשות Playwright מותקן או `ISLAND_PLAYWRIGHT`; בסביבה זו זמינה גם חבילת ה־JS של Python Playwright. `CHROMIUM_PATH` קובע executable לבדיקות החדשות; השחזורים המקוריים משתמשים ב־`/usr/bin/chromium`. יש לפנות את פורט 8766 לשחזורים המקוריים. אין צורך בשירות חיצוני או בנתוני משתמש.

משורש המאגר בענף התוצר:

```bash
bash workout/island/design/review-fixes-v1/apply.sh
```

הסקריפט יוצר worktree חדש עם HEAD מנותק בקומיט הבסיס. הוא מסרב לעץ עבודה המחובר לענף, מאמת שכל patch חל לבדו על הבסיס, מריץ בדיקות קיימות ובדיקות רגרסיה לפני, מחלץ את קובצי הביקורת המקוריים מהקומיט המקובע, ומריץ אותם. לאחר מכן הוא מחיל את כל 16 התיקונים לפי הסדר, דורש מעבר של כל הבדיקות החדשות ושל הקיימות, ומריץ שוב את השחזורים. העותק הזמני מוסר בסיום; הלוגים נשמרים בנתיב evidence שהסקריפט מדפיס. הוא אינו מחיל דבר על main או על ענף התוצר.

לשמירת העותק המתוקן לעיון:

```bash
KEEP_REVIEW_FIX_WORKTREE=1 bash workout/island/design/review-fixes-v1/apply.sh
```

`--tests-only` מדלג במפורש על השחזורים המקוריים ומתאים לאימות קצר יותר; זו אינה ההרצה המלאה המתוארת לעיל. `REVIEW_FIX_ROOT` מאפשר להריץ קובץ בדיקה חדש על עותק אחר של המקורות.

## גבולות האימות

נבדקת קבוצת הבדיקות הקיימות הרלוונטיות לשינויים באמצעות `node --test`; אין טענה שהורצה מחדש כל סוויטת `npm test`. בדיקות במודלים וב־Chromium/SwiftShader אינן מדידת FPS או בדיקת תחושה בטלפון. לא שונו cache version, תגי גרסה או מנגנון הפצה; חיבור עתידי למוצר צריך להתבצע בתהליך השחרור המרכזי של המאגר.
