# בנייה ואימות — hoops-motion-v11

כל המקור והפלטים של המסירה נמצאים בתיקייה זו בלבד. כלי הפיתוח מותקנים ב־`/tmp`; אין צורך לשנות `package.json`, בדיקות מאגר, קובצי שחרור או תגים קיימים.

## תלויות קפואות

נדרשים Node.js, Python 3 לצפייה ידנית ו־Chromium לבדיקת הדפדפן:

```sh
npm install --cache /tmp/hoops-v11-npm-cache --prefix /tmp/hoops-v11-tools --no-audit --no-fund @gltf-transform/core@4.2.1 three@0.160.1 gltf-validator@2.0.0-dev.3.10 playwright@1.56.1 sharp@0.35.5
```

ברירת המחדל של היצואן היא `/tmp/hoops-v11-tools`, וניתן להחליפה באמצעות `HOOPS_TOOLS_DIR`. המאמתים משתמשים באותו נתיב כברירת מחדל דרך `HOOPS_V11_TOOLS`. בשימוש בתיקייה אחרת יש להגדיר את שניהם לאותו נתיב. `CHROMIUM_PATH` מחליף את `/usr/bin/chromium` עבור בדיקת הדפדפן.

שלושת קובצי התוכנה תחת `runtime/vendor/` הם עותקים מקומיים של Three.js 0.160.1 ו־GLTFLoader/BufferGeometryUtils התואמים לו, ברישיון MIT; הודעת הרישיון נשמרת ב־`THREE-LICENSE.txt`. אלה תלויות תוכנה, ואינן מוצגות כנכסי CC0. אין שימוש בדחיסת Draco או meshopt ואין מפענח WebAssembly בזמן הריצה. שאר כלי הפיתוח אינם מועתקים לחבילה.

## מקור הדמויות והצנרת

`runtime/rig.json` ו־`runtime/models/{guard,wing,center}.glb` הועתקו מעותקי הריצה ב־`hoops-tall-v1`, קומיט `cfd4215c314fb673a6585f7a482ac4fb5ea3cbaa`. הגיבובים נבדקים מול נתוני הפרופילים. לכל דמות 18 עצמות, סיבובי מנוחה בזהות, סקאלה 1 ואורכי איברים משלה. יש לשמר את מידות הפרופיל; החלפת גובה באמצעות סקאלה כללית אינה תחליף לפתרון נפרד.

האנטומיה, הפנים, העור והעיניים מקורם בליבת MakeHuman/MPFB ב־CC0. הגופייה נשענת על גזרה מקורית קודמת של המאגר; השיער, הנעליים, המכנסיים והתאמות המידות והמשקולות נוצרו במקור `hoops-tall-v1`. פרטי המקור המלאים לכל קובץ ב־[LICENSES.md](../LICENSES.md).

פונקציות המתמטיקה, יצואן ה־GLB וצנרת האימות הותאמו מהקוד המקורי CC0 ב־`hoops-motion-v10`, קומיט `a5d245981acba83c1bad88de59bf30ca7bde53a5`. הכוריאוגרפיה החדשה מפורטת ב־`author.mjs`; אין שימוש במוקאפ של אדם אמיתי או בנכסי אנימציה מסחריים.

## סדר הפעלה

מפעילים משורש המאגר, לפי הסדר:

1. יצירת 30 המהלכים ופתרון נפרד לשלושת מבני הגוף, עם דגימות סיום ב־30Hz:

```sh
node workout/island/design/hoops-motion-v11/source/author.mjs
```

2. יצוא 90 קובצי GLB של אנימציה, ללא דחיסה וללא גאומטריית דמות כפולה:

```sh
node workout/island/design/hoops-motion-v11/source/export-glb.mjs
```

3. מדידה עצמאית של ערוצי האנימציה, השלד, משטחי הדמויות והאירועים:

```sh
node workout/island/design/hoops-motion-v11/source/verify.mjs
```

4. טעינת כל האנימציות ונתוני המגע על שלוש הדמויות ב־Chromium תחת CSP שחוסם WASM:

```sh
node workout/island/design/hoops-motion-v11/source/verify-browser.mjs
```

הסקריפט מפעיל שרת מקומי שמגיש את החבילה בלבד; כך טעינה מוצלחת אינה נשענת על תיקיות עיצוב אחיות או על CDN. הוא בודק מחשב וטלפון ומייצר צילומי סקירה. SwiftShader מאפשר בדיקת רינדור, אך אינו מודד ביצועי GPU או חומרת טלפון.

5. ביקורת רציפות נוספת ב־30Hz, לקריאה בלבד, באמצעות FK עצמאי ללא ייבוא המחולל או מתמטיקת החבילה:

```sh
node workout/island/design/hoops-motion-v11/source/audit-motion.mjs --json > workout/island/design/hoops-motion-v11/verification/motion-continuity.json
```

הכלי מודד מהירויות כפות ידיים, שינויים בסיבוב עצמות, כיפוף מרפקים וברכיים, ומסלולי שורש. הוא מספק תנאים לבדיקה חזותית ואינו מוסיף תנאי מוכנות או גבולות פיזיולוגיים. בלי `--json` הוא מציג את הרכז בלבד. ברירת המחדל של הנתיבים יחסית למיקום הסקריפט; ניתן להעביר נתיב חבילה כארגומנט. פלט JSON כולל גיבוב SHA-256 של כל קובץ דגימות.

6. לאחר הצלחת בדיקות הנכסים והדפדפן, יצירת הדוח ומלאי הרישיונות, ואז קריאת החבילה הסופית:

```sh
node workout/island/design/hoops-motion-v11/source/document.mjs
node workout/island/design/hoops-motion-v11/source/verify.mjs
```

`document.mjs` קורא את התוצאות שנכתבו בפועל ומסרב לייצר דוח הצלחה אם חסרה תוצאה, אם יש כשל, או אם חסר אחד מ־90 הצירופים. כדי לרענן מספרים אחרי שינוי תנועה יש להריץ מחדש גם את בדיקת הדפדפן.

## מדידה וטעינה

`verify.mjs` אינו מייבא את מחולל התנועה. הוא משחזר FK מערוצי float32 של ה־GLB שנמסר, משווה אותם ל־JSON, בודק 30Hz, קווטרניונים, מידות שלד ו־root motion יחיד, ומריץ glTF Validator על כל 90 האנימציות ושלושת המודלים.

נטיעה נמדדת ב־120Hz במרחב העולם, רק כאשר שתי הדגימות האפויות השכנות מצהירות על אותו עוגן. מגע יד נמדד בדגימות וביניהן תחת תנאי מגע תואם. כל הקפצה משויכת לאירועי דחיפה, רצפה וחזרה בעלי אותו `bounceIndex`; החזרה נמדדת מול מעטפת הכדור בזמן האירוע. איסוף, קליטה והדיפה נמדדים מול כפות הידיים בפועל. מסירות נבדקות מול נקודת המקבל החיצוני, וזריקות מול מעבר יורד דרך פתח טבעת בגובה 3.05 מ׳. סף הנטיעה ושגיאות מגע/חזרה/רצפה הוא 0.02 מ׳. שתי זריקות השלוש נבדקות גם למרחק שחרור של 6.75 מ׳ לפחות.

האימות קורא כל קובץ בחבילה: GLB ו־JSON מפוענחים, JavaScript נבדק לתחביר ותמונות האימות מפוענחות. בדיקות משטח עור בדגימות נבחרות נועדו לזהות השחתה; הן אינן הוכחה להעדר כל חדירה עצמית או לאנטומיה מושלמת. גבולות המדידה ומספרי המדידות נמצאים ב־[REPORT.md](../REPORT.md).

פלטי המדידה: `verification/measurements.json`, `verification/gltf-validation.json`, `verification/browser.json` והצילומים תחת אותה תיקייה. הדוח נוצר מהם, ומלאי הרישיונות סורק את כל הקבצים הקיימים בפועל, כולל התיעוד עצמו.

## חוזה היצוא

כל GLB של אנימציה כולל `Motion`, את השלד הקנוני ו־`Ball`. הזזות המנוחה תואמות לפרופיל המסוים; `Hips.translation` כולל מנוחה והיסט. זמן glTF הוא בשניות; זמן דגימות JSON מנורמל. תרגומים LINEAR וסיבובים SLERP; אין easing נוסף בזמן הניגון. תנועת עולם נמצאת ב־`Motion` בלבד; `Root` נשאר בזהות. האירועים והמגעים כלולים ב־JSON וב־extras של ה־GLB.

הדגמת חיבור לדמות ומשמעות אירועי הכדור ב־[README.md](../README.md). אירועי המסירה, הקליטה וההדיפה הם מטא־נתונים לתזמון; מנוע המשחק אחראי לבעלות בכדור, חוקיות מגעים ותוצאת הפעולה. חיבור בין קליפים דורש יישור שורש ושימור נטיעה לאחר ערבוב.
