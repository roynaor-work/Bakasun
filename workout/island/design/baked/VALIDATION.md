# בדיקות חבילת הצללה

הבדיקות מתייחסות לקבצים המסופקים, לא רק למפרט. סיכום מספרי ומשקל כל התיקייה: [validation.json](validation.json).

| בדיקה | תוצאה |
| --- | --- |
| שלוש מפות AO | WebP, ‏512×512, ללא אלפא, R=G=B בכל פיקסל מפוענח |
| שלוש מפות תאורה | WebP, ‏256×256, ללא אלפא, R=G=B בכל פיקסל מפוענח |
| מקור | SHA-256 של שלושת GLB המקוריים תואם ל־manifest; לא נערך קובץ מקור |
| UV מקור | אולם ומדרון ללא חפיפה בדגימת 1024²; באצטדיון זוהתה חפיפת משטח הדשא ונוצר עותק עם UV שני |
| העותק המפוענח | מספר המשולשים, שמות הרשתות, UV0, צבעי הקודקודים, מיקומים ועוגנים נשמרו; UV1 ללא חפיפות בדגימה |
| תצוגה | 18 רינדורים משלושה מצבים, שלוש סצנות ושני כיוונים; כולם מפוענחים ומשתנים בפועל בין המצבים |
| ללא רשת | פתיחת file:// ב־Chromium עם offline=true וחסימת HTTP/HTTPS; אפס בקשות חיצוניות ואפס שגיאות דף |
| טלפונים | 390×844 ו־844×390, בכל אחד שני כיווני תצוגה ושני מצבי מפות; אין גלילה אופקית |
| מחווני השוואה | שני קצות המחוון נבדקו: 0% ו־100% |
| מסלול צבעים | כלי vertex_bake הורץ על האולם ויצר GLB חדש מחוץ לחבילה; אינו עורך את המקור |
| תקציב | כל הקבצים שבתיקייה נספרים, כולל כלים, תצוגות ודוחות; עד 1,200,000 bytes |

פירוט ביקורת העותק: [geometry-validation.json](geometry-validation.json). ההשוואה נעשית לאחר פענוח Draco מחדש של המקור והעותק; במסירה זו שגיאת המיקום, UV0 והצבע שנמדדה היא אפס. השדה `copy_vertices` יכול להיות גבוה יותר עקב פיצולי תפרי UV1, ללא שינוי משולשים או משטח. מספר הקודקודים המקורי הכולל 10,204, ובעותק 10,264; UV1 מפוענח כ־float32 מוסיף 82,112 bytes, ופיצולי התפרים מוסיפים עלות קטנה נוספת של שדות הקודקוד הקיימים.

האפייה נעשית על נתוני ה־GLB המיובאים. הרינדורים מופקים בייבוא חוזר מהעותק הסופי/המקור עם קובצי ה־WebP שנפענחו, ולא מה־float buffers הזמניים. החשיפה היא Standard, ללא tone mapping משתנה, אותם מרקמי סביבה ובסיס תאורה בין לפני ואחרי. המפות הן הנתון היחיד שמשתנה. כיוון המצלמה מותאם לאורך ולרוחב ונשמר בין מצבי כל כיוון; המודל נשאר שלם בפריים.

נבדקו חזותית שלוש הסצנות: עומק היציעים, מפגש הגג והקורות, החיבור לשולי המדרון, קריאות המשטחים ושמירת השלג בהיר. תצוגת האורך משתמשת במצלמה אורכית ולא במתיחה של רינדור הרוחב. מפת התאורה היא אפשרות נפרדת כדי לא לכפות כיוון אור על מנוע שכבר מכיל תאורה.

מגבלות: ביקורת UV היא בדיקת דגימה של פנים משולשים, לא הוכחה אנליטית לכל חפיפה תת־פיקסלית. איים זעירים מקבלים מעט טקסלים ב־512²; ביטול mipmaps מצמצם זליגה ביניהם. האפייה מתאימה לאביזרים סטטיים במיקומים שב־README. מסלול צבעי קודקודים מאבד פרטי צל על פאות גדולות ודלות קודקודים; לכן מפות הן המסלול המומלץ למשטח המגרש. אין טענה למשחק משולב או למדידת FPS בטלפון פיזי.

## בדיקות כלל המאגר בסביבת Windows

בוצעה הרצת `node --test tests/*.mjs`; היא לא השלימה סיכום כללי ונעצרה, ולכן אינה מסומנת כהצלחה. בהרצה עם checkout מסוג CRLF נרשמו שלושה כישלונות בקבצים שלא שונו: בדיקת מסלול replay של מצלמה, השוואת תיעוד שורות דיבור וביקורת גיבובי קוד Boar Island.

לבדיקת הבסיס נוצר checkout נפרד של אותו קומיט main ללא המרת סיומות שורה (LF). באותם שלושה קובצי בדיקה עברו **24 מתוך 25**: בדיקות תיעוד הדיבור וגיבובי הקוד עברו; בדיקת `synthetic low-standing skeleton goes from zero to five full squats, with a 504ms model gap` נכשלה גם בבסיס הנקי עקב נתיב Windows כפול שמתחיל ב־`C:\C:\`. זו בעיה קיימת מחוץ לתיקיית החבילה. הרצה רחבה נוספת על LF עם אותה חבילה רשמה את אותו כישלון והופסקה ללא סיכום; אין טענה שכל בדיקות המאגר עברו מקומית. לא נערכו תיקונים בקוד או בבדיקות שמחוץ לחבילה. בדיקות המפות, ה־UV, התצוגה, התקציב ומסלול צבעי הקודקודים הסתיימו כמתועד לעיל.
