# האי שלי · הצללה אפויה

חבילת נכסים בלבד, על בסיס `main` בקומיט `039419a2182d40f12d9acbfe0451e18118394d41` מ־30.10.2026. שלוש מפות AO מקוריות, שלוש מפות תאורה סטטיות קטנות ותצוגת השוואה מקומית. כל התוספות נמצאות ב־`workout/island/design/baked/`. קובצי המקור, לוגיקת המשחק ותגי גרסה לא נערכו. זו מסירת עיצוב; אין חיבור למשחק בשלב הזה.

## פתיחה ובדיקה

1. פתחו את [preview.html](preview.html) ישירות מהדיסק. אין שרת, התקנה, CDN או בקשת רשת.
2. עברו בין אורך לרוחב ובין AO בלבד ל־AO עם תאורה. הזיזו את המחוון בכל סצנה; אפשר גם עם מקשי החצים.
3. בדקו שהיציעים מקבלים עומק בין המדרגות, שהמפגש מתחת לגגות כהה בעדינות ושהשלג נשאר בהיר. המצלמה, המשטחים, החשיפה וצבעי המודלים זהים לפני/אחרי. אלו רינדורים מה־GLB הסופיים ומה־WebP המפוענחים, ללא AO, צללים או פוסט־פרוסס בזמן הצפייה.

הטקסטורות הקיימות ב־`../environment/` משמשות במשטחי הדשא, הפרקט והשלג של הרינדורים בלבד. אין עותק נוסף שלהן בחבילה. ה־preview עצמאי גם אם מעתיקים רק את `baked/`.

## קבצים ו־UV

| מודל | קובץ לטעינה | AO | תאורה | ערוץ UV למפות |
| --- | --- | --- | --- | --- |
| אצטדיון | [soccer-stadium-uv2.glb](soccer-stadium-uv2.glb) | [512×512](soccer-stadium-ao.webp) | [256×256](soccer-stadium-light.webp) | `TEXCOORD_1` |
| אולם | `../models/basketball-arena.glb` המקורי | [512×512](basketball-arena-ao.webp) | [256×256](basketball-arena-light.webp) | `TEXCOORD_0` |
| מדרון | `../models/ski-slope.glb` המקורי | [512×512](ski-slope-ao.webp) | [256×256](ski-slope-light.webp) | `TEXCOORD_0` |

כל המפות הן RGB שבו R=G=B בדיוק, 8 ביט לערוץ, WebP ללא אובדן, ללא אלפא. אלה **נתונים ליניאריים**, ללא המרת sRGB. AO: לבן פתוח, שחור חסום. UV מקוריים נבדקו על רשת דגימה של 1024²: באולם ובמדרון לא נמצאו חפיפות, יציאה מהאריח או משולשי UV מנוונים.

באצטדיון, UV הדשא מכסה את כל האריח וחופף לאטלס הקליפה: נמצאו 88,871 פיקסלים חופפים בדגימה. העותק שומר את UV0 עבור צבע הבסיס ומוסיף UV1 ייעודי, ללא חפיפות באותה בדיקה. אין שינוי מכוון בגאומטריה, בצבעים, בשמות או בעוגנים; יש קידוד Draco חוזר בעותק בלבד. UV של רשתות זמניות אוחדו לצורך הפריסה והועברו חזרה לרשת המקורית, בלי לרתך את רשת המסירה. כיוון התמונה מתאים ל־glTF: `flipY=false` ב־Three.

## שילוב דרך aoMap

דוגמה ל־Three.js בסגנון r160 שכבר נמצא במאגר. יש להתאים את מיקום הקבצים למיקום דף הטעינה. `GLTFLoader` עם מפענח Draco מקומי טוען את המודל כרגיל. אין בחבילה יבוא או שינוי בקוד המשחק.

```js
const ao = await new THREE.TextureLoader().loadAsync('baked/soccer-stadium-ao.webp');
ao.colorSpace = THREE.NoColorSpace;
ao.flipY = false;
ao.channel = 1; // stadium: TEXCOORD_1 -> geometry.attributes.uv1
ao.wrapS = ao.wrapT = THREE.ClampToEdgeWrapping;
ao.generateMipmaps = false;
ao.minFilter = ao.magFilter = THREE.LinearFilter;

gltf.scene.traverse(mesh => {
  if (!mesh.isMesh) return;
  const materials = Array.isArray(mesh.material) ? mesh.material : [mesh.material];
  for (const material of materials) {
    material.aoMap = ao;
    material.aoMapIntensity = 1;
    material.needsUpdate = true;
  }
});
```

באולם ובמדרון הגדירו `ao.channel = 0` והשתמשו ב־GLB המקורי. שומרים `vertexColors=true` ואת צבע הבסיס הקיים. ב־Three ישן שקורא `uv2` במקום `uv1`, יש לשכפל את ערוץ ה־UV המתאים **בגאומטריה בזיכרון בלבד**. אין צורך להחליף את UV0 או את מיפוי הדשא כדי להחיל AO.

`aoMap` משפיע על האור העקיף של MeshStandard/Physical; הוא לא מכהה שמש ישירה במלואה. הספקת אור סביבה מתון מאפשרת לראות את ההשפעה. בתצוגה שלנו נעשה שימוש בהכפלה מלאה בצבע, כמו במסלול צבעי הקודקודים למטה; לכן עוצמת האפקט במנוע עם תאורה קיימת יכולה להיות שונה.

## מפת התאורה הקטנה

מפת התאורה מוסיפה הצללה רחבה וצל סטטי מתחת לקורות/שערים. היא אפיית החזר דיפוזי ממשטח לבן: עולם לבן בעוצמה 0.65, שמש בעוצמה 0.7, זווית ריכוך 12°, כיוון מקור ב־Blender ‏`(-1,-1,2)` (ב־glTF ‏`(-1,2,1)`). אין בה טקסטורת צבע. הערכים מוגבלים ל־0.35–1 כדי לשמור על הקריאות והשלג הלבן.

לטעינה כ־`material.lightMap`, מגדירים לה את אותו `channel`, ‏`NoColorSpace`, ‏`flipY=false` ואת אותם מסננים, ואז `lightMapIntensity=1`. עבור המודל הסטטי הזה מכבים תאורה דיפוזית נוספת (Ambient/Hemisphere/Directional), אחרת מוסיפים אור פעמיים. אפשר להשאיר תאורה לשחקנים דרך שכבות נפרדות בשילוב עתידי. שימוש ב־AO בלבד מתאים למנוע שכבר מאיר את הסביבה; מפת התאורה היא אפשרות נוספת, לא חובה.

האפייה היא מקומית למודל ולפריסה המתועדת: שני `soccer-goal.glb` על קווי השער, שער סלאלום במרכז המדרון והסלים המובנים באולם. ב־Blender Z-up: השער הדרומי `(0,-52.5,0.04)`, סיבוב Z=0; הצפוני `(0,52.5,0.04)`, סיבוב Z=π; סלאלום `(0,0,3.25)`. ב־glTF Y-up: `(0,0.04,52.5)` וסיבוב Y=0, ‏`(0,0.04,-52.5)` וסיבוב Y=π, ‏`(0,3.25,0)` בהתאמה. המודלים עצמם נטענים ללא שינוי קנה מידה. אם משנים פריסה, מסירים אביזרים או משנים את כיוון השמש ביחס לסביבה, יש לאפות מחדש. האפייה אינה מתארת צל של שחקן נע.

## מסלול ללא תוספת חישוב בכל פריים

`aoMap` מוסיף דגימת טקסטורה; הוא חוסך חישוב AO וצללים בזמן ריצה, אך אינו חינם לחלוטין. כדי להימנע גם מדגימה זו, מכפילים **בזמן בניית הנכס** את RGB הליניארי של `COLOR_0` בערך AO שנדגם ב־UV המתאים, ומשאירים אלפא ללא שינוי. אם משתמשים גם בתאורה, הנוסחה היא `COLOR_0.rgb *= AO * light`. לא מפעילים שוב את המפות על הצבעים המוכפלים.

[tools/vertex_bake.py](tools/vertex_bake.py) מבצע זאת ב־Blender עם דגימה ביליניארית ושומר GLB חדש בנתיב מפורש. הוא אינו מחליף מודל מקור. לדוגמה, משורש `baked/`:

```text
blender -b --python tools/vertex_bake.py -- --asset basketball-arena --out /path/to/build/basketball-arena-color.glb
```

הוספת `--light` מכפילה גם את התאורה. בעת השימוש בתוצאה, שומרים `vertexColors=true`, לא טוענים AO/lightMap, ומתאימים את תאורת החומר כדי שלא להאיר שוב תאורה שכבר אפויה. אין תוספת קודקודים או שדות קודקוד. ב־COLOR_0 מסוג BYTE_COLOR אפשר לאבד מעט דיוק בגוונים כהים. למשטח מגרש גדול עם ארבעה קודקודים אין מספיק דגימות לצל מגע קטן: הוא יישמר טוב יותר במסלול המפות. אין כאן הבטחה ששני המסלולים ייראו זהים.

## משקל וזיכרון

KB/MB הם עשרוניים; MiB הם בינאריים. משקל החבילה המדויק, כולל כל תמונות ההשוואה, הכלים והתיעוד, מופיע ב־[validation.json](validation.json), ונבדק מול **1,200,000 bytes**.

| סצנה | שתי המפות בדיסק | זיכרון GPU נוסף, RGBA8 ללא mipmaps |
| --- | ---: | ---: |
| אצטדיון | 47,158 bytes | 1.25 MiB |
| אולם | 59,244 bytes | 1.25 MiB |
| מדרון | 20,166 bytes | 1.25 MiB |
| כולן | 126,568 bytes | 3.75 MiB |

AO בלבד: 1 MiB לסצנה; תאורה בלבד: 0.25 MiB. עם שרשרת mipmaps מלאה העלות גדלה בכשליש (כ־1.667 MiB לזוג). המסננים בדוגמה מונעים mipmaps, גם כדי להימנע מזליגת איים קטנים במפות האלה. אין להסיק מגודל WebP את גודל הטקסטורה בזיכרון. ייתכן עותק מפוענח נוסף בצד CPU; עלויות דפדפן/דרייבר אינן כלולות. תצוגת ה־HTML אינה חלק מנכסי זמן הריצה ויש לטעון במשחק רק את הסצנה הפעילה.

עותק האצטדיון שוקל 96,908 bytes בדיסק, לעומת 66,080 במקור; הוא **מחליף** את טעינת המקור בסצנה, ולא נטען במקביל אליו. UV שני עולה 82,112 bytes ב־10,264 קודקודים מפוענחים; 60 קודקודים נוספים נובעים מפיצול תפרי UV ומוסיפים גם עותקים של שדות הקודקוד הקיימים. מספר המשולשים לא משתנה. מסלול הכפלת צבעים מחליף את COLOR_0, ולכן אינו מוסיף טקסטורות GPU או שדה קודקוד חדש.

## שחזור

כלי ההפקה הם Blender 5.2.2 LTS עם Cycles CPU, ‏64 דגימות ו־seed=271030, ‏AO בטווח 4 מ׳ לאצטדיון, 1.4 מ׳ לאולם ו־1.8 מ׳ למדרון; padding של 4 פיקסלים. [manifest.json](manifest.json) כולל ערוצי UV, גיבובי מקור, ביקורת UV ונתוני מפות. מקורות ורישיונות ב־[LICENSES.md](LICENSES.md).

1. משורש `baked/`, מריצים `blender -b -t 6 --python tools/bake.py -- --scratch /path/to/scratch`.
2. מריצים `python tools/package.py --scratch /path/to/scratch` (נדרשים numpy ו־Pillow).
3. מריצים שוב את פקודת Blender עם `--render-only`, ואז את פקודת Python עם `--renders`.
4. מריצים `tools/validate_blender.py` ב־Blender ו־`tools/validate.py` ב־Python. בדיקת הדפדפן היא `node tools/validate-browser.cjs` עם Playwright מותקן.

התוצרים היחידים שהכלים כותבים לתיקיית החבילה הם עותק האצטדיון, המפות, רינדורים דחוסים ודוחות. נתוני אפייה זמניים ורינדורי PNG נכתבים לנתיב scratch מפורש. התוצאות עשויות להשתנות מעט בין גרסאות Blender/Draco; אין צורך להפיק אותן כדי לפתוח את התצוגה.
