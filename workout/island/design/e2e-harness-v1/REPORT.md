## סביבת הבדיקה ומשמעות המספרים

Chromium 151.0.7922.173, Playwright 1.62.1 ו־Node 24.19.0, מסך 844×390, יחס פיקסלים 1, מגע ומצב מובייל. דגלי הגרפיקה היו `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`. כל משחק קיבל הקשר חדש, ללא מצב שמור, ו־Service Workers חסומים. מפענחי הנכסים הקיימים פעלו כרגיל.

משך ההרצה הראשית כולה היה כ־12.1 דקות, כולל עליית האי, בחירת משחקים, טעינות וצילומים. זמן הפריים הראשון בטבלה מתחיל בנגיעה שמפעילה משחק וכולל את הטעינה והספירה שלאחריה. `islandToFirstFrameMs` בדוח JSON כולל גם את המסלול מעליית האי. הזיהוי הוא דגימה ראשונה של מוני ציור חיוביים בקנבס המשחק הפעיל; הוא אינו חותמת זמן GPU מדויקת.

זמן המשחק הפעיל הוא זמן קיר בין תצפיות פעילות. זמן הסימולציה נמדד בנפרד בדוח, ועלול להתקדם לאט יותר כשהציור ב־SwiftShader כבד. למשל, במרוצים נצפו 1.47 שניות התקדמות סימולציה במהלך 33.11 שניות פעילות, ובחזירים 2.23 שניות במהלך 35.09 שניות. לכן התוצאות מאשרות את מסלול הדפדפן, המגע, תקינות ההפעלה והמדידה; הן אינן אישור לביצועים בטלפון. הבדלי הזמן האלה ומספרי המשולשים הגבוהים בסקי ובחזירים מצדיקים בדיקת ביצועים במכשיר אמיתי.

מוני המשולשים וקריאות הציור מגיעים מנתוני המנוע הקיימים. אלה שיאים שנדגמו לאורך התרחיש, ללא עטיפה או שינוי של פונקציות הציור. צללים והשתקפויות נספרים לפי דרך הדיווח של כל משחק. לא הוחל תקציב גרפי אחיד; אפשר להוסיף תקציב מפורש ב־API או ב־CLI.

מדיניות ה־CSP הוגשה כפי שהיא באפליקציה. למסגרת הפנימית של החזירים לא נמצאו כותרת CSP או מטא־CSP משלה; מדיניות הדף האב אינה מדיניות התוכן של מסגרת HTTP נפרדת. לכן אפס הפרות שם אינו אישור לכיסוי מלא במדיניות. הראיה מופיעה ב־`documentPolicies` וב־`cspDocuments` של [תוצאת החזירים](artifacts/baseline/boarDefense/baseline/result.json). הניטור עצמו אומת גם באמצעות הפרות מכוונות במסגרת ובעובד בעלי מדיניות.

## החלטת WASM והמסירה לקלוד

לאחר שהתגלה שחלק מהמפענחים הקיימים דורשים WASM, רועי ביקש שאבחר את ההמלצה ואעדכן את קלוד. ההחלטה: קוד הערכה החדש נשאר JavaScript בלבד, וההרצה הראשית משתמשת במפענחים שהאפליקציה כבר מספקת. לא נוספו מפענח או קובץ WASM.

אבחון נפרד עם WASM כבוי נשמר במלואו. הוא הסתיים ב־2 מסלולים שעברו ו־8 שנכשלו: כדורגל, כדורסל וסקי נחסמו לפני פריים משחק; במסלולים נוספים נתפסו חריגות של מפענחים, ובספינות השלב הקצר הסתיים מוקדם. חלק מהמסלולים המשיכו עם גרפיקת גיבוי. נשמרו השגיאות הגולמיות וצילומי הכישלון; כמה ערוצי ניטור עשויים לתעד את אותה תקלה יותר מפעם אחת. באבחון זה WASM אכן לא היה חשוף; הדגל `--jitless` מכבה גם JIT, ולכן זמניו אינם בסיס להשוואה להרצה הראשית.

נוצר [קובץ מסירה לקלוד](CLAUDE-HANDOFF.md) עם ההחלטה, הפקודות והממצאים. לא נמצא בסשן ערוץ שליחה ישיר לשיחת קלוד; הקובץ נמסר דרך הענף.

## שחזור

בדיקת הערכה:

```bash
node --test workout/island/design/e2e-harness-v1/src/tests/*.test.mjs
```

הרצה ראשית חדשה:

```bash
node workout/island/design/e2e-harness-v1/src/cli.mjs --games all --timeout-ms 90000 --output workout/island/design/e2e-harness-v1/artifacts/baseline-new
```

בדיקת כל דגלי החזרה באמצעות ה־CLI, כולל פתיחות הבסיס:

```bash
node workout/island/design/e2e-harness-v1/src/cli.mjs --matrix --scenario opening --output workout/island/design/e2e-harness-v1/artifacts/flags-new
```

סדרת 13 המקרים שנמסרה הופעלה דרך `runScenario` עם `scenario: 'opening'`, השאילתה והציפייה של כל מקרה, והופק דוח מאוחד. אפשר לשחזר מקרה יחיד עם `--case`.
