# G3j — כדורגל: דוח אימות

ענף `codex/g3j-soccer`, נפתח מ־`origin/main` ב־`1f05826` (כולל G3i). לפני הריצה המלאה בוצעו fetch ומיזוג main; main כבר היה כלול בענף.

## אימות

- `tests/island-g3j.test.mjs`: 25 בדיקות חדשות, כולל מקורות Web Audio ותזמון עצירת הקהל אחרי 2.08 שניות (כולל דעיכה).
- `node --test tests/*.mjs`: 1,898 בדיקות; 1,860 עברו, 38 דולגו, **0 כשלים**.
- 16 תרחישי בעיטה רגילה הושוו למימוש המקורי ב־`origin/main`: כיוון אוטומטי/ידני, שתי מחציות וארבעה משכי לחיצה. אירוע הבעיטה, פיזיקת הכדור והטעינה זהים בדיוק. קובץ `soccer-shot.mjs` לא שונה.
- בדיקות G3j בדפדפן: Chromium / SwiftShader, מגע מדומה, 844×390 ו־740×360. נבדקו גם גודל וגבולות הכפתורים, העדר מלל, מקורות קול שנפתחו בפועל, AudioContext במצב running בזמן הגול, וניקוי בסיום.
- מגבלות רינדור: עד 130,000 משולשים ו־90 קריאות ציור; המדידות בדוח JSON.
- ריצת כל 33 קובצי `workout/island/tests/*-browser.mjs` ב־844×390: **33/33 הסתיימו בקוד 0**. תוצאות, ניסיונות חוזרים והגדרות הרצה ב־[browser-suite.json](../verification/g3j/browser-suite.json). G3j נבדק גם ב־740×360.
- השרת: `python3 -m http.server 8765 --bind 127.0.0.1`, משורש המאגר. בדיקת bind אישרה שהפורט פנוי לפני שהופעל; לא נעשה שימוש בשרת ישן. לכל בדיקות הדפדפן הוגדר `ISLAND_URL=http://127.0.0.1:8765/workout/island/?dev=1`.

הציפיות הישנות בבדיקות הכדורגל עודכנו רק במקום שבו הדרישה החדשה מחליפה התנהגות קודמת: מעבר שליטה בעת המסירה, בחירת שחקן שדה בחידוש, מיקום על קו החמש, נגיחה וכיוון קולות הגול. ספי רגרסיית התנועה, ההפרדה והקושי נשמרו. שחקני כיסוי מגיבים גם לכיוון תנועת הכדור; יריב מנצל נתיב בעיטה שנפתח בלי לחכות למחזור החלטת המסירה הבא.

## גבולות השינוי

רק קובצי כדורגל, בדיקות הכדורגל, הוכחות G3j וסעיף `minigames.soccer` ב־config השתנו. CSS חדש ב־`minigames/g3j-soccer.css` ונטען עם `?v=g9-20261020-1`. אין שינוי ב־DATA_VERSION, CURRENT_VERSION, מחרוזות שאינן כדורגל, shared sound, game-shell, press, app, styles.css, buildings, CHANGELOG או QA. אף דגם GLB לא שונה או נמחק.

לא בוצעה בדיקה בטלפון פיזי, ב־Safari/iPhone או מדידת FPS בטלפון. בדיקת הקול מאמתת טעינת דגימות, יצירת מקורות, אירועים ותזמון; שמיעה ברמקול המכשיר נשארת למשוב הבעלים.

ב־G3d אופס גם זמן ההמתנה של ההחלפה בתרחיש ההגנה כדי לבודד אותו ממסירה בתרחיש הקודם. בדיקת הטניס בקובץ `g4d-browser.mjs` קוראת דווקא `G4E_WIDTH`/`G4E_HEIGHT`; כאשר כופים רוחב, שומר הבדיקות יוצר `844-verification.json` אך סיום הסקריפט מצפה ל־`verification.json`. להרצה הסופית הוגדר הרוחב הנכון ונוצר hard link זמני בין שני שמות אותו דוח, כך שהכתיבה מעדכנת את שניהם וה־rename מסיים בקוד 0. כל האסרטים עברו; קובצי הטניס לא נערכו, ותוצרי הבדיקות של המשחקים האחרים הוצאו מהשינוי.
