# תצוגת עיר מלאה (`?cityPreview=full`)

תאריך: 07/11/2026. ענף: `claude/city-full-preview`. גרסה: לא נגעתי ב-`release.json`, בתגי `?v=` ובגרסה (דגל כיבוי: בלי `?cityPreview` הכול כמו קודם).

## איך משתמשים

| כתובת | מה רואים |
|---|---|
| `…/workout/island/?cityPreview=full` | עיר מלאה, 563 בניינים וכבישים על 32×32 משבצות |
| `…?cityPreview=half` | חצי מלאה: כל הבניינים הגדולים ועוד כמחצית מהקטנים (425) |
| `…?cityPreview=empty` | ריקה: רק כביש ההתחלה |
| `…&cityLod=0` | בלי הקלות ביצועים (להשוואה בלבד) |

בראש המסך סרגל: **מלאה / חצי מלאה / ריקה / סיבוב** (סיבוב מצלמה איטי) **/ צילום** (מסתיר את הסרגל, נגיעה בפינה השמאלית התחתונה מחזירה) **/ יציאה** (טוען את העיר האמיתית בלי הדגל). ליד הכותרת מספר פריימים לשנייה חי, כדי שאפשר לקרוא אותו בטלפון.

## קריאה בלבד: איך מובטח

| שכבה | מה עושה |
|---|---|
| אחסון | המנוע מקבל עטיפה שקוראת מהאחסון האמיתי אבל כל כתיבה ומחיקה נבלעות (`readOnlyStorage`). אין שמירה אוטומטית, ואין כתיבה ל-localStorage |
| תצוגה | `view.setWorld` נעול על שורות התצוגה. המנוע והמצב שלו לא משתנים |
| רקע | בתצוגה לא נרשם service worker ולא יורדת מטמון לא-מקוון (כדי שלא ייכתב סטטוס לאחסון) |
| ממשק | חלון יצירת הדמות והממשק הרגיל מוסתרים בזמן התצוגה |
| ענן | באי אין ענן. לא נוסף |

**בדיקה אוטומטית** (`tests/island-city-preview.test.mjs`, בדפדפן עם `ISLAND_CITY_PREVIEW_BROWSER=1`): שומרים משחק, יוצאים מהדף, מצלמים את כל ה-localStorage; נכנסים לכל אחד משלושת המצבים (בתוך המצב לוחצים על כל הכפתורים); יוצאים ומשווים. **התוצאה: זהה בית לפני ואחרי, בשלושת המצבים, בלי שגיאות קונסול** (`changedDuringPreview: []` ב-`measurements-*.json`).

הערה: `changedAfterExit` בקבצי המדידה לא ריק, וזה צפוי: אחרי היציאה נטענת העיר האמיתית והמנוע הרגיל שומר לבד (מגדיל כסף לפי זמן). זה לא קשור לתצוגה.

## ביצועים

כל המדידות ב-swiftshader (עיבוד תוכנה, 844×390). **הן מראות יחס, לא קצב בטלפון.**

| מדד | לפני (`&cityLod=0`) | אחרי (ברירת מחדל) | שינוי |
|---|---|---|---|
| משולשים בפריים | 2,415,141 | 973,807 | **-60%** |
| קריאות ציור | 345 | 344 | אפס |
| זמן ציור פריים (swiftshader, חציון) | 4,557 מ"ש | 2,195 מ"ש | **-52%** |
| זמן עד מוכן | 3.6 שניות | 3.5 שניות | אפס |
| חצי מלאה | | 686,327 משולשים, 1,571 מ"ש | |
| ריקה (כביש בלבד) | | 157,910 משולשים, 213 מ"ש | |

| רכיב | משולשים לפני | אחרי | איך |
|---|---|---|---|
| בניינים (563) | ~1.6M (הערכה: סך הכול פחות שאר הרכיבים) | 611K | עותקים קלים של 25+13 דגמים: כ-1.6K משולשים במקום 4.6K בממוצע, מרקם 256 |
| דקלי רחוב (28) | 146K-262K | 37K | דקל קל (1.3K במקום 5.2K) ורמת רחוב נמוכה |
| נטיעות | 171K | 6K | רמת רחוב נמוכה (הקיימת במשחק) |
| צללים אמיתיים מהבניינים | 563 | 0 | נשארים צללי המגע הרכים |
| סביבה (ים, חוף) | 131K | 131K | לא נגעתי |

- **מתי מה פעיל:** מרחוק (זום קטן מ-2.2) עותקים קלים. כשמתקרבים, או במצב צילום, הדגמים המלאים. המעבר שקט: הדגם הקודם נשאר עד שהחדש נטען.
- **קצב פריימים:** ב-swiftshader הוא 1.2 בכל המצבים, גם בעיר ריקה, ולכן לא מגלה כלום. **צריך מדידה בטלפון.** היעד 30. בטלפון קורא המשחק לעצמו להוריד איכות כשהקצב נמוך, ובתצוגה זה פעיל.
- **הורדה:** 38 קבצי LOD (3.0MB) ועוד דקל (122KB), נטענים רק בתצוגה ורק לפי הצורך. המשחק הרגיל לא מושפע.
- אם בטלפון יהיה עדיין כבד: לשים 4 רמות (מקרוב, בינוני, רחוק, תיבה), להוריד עוד את הדגמים הרחוקים לכ-500 משולשים, להסתיר בניינים מחוץ למסך (כבר נעשה בלי כוונה: three.js לא מצייר מה שמחוץ למסך).

## המלצות לפי רמת העיר (כמו SimCity)

| רמה | מה זה | מה צריך | עלות |
|---|---|---|---|
| א. כמו היום | משבצת 1×1, בניין אחד, בלי אזורים | כלום | 0 |
| ב. חלקות גדולות | מפעל, בית חולים, אצטדיון וכו' בחלקות 2×2 עד 4×4 | `footprint` בנתוני הבניינים ו-`PREVIEW_FOOTPRINT` כבסיס. חוקי ההנחה והמחיר לפי השטח | קטנה |
| ג. אזורים | רועי מצייר אזור מגורים/מסחר/תעשייה והעיר ממלאת לבד לפי ביקוש | `engine/city-management.mjs` כבר מכיל `zones`; לחבר למילוי אוטומטי כמו בתצוגה הזו | בינונית |
| ד. שירותים וכבישים | כיסוי כיבוי/משטרה/בית חולים לפי מרחק, תנועה ורמזורים | מדידת כיסוי, עומס כבישים, רמזורים אמיתיים (דגם 55) | גדולה |
| ה. SimCity מלא | חשמל, מים, מיסים, פשיעה, מגדלים שגדלים לבד | כל הנ"ל ועוד מערכת כלכלה | גדולה מאוד |

**המלצה:** ב' עכשיו (התצוגה הזו מראה בדיוק איך זה נראה), ג' אחר כך. ד'-ה' רק אחרי שרועי אישר שהוא רוצה את הקצב האיטי של משחק ניהול.
