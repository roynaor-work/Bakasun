# מעבדת מצלמה פרטית

מעבדה נפרדת ב־`workout/cam-lab/`. אין קישור מהאפליקציה החיה, אין ייבוא של הקוד שלה ואין שינוי בנתונים שלה.

## פתיחה בטלפון

הכתובת **אחרי מיזוג ה־PR ופריסת Pages**:

```text
https://roynaor-work.github.io/Bakasun/workout/cam-lab/
```

1. מבוגר פותח ב־Chrome באנדרואיד או Safari מעודכן באייפון/אייפד. נדרש HTTPS והרשאת מצלמה; פתיחת קובץ או HTTP דרך כתובת IP לא מאפשרות מצלמה.
2. מזינים גיל וגובה, בוחרים תרגיל ומאפשרים מצלמה. לא מתבקשת הרשאת מיקרופון.
3. מניחים את המכשיר יציב בגובה המותניים, כ־2–3 מטרים מהילד, באור טוב ועם מרחב פנוי. מתאימים את המרחק לפי המסגרת, לא לפי מספר קבוע.
4. עומדים ישר מול המכשיר. הראש, הידיים ושני הקרסוליים צריכים להיות בתמונה במשך 1.5 שניות. משאירים מקום לידיים למעלה ולקפיצה. הכפתור מופעל רק כשהזיהוי מתאים.
5. לוחצים ״מתחילים״, נשארים בעמידה רגע, עושים תרגיל ולוחצים ״סיום ותוצאה״. התוצאה מציגה חזרות, ניסיונות שלא נספרו וסיבות.

המודל וה־WASM כבר במאגר. אין npm install, אין CDN בזמן שימוש ואין שירות ענן. יש צורך בתמיכה ב־Worker, OffscreenCanvas, createImageBitmap ו־WebAssembly; אם אינם זמינים מוצגת הודעה, אין מעבר לזיהוי בענן.

המשוב מתאר תנועה, לא את הילד. כשלא ברור מה קרה, ההנחיה היא לשאול מבוגר. ״ברכיים פנימה״ הוא סימן חזותי אפשרי ולא אבחון. אין לבקש מהילד לבצע תנועה לא תקינה לצורך ניסוי. אפשר לבדוק מצב כזה בנקודות המדומות.

## בחירת התרגיל השלישי

`high-knees` — ״ברכיים גבוהות״ מהקטלוג הקיים (`workout/js/exercises.js`). תנועה בעמידה עם שינוי גדול בגובה הברך והקרסול, ללא ציוד, מגע ברצפה או תנועה במסדרון. עדיפה לניסוי ראשון על הרמות עקבים (שינוי קטן), שכיבות סמיכה (הסתרות) וריצה במסדרון (יציאה מהמסגרת). בקטלוג זה תרגיל זמן; במעבדה בלבד סופרים כל הרמה וחזרה בנפרד.

## ספים והיגיון

הספים הם נקודת פתיחה הנדסית, **לא** נורמות רפואיות או ספי כושר מוכחים לילדים. נדרשת השוואה לספירה ידנית לפני שימוש אמיתי. גובה שהוזן אינו מאפשר להפיק סנטימטרים מדויקים ממצלמה יחידה; מדובר בקירוב יחסי לגובה גוף בתמונה, שנמדד בעמידה ואינו משתנה באמצע חזרה.

| מדד | סף | הסיבה |
| --- | --- | --- |
| גוף בתמונה | visibility ≥ 0.65 לראש, כתפיים, מרפקים, ידיים, אגן, ברכיים וקרסוליים; שוליים 3.5% | לא סופרים מפרקים מוסתרים או מחוץ למסגרת. מעל האף נשמר שול נוסף של 10% מגובה הגוף לקירוב קצה הראש |
| החלקה | EMA לפי הזמן, קבוע 90ms | מסנן רעד בלי תלות במספר FPS |
| מעבר מצב | 140ms בגיל 5–8; 120ms בגיל 9–12 | גם התחלה, גם עומק וגם חזרה לעמידה צריכים להתמיד |
| סקוואט | התחלת ניסיון מתחת ל־145°; עומק מתחת ל־120° בגיל 5–8 / 115° בגיל 9–12; חזרה מעל 158° | זוויות ירך–ברך–קרסול מ־world landmarks תלת־ממדיים; מרווח כניסה/יציאה מונע ספירה כפולה; לילד צעיר סף עומק מתון יותר |
| ברכיים פנימה | רוחב ברכיים / רוחב קרסוליים < 0.65 למשך 200ms, רק כשהכתפיים נראות חזיתיות | מפחית פסילות בגלל פריים בודד או מבט צד. זה אינו בודק את כל טעויות התנועה |
| פישוק | פתיחת רגליים > 1.55 מרוחב כתפיים בגיל 5–8 / 1.65 למבוגר יותר; סגירה < 1.18 | נרמול לגוף ומרווח בין פתיחה לסגירה |
| ידיים בפישוק | שני שורשי כף יד לפחות 8% מגובה גוף מעל הכתפיים; בסגירה 12% מתחת | דורש פתיחת ידיים ורגליים יחד, לא רק פישוק |
| ברך גבוהה | קרסול מורם לפחות `8 / heightCm` מגובה הגוף (מוגבל ל־5–8.5%); חזרה מתחת ל־2.5% | קירוב להרמה של 8 ס״מ, עם מגבלות; הגובה משפיע על סף הספירה בכל אימון של ברכיים גבוהות |
| אימות ברך גבוהה | כיפוף ברך < 135° והברך לא יותר מ־12% מגובה גוף מתחת לאגן | מונע ספירת בעיטה ישרה או עקב לאחור |
| מחזור | לפחות 450ms, לכל היותר 12 שניות; פער פריימים > 600ms פוסל תנועה פעילה | ספייקים, עצירה ארוכה ואובדן עקיבה אינם מחזור מלא |

מכונת המצבים: לא חמוש → עמידה יציבה → מוכן → ניסיון בתנועה → עומק יציב → חזרה יציבה. ניסיון שהתחיל ולא הגיע לעומק נפסל כשחוזרים לעמידה. סיום/רקע בזמן ניסיון מסמנים ״הגוף לא היה ברור״. אין הבטחה לגילוי קפיצה אמיתית לעומת פתיחה בלי ניתור; זה אב־טיפוס לזיהוי מחזור תנועה.

## פרטיות וביצועים

- הפריימים מועברים כ־ImageBitmap ל־worker מקומי ומסוגרים אחרי `detectForVideo`. אין MediaRecorder, העלאות, analytics, IndexedDB או localStorage. גם גיל, גובה ותוצאות נשארים בזיכרון בלבד.
- מופעל רק קול עברי עם `localService=true`. אין מעבר לקול מרוחק; אם אין קול כזה, מוצג טקסט. את זמינות הקול ואיכות ההגייה צריך לבדוק בטלפון.
- המצלמה נעצרת בסיום, בביטול, במעבר לרקע ובעזיבת הדף. לא נשמרות נקודות גוף בלוג.
- לכל פריים מעובד יש FPS בין תשובות, זמן inference ב־worker וזמן סבב (יצירת תמונה, העברה ועיבוד). זה FPS העיבוד, לא FPS המצלמה. לוג מוגבל ל־600 פריימים בזיכרון ונכתב גם ל־console.debug. העתקה יזומה כוללת רק סוג תרגיל ומדדים מספריים.
- מודל CPU lite, בקשת מצלמה 640×480 ועד 30FPS, ורק פריים אחד בתהליך בכל רגע. טלפון איטי לא צובר תור פריימים. יש למדוד על מכשיר ישן; נתוני מחשב אינם ראיה לביצועי טלפון.

## פיתוח ובדיקות

מהתיקייה הזאת:

```sh
node --test tests/*.mjs
```

משורש המאגר, בדיקות הרגרסיה הקיימות (בלי שינוי מחוץ ל־workout/):

```sh
node --test tests/*.mjs
```

הבדיקות החדשות נמצאות כאן ב־`tests/`, בתוך גבולות התיקייה שהותרה. הבדיקות בשורש אינן כוללות אותן, ולכן יש להריץ את שתי הפקודות. אין שינוי ב־CI של המאגר.

שרת פיתוח משורש המאגר:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

זה מתאים לבדיקת דפדפן מקומית במחשב, ולא לחיבור מצלמה בטלפון דרך HTTP. לטלפון משתמשים בפריסה מאובטחת.

בדיקת שלמות הנכסים משורש המאגר:

```sh
sha256sum -c workout/cam-lab/assets.sha256
```

## מה נבדק ומה לא

נבדקו רצפי נקודות מדומים: שלושת התרגילים, התחלה באמצע תנועה, חזרות חוזרות, טווח חלקי, ידיים חסרות, ברכיים פנימה, רעד, ספייק, אובדן זיהוי, פער פריימים, timeout, החלפת רגליים, הרמת עקב, גיל/גובה, נרמול ו־world landmarks. נבדקות בנפרד גם בדיקות המאגר הקיימות.

לא נבדקו כאן הילד, מצלמה פיזית, דיוק תנועה אמיתית, טלפון ישן, Safari/iOS וקול עברי פיזי. אין טענה שהספים כבר מתאימים לילד או שהמערכת מזהה כל שגיאה.

נבדק גם Chromium עם מצלמה מדומה: מודל lite אמיתי נטען מהקובץ המקומי ועיבד פריימים בתוך worker; אין בקשות חיצוניות ואין שגיאות JavaScript. בדיקת UI נוספת עם נקודות מדומות מכסה הצבה, שלושת המונים, תוצאה עם סיבת פסילה וסגירת המצלמה. הבדיקות האלה אינן בודקות דיוק על אדם.

שחזור בדיקות הדפדפן (אופציונלי, אחרי הפעלת השרת; דורש Python Playwright ו־`/usr/bin/chromium`):

```sh
python3 workout/cam-lab/tests/browser-smoke.py
python3 workout/cam-lab/tests/browser-ui.py
```
