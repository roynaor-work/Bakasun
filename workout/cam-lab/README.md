# מעבדת מצלמה — האימון שלי

ניסוי נפרד, ללא קישור מהאפליקציה וללא שינוי בקוד האימון החי. כל הקוד והנכסים החדשים נמצאים ב־`workout/`. הבדיקות ב־`workout/tests/`, כדי לשמור גם אותן בתוך תחום העבודה שאושר.

## פתיחה בטלפון

אחרי מיזוג ה־PR ופריסת GitHub Pages, הכתובת תהיה:

```text
https://roynaor-work.github.io/Bakasun/workout/cam-lab/
```

1. פותחים את הכתובת ב־Safari או Chrome מעודכן בטלפון/טאבלט. המצלמה דורשת HTTPS; כתובת HTTP ברשת הביתית לא מספיקה.
2. מכניסים גיל וגובה אמיתיים, בוחרים תרגיל ולוחצים „הפעלת מצלמה והדרכה”. מאשרים מצלמה בלבד; אין בקשת מיקרופון.
3. מניחים את המכשיר ביציבות בגובה האגן, מול הילד, במרחק התחלתי של כ־2–3 מטר. מכוונים לפי התמונה ולא לפי המרחק בלבד: הראש וכפות הרגליים בפנים, ומקום לידיים מעל הראש ולצדדים. אור מול הילד ומבוגר לידו.
4. עומדים ישר, ידיים למטה ורגליים קרובות. אחרי 1.2 שניות זיהוי רציף המסגרת ירוקה ו„מתחילים לספור” זמין. לוחצים, חוזרים רגע לעמידת ההתחלה, ומבצעים בנחת.
5. „סיום ותוצאה” מפסיק את המצלמה ומציג ספירה, תנועות שלא נספרו וסיבות. מעבר לאפליקציה אחרת מפסיק את המצלמה ומסיים את הניסיון. „תרגיל נוסף” חוזר להגדרה.

אין צורך לקנות ציוד. מומלץ להשתמש במשטח או מדף יציב שכבר יש בבית. לא מחזיקים את המכשיר בזמן התרגיל.

לפני מיזוג אפשר לפרוס **את ענף ה־PR בלבד** בשרת HTTPS לבדיקה. כתובת ה־Pages לעיל אינה תצוגה מקדימה של PR ולא תציג את המעבדה לפני פריסה.

## זיהוי וספי ספירה

`PoseLandmarker` מתוך `@mediapipe/tasks-vision` בגרסה **0.10.32**, מודל **lite / float16 / version 1**, `runningMode: 'VIDEO'`, `detectForVideo`, אדם אחד, CPU, ללא segmentation. המודל ועיבוד ה־WASM חיים ב־dedicated web worker קלאסי; החבילה המקורית נטענת ב־dynamic import כי טוען ה־WASM משתמש ב־`importScripts`. הקנבס לעיבוד הוא `OffscreenCanvas`. אין טעינת חבילה/מודל/WASM מ־CDN בזמן שימוש.

אלה **ספי הנדסה ראשוניים**, לא נורמות ילדים, מדידה רפואית או כיול שנבדק על ילד בן 7. גיל וגובה אינם מאפשרים להסיק דיוק אנטומי. נדרש ניסיון על המכשיר והילד לפני שימוש בספירה לצורך אימון. אין כאן אישור בטיחות לתרגיל.

מכונת המצבים היא המתנה → עמידת התחלה יציבה → תנועה → יעד יציב → חזרה יציבה. מחזור שמתחיל כבר בכריעה אינו נספר. ירידה חלקית, אות ברכיים פנימה, חזרה ללא החלפת רגל, אובדן מעקב, timeout וסיום באמצע נשמרים **בזיכרון בלבד**, עם סיבה. אובדן מעקב אינו נחשב הוכחה שהתנועה לא נכונה: המשוב אומר שהמצלמה לא ראתה ברור ומציע לשאול מבוגר. גם תוצאה של אפס פריימים אינה מוצגת כהצלחה בזיהוי.

## פרטיות וקול

- לא משתמשים ב־MediaRecorder, בענן, ב־analytics, ב־localStorage או ב־IndexedDB. אין צילום סטילס או שמירת landmark sequences.
- ImageBitmap מועבר ל־worker, נסגר אחרי כל פריים, ורק נקודות הזיהוי של הפריים הנוכחי חוזרות לציור ולספירה. אין תור של תמונות: רק פריים אחד בעיבוד.
- CSP מגביל טעינות וחיבורים לאותו origin. הדף אינו מייבא מודולים מהאפליקציה החיה, service worker או ספריות ענן.
- שימוש בקול רק אם יש voice עברי עם `localService: true`. קולות רשת אינם נבחרים. הטקסט מנוקד; קצב 0.85 והפסקה של 6 שניות בין משובים מונעים הצפה. אם אין קול עברי מקומי, מצוין זאת וכל ההדרכה זמינה בכתב. אפשר לכבות קול.
- עצירה, תוצאה, מעבר לרקע או יציאה מהדף משחררים מצלמה ו־worker. נדרש אישור מצלמה בכל מדיניות דפדפן שבה ההרשאה אינה נשמרת.

## ביצועים

מצלמה מבקשת עד 640×480 ועד 24 FPS (20 מועדף). זיהוי רק לפריים וידאו חדש, ללא פענוח מקביל וללא backlog. לוג בזיכרון שומר עד **900 הפריימים האחרונים**, כל אחד עם FPS, זמן `detectForVideo`, וזמן מצילום ה־ImageBitmap ועד חזרת התוצאה ל־main thread; בוליאני `tracked` מציין אם הגוף זוהה. הוא אינו מכיל תמונות, נקודות גוף, גיל או גובה. בסיכום: מספר כל הפריימים, FPS ממוצע לאורך הניסיון, זמן זיהוי ממוצע ו־P95 של זמן העיבוד בפריימים הנשמרים. ייצוא JSON מקומי רק לפי לחיצה מפורשת.

FPS של הפריים הראשון הוא 0 כי אין מרווח קודם. זמן העיבוד הראשון כולל warm-up. אין להסיק מביצועי Chromium על שרת מה יהיו ביצועי טלפון. פערים מעל 450 מ״ש גורמים להמתנה/ביטול ספירה: אם הטלפון מתחת לכ־2.2 FPS לא תתקבל ספירה רציפה; גם מעל קצב זה חשוב לבדוק תנועות מהירות בפועל. דפדפנים ללא OffscreenCanvas, Worker, createImageBitmap או WebGL מציגים שגיאה במקום ליפול לעיבוד חוסם במסך.

## הרצה ובדיקות למפתחים

מתיקיית המאגר:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

פתיחה במחשב לצורך פיתוח:

```text
http://localhost:8765/workout/cam-lab/
```

בדיקות המעבדה, בתוך `workout/`:

```sh
node --test tests/*.mjs
```

בדיקות הרגרסיה הקיימות, מתוך שורש המאגר:

```sh
node --test tests/*.mjs
```

בדיקת שלמות הנכסים, בתוך `workout/cam-lab/`:

```sh
sha256sum -c assets.sha256
```

אין build ואין התקנת npm להרצת המעבדה. Node נדרש לבדיקות בלבד; Python רק לשרת פיתוח. השתמשו ב־checkout הקיים; משימות cloud כבר מבודדות ולא צריך worktree.

## מה נבדק ומה עדיין לא

נבדקו רצפי נקודות מדומים: חזרות מלאות, חלקיות, רעידות, קצה ממושך, ברכיים פנימה, פער פריימים, היעדר נקודות עולם, החלפת רגל, timeout וסיום באמצע. גם חבילות הנכסים אומתו מול המקור.

נבדקו ב־Chromium headless: טעינת worker ומודל מקומיים, עיבוד פריימים ממצלמה מדומה, ו־33 נקודות גוף ו־33 נקודות עולם מתמונת הדגמה ציבורית של MediaPipe. זרימת UI נבדקה בנפרד עם נקודות מדומות לשלושת התרגילים: מוכנות, ספירה, פסילת תנועה חלקית, תוצאה, ייצוא לוג ושחרור המצלמה. נבדקו גם סירוב הרשאה, מודל חסר, מעבר לרקע, היעדר כתיבות לאחסון והיעדר בקשות ל־origin חיצוני. תמונת ההדגמה וצילומי הבדיקה אינם בריפו.

**לא נבדקו:** ילד אמיתי, וידאו של תרגילים אמיתיים, דיוק/רגישות הספים, כיול גיל/גובה, תאורה והסתרות בבית, הבחנה בין כמה אנשים, TTS עברי בפועל, Safari/iOS/Android, סוללה/חום או טלפון ישן. בדיקות UI עם נקודות מדומות אינן מוכיחות ש־MediaPipe יזהה את התנועה של הילד. אין benchmark שמצדיק הבטחת FPS בטלפון.
