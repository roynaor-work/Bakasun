# סבב 04 — משקל, מודולים וביצועים

נבדקו כל 6,103 הקבצים בבסיס, כולל 236 GLB, גרף ES modules, תמונות מוטמעות, תצורת פריסה ורשימת offline. שישה benchmarks של משחקים הושלמו בשתי התנוחות. מדידות startup נעשו פעם מקומית ושלוש פעמים עם CPU ×4 ורשת 1.6Mbps/150ms לכל אפליקציה.

## ממצאים והבחנות

- שלוש האפליקציות הגדולות טוענות גרפים רחבים בפתיחה; 124 מודולים static בעסק, 69 באימון ו־107 באי לפני הרחבות דינמיות. המשקל המפוענח ו־gzip המחושב נשמרים בנפרד.
- שתי זהויות URL של offline.mjs מחזיקות שני guards נפרדים. שחזור עם manifest סינתטי הראה הורדה כפולה של אותו URL, מול הורדה אחת דרך אותו singleton.
- 419MB הם חבילת Pages לפי ה־workflow; הם אינם תעבורת פתיחה. חבילת offline הייחודית של האי היא כ־42MB. חומרי verification/tools מהווים חלק גדול מחבילת הפריסה.
- קובץ GLB אחד מעל 1.5MB אינו הדמות הפעילה בסקי. אין לייחס לו אוטומטית את עלות המשחק הנוכחי.
- דמות הכדורסל הפעילה היא v4 עם 52 עצמות; חלק מנכסי v6 הם 18 עצמות אך טרם חוברו. file presence אינו runtime verification.
- קהל instanced ו־LOD קיימים, וה־bench מדווח הורדות איכות. זהו ממצא חיובי אך אינו הוכחת יעד FPS בטלפון.

## ביקורת עצמית ותיקונים

תקרת Resource Timing ברירת המחדל היא 250; היא קטעה חלק מספירת הבסיס. נוספה תקרה של 5,000 לפני טעינה. אין להציג את 250 כ״כל הבקשות״. מדידת האי הראשונית הסתיימה במסך loading, ולכן שלוש דגימות האי הוחלפו במדידות שממתינות גם לעיר ולדמות מוכנות.

GLB triangles מחושבים מ־accessor counts ואינם כוללים הכפלת instances או מעברי צל. texture image count אינו UV atlas count. אלה כותרות מפורשות בטבלאות. benchmark המשחקים הוא על SwiftShader בענן משותף ו־FPS אינו מייצג טלפון בינוני; אין שינוי ספים או העמדת פנים שהיעד הושג.

מבט רחוק בתפריט אינו camera framing של כל minigame. צילומי משחק הכדורסל משתמשים בכלי המשחק האמיתי; מדידות המשחקים נפרדות ומפורטות ב־game-performance.json. אין reference חזותי חיצוני להשוואת איכות נכסים.

המשך: בדיקות fault/ללא רשת, יציבות ממושכת ושלילת מסקנות ממבחני דפדפן שמוסיפים CSP מעבר לתצורת הפריסה.
