# סבב 05 — ללא רשת, אחסון ו־CI

נבדקו Cache API אמיתי, service workers אמיתיים, פגם JSON, QuotaExceededError, כשל שמירת הזמנה ו־sessionStorage, ופתיחה עצמאית ללא רשת. צילומי מצב 05 מציגים יומן, מעקב אימון, עיר וקופה; צילומי error-cache הנוספים מוכיחים shell שלא עלה אחרי הרעלת 503 סינתטית.

## תוצאות

- עדכון root worker מוחק מטמוני אפליקציות ותור שיתוף; 503 יכול להחליף קוד תקין. שניהם אומתו בדפדפן ולא רק בתבנית טקסט.
- האי משמר JSON פגום וגיבוי corrupt; העסק, האימון והחנות דורסים לאחר שינוי. העסק מציג כשל מכסה, בעוד האימון והסל שותקים.
- כשל רשת בקופה מרוקן סל; עם כשל sessionStorage אין עותק שמור. מספר תודה שרירותי מוצג כנקלט. אין הזמנה אמיתית בשחזור.
- פתיחה עצמאית warm→offline עם HTTP cache מבוטל: עסק עבר לאחר התקנת worker; אימון וחנות ללא shell worker נכשלו. האי דורש הורדה ייעודית או ביקור תחת worker, ואינו מבטיח offline מיד בביקור הראשון.
- בדיקת האי המלאה אחרי הורדה עברה את שלושת המשחקים, ושחזור נכס חסום עבר. מבחן ההורדה האוטומטית נכשל בהמתנה ל־avatarLoaded וחזר ונכשל בריצה ממוקדת. זו תוצאה לא ירוקה ואינה מוסתרת.
- שלוש הרצות מלאות: 3,227 passed, 51 skipped, אפס failed בכל הרצה. 33 מהדילוגים הם יעדי תיקון B3; אין לראות בהם אישור שתוקנו.

## ביקורת עצמית

כשל המבחן האוטומטי אינו כשלעצמו הוכחת באג במוצר: אבחון נפרד הצליח לטעון דמות בשני contexts. תנאי סדר פתיחה, ניטור CSP ועומס ה־GPU אינם זהים בכל הריצות. הדוח משמר את הכשל ואת הגבול, ולא מתייג אותו כ״flaky שתוקן״ או ככשל פרודקשן מוכח.

ה־fixture הראשוני של מפת הפריסה התייחס למחרוזת ריקה ב־offline manifest כקובץ חסר; היא למעשה alias ל־index. הכלי תוקן, וכעת אין קובצי manifest חסרים במודל הפריסה. זה היה ממצא שווא של כלי הביקורת, לא תקלה במוצר.

מבחן היציבות ממשיך ברקע. נצפתה הצטברות מאזינים במסכי העסק והאימון; בסבב הבא נבדקת סיבתיות ונבדק דף המסירה עצמו ללא רשת.
