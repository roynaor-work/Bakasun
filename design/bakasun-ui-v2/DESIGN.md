# החלטות עיצוב ומיפוי לחיבור עתידי

הרפרנס הוא מערכת העיצוב הראשונה בתיקייה הסמוכה. במקום להחליף את זהותה, ההרחבה שומרת על משטח שנהב, כותרות כהות, טרקוטה לפעולה אחת עיקרית וירוק מרווה למידע רגוע. הניווט גדל מארבעה יעדים לארבעה קיצורים ועוד תפריט מלא בנייד, ולמסילת צד במחשב.

## שפה חזותית

| החלטה | יישום | הסיבה |
|---|---|---|
| צבע לפי תפקיד | canvas, surface, ink, muted, accent, positive, caution, info, negative | החלפת מצב אינה משנה את משמעות הצבע |
| פעולה ראשית יחידה | כפתור טרקוטה בראש מסך או באזור המשימה | עדיפות ברורה גם בחלון קטן |
| הדגשת מידע נדרשת | התראה קצרה לפני הפירוט, לא חלון קופץ בכניסה | המשך קריאה בלי חסימת עבודה |
| תנועה מצומצמת | אין כניסות מונפשות; רק סמן טעינה בספרייה | יציבות, צריכת סוללה נמוכה וקריאות |
| גופן עברי מוטמע ב־CSS | 400 לגוף, 700 לכותרות ולפעולות | קריאה עקבית, גם ללא רשת |
| מספרים | bdi, ספרות טבלאיות והפרדת טווחי שעות | RTL שאינו הופך סכומים או רצף זמן |
| טבלה בטלפון | אותן שורות וסדר נתונים, פריסה לכרטיס עם תוויות | אין צורך לגרור טבלה לרוחב |
| לשוניות התיק | פס נגלל במחשב/לרוחב, בורר native בנייד צר | 13 יעדים זמינים בלי כפילות בגובה |
| חלון | dialog מקורי, Escape, לכידת מיקוד וחזרה למקור | התנהגות מקלדת צפויה |
| חתימה | ציור pointer + חלופה מוקלדת | השלמת הפעולה בלי צורך במחווה מדויקת |

## חיבור עתידי למוצר

החבילה עצמאית. אין ייבוא מקוד המוצר או חיבור לענן. הטבלה מתארת היכן לחבר לאחר סקירה, ואינה הוראה לשנות את המודולים האלה במסגרת המשימה.

| אזור תצוגה | מודול מוצר קיים | התאמה נדרשת בחיבור |
|---|---|---|
| היום | js/logic/dashboard.js | להחליף נתוני דמה בנתוני אמת רק בזמן ריצה מורשית |
| לוח אירועים | js/logic/pipeline.js | סינון שלבים, סוג וטקסט; לשמור את הזרימות הקיימות |
| פרטי תיק, ספקים, לו״ז וצוות, כספים, רשימות | js/screens/cases.js | למפות את חמש לשוניות הבסיס לפי מפתחות |
| משתתפים | js/screens/participants.js | שמות/פרטי משתתפים לא נכנסים לנכסים סטטיים |
| חוזה ורשימת בדיקה | js/screens/contracts.js | אישור/חתימה של המוצר, לא פעולת ההדגמה |
| תקציב | js/screens/budget.js | סכומי אמת, מטבע ומע״מ לפי לוגיקת המוצר |
| יום האירוע | js/screens/runsheet.js | תלויות ומצב חי של המוצר |
| קבצים | js/screens/casefiles.js | הרשאות וגישה לקבצים במוצר |
| קבוצת עבודה | js/screens/workgroup.js | הצוות המוגדר, בלי המצאת אנשי קשר |
| היסטוריה | js/screens/calendar.js | רישום אמיתי של שינויים לפי המוצר |

## רכיבים ומצבים

- כפתור: ראשי, משני, עדין, disabled ומיקוד. הפעולה תמיד כתובה, עם סמל תומך.
- שדה: label מפורש, required, הסבר מקושר, invalid עם הודעה טקסטואלית ו־disabled.
- טבלה: caption, כותרות עמודה, סדר עקבי ותוויות של כל שדה בנייד.
- כרטיס: כותרת, מידע משני ופעולה; כרטיס שלם מקושר רק כשהוא מוביל ליעד יחיד.
- לשונית: tablist/tab/tabpanel, בחירה אחת, חיצים בכיוון RTL, Home/End וקישור ישיר.
- התראה: מידע, אזהרה, שגיאה והצלחה עם סמל וטקסט; ההודעה אינה תלויה בצבע בלבד.
- ריק: 8 איורים לפי הקשר, הסבר של מה חסר ופעולה מתאימה.
- טעינה: מצב דוגמה מסומן aria-busy, אנימציה מבוטלת בהעדפת הפחתת תנועה.
- משוב זמני: אזור status עם טקסט, ביטול אמיתי לפעולות ההדגמה וחלון זמן ארוך יותר לביטול.

## גבולות הבדיקה

axe ומטריצות דפדפן בודקים חלק מהקריטריונים של WCAG AA. בדיקת מקלדת, ריווח, reflow, ניגודיות וחתימת מגע מוסיפות ראיות, אך אינן אישור נגישות משפטי או בדיקת קורא מסך אנושית. יעד 30fps נבדק בהדמיית CPU ובגלילה מתמשכת; הוא אינו מדידה של טלפון פיזי.

אין סצנת תלת־ממד במסכי ניהול האירועים. לכן אין טעינת three.js, קובצי GLB, משולשים, טקסטורות, קהל או שלד. פרמטרי r160/Draco/LOD/instancing/18 עצמות יחולו על תוצר תלת־ממד עתידי אם יתבקש, ואינם תלות מיותרת בחבילת הממשק הזו.
