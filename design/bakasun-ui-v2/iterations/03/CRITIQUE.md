# סבב 03 — עקביות ונתונים

תוקנו שימור הצבע בכל קישור, בחירת סוג האירוע, לשונית כספים ייעודית לאירוע, שורות ניהול ורזרבה בתקציב וקישור פתיחה שנגזר מההגדרות. נשמרו גם תצלומי תוכן מסומנים `content` ללא הסרגל הצף; `near` ו־`far` נשארו צילומי הדפדפן הרגילים.

| בדיקה | תוצאה |
|---|---|
| רינדורים | 196, כולל 320 / 360 / 768 / 1024 / 1440 |
| לשוניות | 52 מצבים נבדקו וצולמו |
| axe | 108 מצבי מסך/לשונית, 0 הפרות |
| זרימות | 18 מתוך 18 עברו; 0 שגיאות ורשת |
| בדיקה סטטית | 14 דפים, 68 סמלים, 8 איורים, קישורים ומזהים תקינים |
| ניגודיות tokens | כל 38 הזוגות עברו; הגבול הנמוך ביותר הוא 3.029:1 עבור גבול שדה |

השוואה לרפרנס: תיק האירוע מציג עכשיו תוכן מוקדם יותר בנייד בלי לוותר על כרטיס המידע; הטופס השגוי והחתימה ממשיכים את אותם צבעים ופינות. נבדקו גם צילומי טופס חשבונית שגוי ואישור חתימה מצוירת. שורות המטבע נשארות קריאות ואינן נחתכות.

ביקורת עצמית: (1) טווח השעות בפרטי האירוע צריך בידוד כיוון כדי להיקרא 10:00–14:00 ללא היפוך. (2) דף היום משמש כניסה, אבל חסר דף תצוגה ממוקד שמאפשר להשוות מסכים, מידות ומצבים בלי לשנות את חלון הדפדפן. (3) חסרים בצורת JSON ערכי הצבע עצמם, אף שקיימים ב־CSS. (4) מצב ניסיון חוזר משנה טקסט וצבע אך משאיר סמל שגיאה; צריך לעבור גם לסמל הצלחה. (5) חסרה עדיין בדיקה רציפה של הגדלת טקסט, forced colors, חתימה במגע והתנהגות לאורך זמן. (6) כמה נתוני פרטים בדיוניים חוזרים בקוד ובמסך; לפני מסירה צריך לאמת שהם תואמים, לא רק יפים.

המשך לסבב 04: לתקן את הכיווניות וסמל המשוב, להוסיף דף תצוגה מקומי ו־tokens מלאים, ולהתחיל בדיקה מורחבת. ציון ביניים: 8/10; נדרשים עוד לפחות שלושה סבבים ואימותי מסירה.
